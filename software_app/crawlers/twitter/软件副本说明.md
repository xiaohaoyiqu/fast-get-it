# 推特爬虫软件副本

这个目录是新版软件拥有并维护的 X/Twitter 爬虫实现。

原始目录：

```text
推特爬虫/
```

新版软件只使用当前目录：

```text
software_app/crawlers/twitter/
```

维护规则：

- 后续为了软件化改推特逻辑时，优先改这个副本。
- 不直接修改原始 `推特爬虫/`。
- 通过 `service.py` 在应用进程内调用，不再把 CLI 子进程当作正式架构。
- 2026-09-12 已同步原目录的 `2026-09-08-media-routes-v12` 媒体路由、代理、重试和 PNG 修正。
- 仓库维护运行需要的源码和默认配置；Cookie、下载记录和 ChromeDriver 属于本地运行/打包资料，不进入 Git。
- 没有复制旧的已下载作者媒体目录。

运行数据目录：

```text
data/software_app/twitter/
```

新版软件会优先从运行数据目录读取 Cookie、配置、下载记录。首次运行时，如果运行数据目录缺少这些文件，会从当前源码副本复制一份。

复制仅在对应本地文件存在时生效，克隆源码不会得到已登录 Cookie 或历史记录。当前桌面端还通过任务选项控制 Twitter 图片/视频命名、原始名副本、未完成 TXT、逐媒体进度与文件回调；维护这些功能时需同时核对 `service.py`、`manga_downloader.py` 与 `download_method.py`。

## 2026-10-28 维护约定

- `configure_downloads` 返回不可变网络配置，调用者必须接收并沿媒体下载调用链传入 `network_config`；它不会再修改模块级代理、超时和重试参数。桌面服务、独立 CLI、媒体线程和头像缓存均按此方式调用。
- 下载浏览器使用任务代理；桌面在线资料、批量资料、关注刷新和头像缓存使用已保存的代理。维护这些入口还需核对 `driver_init.py`、`profile_preview.py`、`following_collector.py`、适配器和 UI 调用点。
- 成功/失败及账号历史 JSON 使用跨进程路径锁覆盖完整读改写事务，进程内共享缓存；写入时强制重读，提交成功后才发布缓存。默认复用策略只在成功记录指向的媒体仍存在时跳过；覆盖、报错和自动改名策略不被成功历史提前跳过。自动改名的实际成品路径必须回写记录和 FileRecord。不要退回各实例各自修改旧缓存后直接覆盖文件的写法。
- `DEFAULT_CONFIG`、随仓库的 `config.json` 与桌面任务选项是不同层次。记录默认值时注明层次，避免把示例中的 GIF 帧率、宽度或并行用户数当成统一缺省值。
- 未完成 TXT 由桌面服务处理；独立 CLI 的功能、参数与默认值见本目录 README。`way.md` 保留为旧响应样本，不是当前 API 契约。
