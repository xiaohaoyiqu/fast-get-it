# 第一版说明

这是本地内容下载器的第一版原型，目标是先把已有推特/X 爬虫接入本地软件，并把爬取后的文件索引到本地库里展示。

## 当前能力

- 桌面入口：`python run_desktop.py`
- 命令行预览：`python prototype.py preview @username`
- 命令行下载：`python prototype.py download @username -t 5`
- 支持把用户名、`@用户名`、`twitter.com` 链接规范化为 `x.com/.../media`
- 下载任务通过后台线程执行，不阻塞桌面界面
- 下载日志写入 `data/content_downloader.db`
- 下载完成后扫描本地保存目录，把图片、视频、音频、文本索引到 SQLite
- 桌面界面可以查看本地文件列表，图片可内嵌预览，视频/音频可调用系统默认程序打开

## 推特下载类型

- `1` 图片
- `2` 视频
- `3` GIF
- `4` 音频
- `5` 全部
- 多类型可用逗号组合，例如 `1,2`

## 目录结构

- `app_core/`：通用数据模型、SQLite 存储、任务管理
- `adapters/twitter_adapter/`：推特/X 爬虫适配器
- `desktop_ui/`：Tkinter 本地桌面界面
- `prototype.py`：命令行原型入口
- `run_desktop.py`：桌面软件入口
- `data/content_downloader.db`：本地任务、日志和文件索引数据库
- `推特爬虫/`：原有推特爬虫实现

## 运行前检查

当前第一版复用 `推特爬虫/twitter_Crawler_2.py`，所以需要：

- `推特爬虫/X_cookie.json` 可用
- `推特爬虫/chromedriver.exe` 可用并匹配本机 Chrome
- 当前 Python 环境安装了 Selenium

## 为什么第一版用 Tkinter

当前环境能直接导入 `tkinter`，但没有安装 `PySide6`。所以第一版用 Python 内置 Tkinter 做可运行验证，先打通“输入目标 -> 爬取 -> 入库 -> 本地渲染”的链路。后续如果要做更像正式软件的界面，再切换到 PySide6/Tauri/Flutter。

## 本地版本管理

项目已在根目录初始化本地 Git 仓库，默认分支为 `main`。Git 当前只用于本地版本记录，没有远程仓库，也不会自动上传。

根目录 `.gitignore` 会排除虚拟环境、缓存、构建产物、数据库、下载记录、Cookie、ChromeDriver 和已下载媒体目录。需要提交或上传时，必须由使用者明确指定。
