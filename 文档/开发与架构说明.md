# 欲求达开发与架构说明

欲求达采用桌面界面、平台适配层、爬虫实现和公共服务分层。平台代码通过统一任务模型接入，界面不直接依赖具体网站的请求细节。

本文补充核对至 2026-10-31，涵盖 2026-09-22 以来的提交与未提交实现，不表示这些能力均已发布或完成真实平台验收。最新维护记录见顶部，参考资料见对应章节与参考源码评估；历史验证不覆盖后续源码修改。

## 下载库成品基线与只读核验（2026-10-31）

新增 `core/library_integrity.py`，复用完整索引筛选和输出锁，不修改数据库结构或记录。导出先收集最多 10000 条匹配记录并关闭 SQLite 读取快照，再按文件持锁、以最多 1 MiB 块读取并计算 SHA-256。路径 lstat 和句柄 fstat 比较设备／文件身份、长度及 mtime，限制读取为初始长度并检查额外尾部；文件变动、占用、缺失及不安全路径单独报告。检测文件和父目录链接／Windows 重解析点；短路径与长路径按安全父目录规范化匹配。

版本 1 清单使用相对路径、大小、摘要、基线状态和来源字段白名单。原始 Cookie、任务参数和 metadata_json 不导出；来源 URL 移除 userinfo、所有查询和片段。核验根目录由用户显式选择，JSON 不能指定绝对根；先整体校验版本、类型、重复字段／路径及摘要，再开始读目标文件。拒绝绝对路径、上级目录、驱动器／UNC／设备名等形式，单文档限 16 MiB。

导出／核验后台复用下载库窗口的 Queue、停止事件及忙碌按钮状态，核验不使用窗口筛选条件。清单／报告先在同目录生成并刷写临时文件，最后以独占硬链接发布，删除临时名；新出现的目标文件不会被覆盖。文件系统不支持该操作时失败，不退回可覆盖提交。输出不能占用现有文件、数据库或已有索引的缺失路径；报告也不能占用导入清单中的资源路径。UI 不会因核验修改索引、历史或重下文件。

这是用户主动创建的本地基线，不是下载时自动验证，不提供可信来源证明或源到转换产物关系；不保证对不合作程序同时恶意修改路径、字节及基线的完整防护。

## 通用转换取消与长限流期限（2026-10-31）

`crawlers/common.convert_media_file` 增加可选 `cancel_event`，锁等待和转换前检查使用同一事件；公共媒体下载、网页直连和浏览器预取媒体传入任务事件。通用 FFmpeg 转换复用 `core/media_process.run_media_process`，限制诊断尾部为 64 KiB、持续消费 stderr、取消／超时回收本次直接子进程，保留 1800 秒转换超时。成功后要求临时成品存在且非空，再次检查取消后替换。图片渲染后、文件占用重试前也检查取消；不抢占正在执行的 Pillow 调用，也不在暂停时挂起操作系统进程。

直接转换入口在失败或取消时保留输入及旧成品，清掉自己的临时转换文件；下载器内部的源工作副本继续按原 finally 清理，不将其宣称为用户源文件备份。取消检查与最终文件替换不是一个操作系统原子操作，提交后才到达的取消不能撤销已发布文件。

`retry_after_seconds` 和 `DomainBackoff.defer` 移除 300 秒截短，保留秒数或 HTTP 日期得到的完整期限。超过 `threading.TIMEOUT_MAX` 的有限期限明确报错，不缩短后提前请求；非法／非有限输入沿用有限回退。协调器仍最多保存 1024 个主机，等待以最多 0.1 秒片段响应任务控制，不新增持久延期队列或跨实例协调。

## Pixiv 漫画系列持久范围与逐媒体补下（2026-10-31）

本轮继续扩展作品搜索与排行榜：复用版本 1 范围记录及逐媒体流程，`search`／`ranking` 类型的 `owner_id` 改存完整目标文本的 SHA-256，校验时与原任务目标重新计算比较，不把关键词中的数字当账号。作品搜索只接受默认、三种标签及标题／简介模式；年龄范围和最低收藏数仅加入新搜索计划的选择摘要，避免使已有收藏／系列计划失效。范围标签在任务管理器、队列详情及日志共用。

搜索／排行先完成选定列表发现，再提交作品范围及逐媒体计划；自动重试、中断恢复和精确补下使用原记录。排行榜不指定日期时仍只固定当次发现的作品 ID，不保证站点提供某一时刻的原子榜单。小说、作者搜索、新作及作者标签未扩展；无持久分页游标，无数据库结构或新依赖变更。

漫画系列复用版本 1 集合计划，新增 `manga_series` 类型；原 `owner_id` 字段在此类型保存系列 ID，不代表账号。发现选定列表后先提交不可变作品 ID 范围，再完整解析所选作品的图片页／动图组，提交逐媒体清单后才传输。范围及媒体计划提交失败均停止后续工作，分页失败不保存部分范围。

作品收藏和漫画系列共用 `collection_media`，补下只读取原范围内未完成作品，刷新地址后核对页序、类型和路径身份，使用原相对目录；作者／标题变化不迁移补下目录。管理器已有自动重试及中断恢复继续复用清单；按当前设置完整重试重新发现集合，子集补下拒绝此操作。原收藏计划格式及数据库结构保持兼容，小说搜索／小说系列等集合尚未扩展，无持久分页游标。

验证使用生成数据、真实 SQLite 与任务管理器；不访问平台账号，不据此声明实站兼容，打包产物仍以接续页所列版本为准。

## HTTP 本地摘要检查点（2026-10-31）

新增 `core/http_checkpoint.py`，版本 3 记录入口／最终资源指纹、服务端总长／验证器、`checkpoint_size` 和前缀 `sha256`。元数据限读 16 KiB，类型／整数／摘要／必要验证器不合法或旧版本时不认领进度。恢复时只读检查点前缀，每块最多 1 MiB，支持任务暂停与取消；不再用物理文件长度决定 Range 起点。前缀摘要不符或截短则完整重取，未提交尾部在服务器返回匹配 206 后截掉。

`CheckpointWriter` 在写入时增量计算摘要，累计 4 MiB 或经过两秒时提交；在数据块边界判断时间，不为停滞连接单开计时线程。正常取消、网络异常及 EOF 前强制补最新检查点；其他写入／元数据错误保留上次有效检查点，可能丢掉最后未提交尾部。先 flush／fsync 数据，再写唯一临时 JSON、flush／fsync 并 replace。检查点保存失败不会把新尾部变成可信进度，也不将未完成内容作为成品。

恢复校验前后核对文件身份、长度和 mtime，打开追加句柄后再次核对；校验中变化则拒绝本次缓存，校验后到追加前变化则报错，避免继续拼接。Windows 路径 stat 与句柄 fstat 的 ctime 语义在本机运行时不同，故跨两者使用设备／文件身份、大小与 mtime；内容另由 SHA-256 判断。最终提交仍沿用旧成品保留、输出锁、代理／凭据隔离、重定向与媒体预算。这里不实现可信来源 checksum 或对恶意并发改写的完全防护。

真实 8 MiB HTTP 样本在写至 5 MiB 时 `os._exit`，无 finally／atexit；磁盘保留 4 MiB 检查点和 1 MiB 未提交尾部，恢复只从 4 MiB Range 获取，完整摘要匹配。坏前缀及旧版记录完整重取，详见最新测试报告。此前仅地址指纹的版本 2 被新格式替代，旧同级附件不接管，受控清理的文件名协议不变。

## 2026-10-31 Windows 浏览器进程所有权

原实现实测强杀本次 ChromeDriver 后，`quit` 仍留下七个 Chrome 子进程且临时目录无法删除。新增 `core/browser_process.py`：`ManagedChromeService.start` 先创建匿名、不可继承的 Windows Job Object，启动驱动后以本次 Popen 保留的进程句柄绑定，再返回 Selenium 创建 Chrome 会话；进程归属不通过 PID 重新打开、进程名或路径字符串推断。Job 设置 KILL_ON_JOB_CLOSE，不允许本组 breakaway，不设置 CPU／内存限制。

`stop` 用实例 RLock 串行化，先走 Selenium 正常退出，再 TerminateJobObject 回收本组残留，查询活动进程至零，额外等待最多三秒，最后关闭句柄；查询／退出出错仍尝试关闭句柄。持有应用被强杀时，内核关闭最后 Job 句柄，关联进程随之结束。绑定失败在 Chrome 会话创建前停止驱动、关闭空 Job，报告结构化 `browser_process`，不自动重试或无保护继续启动。依赖标准库 ctypes，无新依赖；非 Windows 仍走 Selenium 原服务退出流程。

接入 Twitter／Google／动态网页／自动 Cookie 捕获／JM 资料读取的 Selenium Service。JM 普通浏览器手动登录入口仍是原有独立流程，不接管其浏览器或清理长期资料。未新增按进程名结束 Chrome、连接现有 DevTools 会话或历史进程认领。

真实首次修复已清掉进程，但单次 rmtree 遇到退出后的短暂文件占用仍留目录。Twitter 的临时 profile 现在记录创建目录的设备／文件身份，删除前核对实际受管理父目录、twitter_ 名称、普通目录及非重解析点属性，重试时再次核对；只对该次创建的目录递归清理，占用重试最多两秒。原路径被替换、越界、链接或持续占用时保留并报错。启动失败清理仍保留主错误，既有业务 finally 继续负责名额释放；软件强杀没有机会删临时资料，不增加下次启动自动扫描。

依据微软 [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject) 和 [Job 限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information)。这落实 browser-use 参考中的创建者所有权原则，但为本项目独立实现，未引入其事件总线／psutil 依赖。具体实测边界见测试报告顶部；不保证外部程序刻意逃离进程组的情形或跨系统相同能力。

## 2026-10-31 HTTP 续传最终资源身份

对照参考下载器并核查 RFC 后，复现公共 HTTP 的入口 URL 不变但重定向资源变化，同长同 ETag 的 206 被直接接到旧前缀。`core/http_transfer.py` 从版本 2 起绑定最终资源，当前版本 3 沿用并增加本地摘要；保存 `url_key` 与 `final_key` 两个 SHA-256；后者取实际响应的完整 URL，包含查询字符串，不保存签名地址原文。206 追加除原范围／总长／验证器检查外，要求最终身份一致，否则清本次内部前缀并发无 Range 的完整请求；若仍返回不匹配 206 则报错，不发布拼接成品。200 仍按完整新资源重写临时数据。

版本 1／2 内部记录缺少当前要求的本地摘要，保守从头重取，不迁移为可信状态；旧同级 `.part/.resume` 附件不接管。归属目录、输出锁、跨源凭据隔离、逐跳验证、HTTP 预算和取消协议保持。最终地址指纹只用于资源身份；本地前缀摘要检查见上节，仍不等于可信来源内容校验。

依据 [RFC 9110 §8.8.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.1)，验证器的唯一性不跨不同资源保证；参考采用及不采用项见参考源码评估、开源下载器对比顶部。

## 2026-10-31 浏览器中断与工作线程错误传递

复现 Twitter `url_producer` 连续五轮异常后直接结束，`download_media` 仅等待队列结束并返回统计，导致关闭／崩溃浏览器或持续页面错误被误当任务成功。现在终止错误向线程外传回，线程包装收集异常，生产者结束信号确保下载工作线程退出；等待队列及工作线程收尾后优先检查取消，再抛原始错误。普通页面错误仍有限重试，明确会话失效立即终止；不取消已排队的独立媒体 HTTP 请求，也不把部分传输称为发现完整。

新增 `core/browser_session.py`，以 Selenium 的 InvalidSessionId／NoSuchWindow 类型、ChromeDriver 明确的致命协议消息前缀，以及本实例持有驱动进程已退出的证据识别会话中断。只对 WebDriver／urllib3 控制通道错误采用进程退出证据，不凭任意错误文本判定。`BrowserSessionLost` 携结构化 `browser_session_lost`、不可自动重试标签，任务管理器沿现有规则存为失败，避免用户关闭窗口后自动重开；取消优先。无法区分手动关闭、崩溃及外部终止的具体根因。

Twitter DevTools 读响应和下载前主页补充不再吞掉会话失效；普通已逐出的响应可跳过。Google 搜索沿用兼容异常类，增加结构化标签及取消优先；动态网页收集、滚动、脚本超时设置和预取分支传递致命中断。既有 finally 仍负责退出／注销／释放名额；没有新增强制终止进程树、浏览器重建或自动重新登录，也未改 Cookie 捕获、JM 普通浏览器和关注列表的既有部分结果协议。

本轮只读本地 Selenium 实现以核对服务启动／退出行为，未修改第三方包，没有外部资料或平台网络请求。真实 Chrome 验证关闭最后窗口及 `chrome://crash` 标签页崩溃后，错误分类、名额、临时资料及所观察到的子进程回收通过；驱动进程本身被强杀只做替身诊断测试，不据此保证孤儿 Chrome 均能回收。

## 2026-10-31 工具安装提交顺序

复现旧 `download_chromedriver` 覆盖正式文件后才运行 `--version`，无效候选会删除正式驱动；aria2 原流程也在覆盖后才验证。现在 `core/tool_install.py` 使用同目录 `mkstemp` 分配独立候选，写入后关闭句柄，保留 `.exe` 扩展名；非 Windows 在验证前设置执行权限。上下文正常／异常退出都只清理自己的候选文件。

ChromeDriver 在候选上最多三次版本探测，主版本匹配后才 `replace`；aria2 在候选上运行原 `aria2_status`，通过后写许可等文档，最后替换可执行文件。返回路径指向正式安装位置。首次安装创建父目录；验证、中断、文档失败或替换失败均不会主动覆盖／删除旧可执行文件。文档逐个独立替换，失败时已提交文档不回滚，因而不宣称目录整体事务。

唯一临时名避免并发安装共用 `.installing` 而互相覆盖／删除；不新增全局安装锁。Windows 仍可因文件占用或同时替换拒绝其中一次提交，错误向上传递，保留已提交工具。沿用原来源、ZIP 大小／条目检查及 aria2 固定发布摘要，未增加下载源或更新协议；只读审查本地实现，没有本轮外部资料或真实下载请求。

## 2026-10-31 续传缓存清理与 aria2 任务限速

`core/transfer_cleanup.py` 只扫描用户显式选择的根目录，识别现有 HTTP／HLS 内部目录及版本 1 归属标记，预览不写入缓存。仅列入受控的普通内部文件；出现未知内容、子目录、硬链接、链接或重解析点时整项拒绝。扫描目录、缓存目录及文件数量有上限，可取消，预览结果冻结路径与文件身份／大小／时间，不解析含签名 URL 的资源状态供界面展示。

`output_lock.output_key_lock` 允许用已有归属摘要取得与 `output_path_lock` 相同的锁；原锁文件名、系统固定目录和内核锁协议不变，没有输出锁命名空间迁移。执行在本实例 `library_maintenance` 期间进行，每个目录另以 SQLite `BEGIN IMMEDIATE` 阻止共享库创建任务，并检查未结束任务；不同数据库的合作实例由同一输出锁排除。获得锁后重新读取完整文件清单和指纹，变化则跳过。只逐个 unlink 已确认文件，owner 最后移除，不做递归删除；取消和 IO 失败保留剩余内容并报告已完成部分。此协议不宣称针对不合作外部进程的原子快照，也不逐片重新算摘要。

Windows Python 3.10／3.11 没有 `Path.is_junction`，共享 `_linked` 增补 `lstat().st_file_attributes` 的重解析点检查，依据 [Python stat 的 Windows 属性常量](https://docs.python.org/3.10/library/stat.html#stat.FILE_ATTRIBUTE_REPARSE_POINT)。当前实际运行 Python 3.12；旧 API 缺失分支用替身回归并作 3.10 AST 检查，没有宣称在 3.10 实机执行过。

`aria2_bt.Aria2Limits` 校验独立的开关及下载／上传 KiB/s，映射为 [aria2 官方总体速度参数](https://aria2.github.io/manual/en/html/aria2c.html#cmdoption-max-overall-download-limit)，数值转换成 bytes/s。`--no-conf=true` 保证不读取外部配置，关闭时明确传 0（不限速）。没有新增 RPC 服务或合并 HTTP token bucket；限制按每个 aria2 进程生效，不是多个进程的共享总额。

TaskManager 为新 EH 任务固定参数；原设置重试保留，缺字段的旧任务保持不限速兼容，当前设置重试取新值。EH 生产入口显式传 `limits`，执行前报告及日志显示范围。设置保存沿用原整组事务，任何非法上限阻止全部保存；运行中进程不动态更新。设置页缓存对话框通过 Queue 回主线程，后台扫描／删除可停止，不自动清理真实用户缓存。

## 2026-10-31 HLS 复查修复

首次下载没有记录时，异常 304 若带 ETag／Last-Modified，会访问空记录。现在仅在已发送条件请求时比较旧验证器；其他 304 再发一次无条件 GET，仍不是 200 则拒绝，不写空片段。依据为 [RFC 9110 的 304 语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.4.5)，并增加两种响应头的回归。

真实 FFmpeg 试验还确认：第二个 TS 换成非媒体文本，默认及 `-xerror` 均可能零退出、无错误输出，并产生仅含前一段的 MP4。因此不能只凭退出码及非空成品判断分片完整。新增 `_validate_resource`：TS 检查 188 字节包边界及同步字节；fMP4 有界遍历顶层盒，检查 32／64 位长度、初始化 ftyp／moov、成对 moof／非空 mdat 及尾部截断。盒结构依据 [RFC 8216 §3.3](https://www.rfc-editor.org/rfc/rfc8216.html#section-3.3)。新下载在提交缓存前检查，旧缓存摘要匹配后也重查，拒绝旧版本已保存的明显错误响应。IO 错误继续传播，结构检查失败不改写旧成品。

这是容器边界与必要盒检查，不解析全部采样表、编码内容或持续时间，也不能保证识别所有缺帧、错误轨道及服务器自洽但内容错误的响应。没有引入逐片 FFmpeg 子进程或新依赖。复现与最终验收见测试报告顶部，参考项目与采用边界见参考源码评估。

## 2026-10-31 Bluesky 有限 HLS 点播恢复

`core/hls_playlist.py` 根据 [RFC 8216 的主／媒体列表、结束标记和初始化片段定义](https://www.rfc-editor.org/rfc/rfc8216) 实现有界解析，当前选择未加密且具有结束标记的单路点播范围：最高带宽变体、TS 与带 MAP 的 fMP4，保留序号及不连续标记。明确拒绝直播、加密、字节范围、独立音视频轨和增量布局；不是完整 HLS 客户端。

`core/hls_transfer.py` 使用匿名 Session 视图和逐跳公共地址检查获取所有资源，媒体分片接入 `limited_chunks`，播放列表接入限量读取，429／503 沿用主机退避。FFmpeg 的输入由程序生成，仅包含受控的本地资源名，协议白名单只含 file；不将原始远端列表直接交给引擎，网络代理和凭据边界由 HTTP 入口负责。

状态位于输出文件同级的带归属标记 `.yuqiuda-hls-<摘要>/`。整份解析计划、完整地址和序号等只在内存中用于指纹计算；磁盘只记录指纹、每资源大小／SHA-256、最终地址摘要、ETag／Last-Modified 和封装结果摘要。每资源 JSON 独立原子更新，避免每片重写整个计划。复用须本地摘要通过并得到同最终地址的匹配 304；无验证器则重下，缓存损坏不信任。同地址内容变化会清掉本代旧资源并重新获取一次；列表、变体和完整 URI（含签名参数）变化也重置。此策略保守，不能据此宣称服务器提供原子媒体快照。

内部文件使用固定生成名，禁止链接及未知归属目录，不接管旧 `.part.mp4`。封装失败／取消保留完整分片，单片内不做 Range；提交失败保留已封装文件，再次校验资源后可重试提交。输出锁由 `media_output` 取得，成功只清理本次拥有的文件，未知内容保持原样。库扫描跳过两种内部目录，任务删除仍不隐式删除媒体或缓存。

有界范围为 2 MiB 播放列表、10000 分片、四层列表、单资源 512 MiB、合计 64 GiB。真实生成 TS／fMP4 的 HTTP 304 复用和 FFmpeg 解码已验收；没有真实账号／平台视频下载，也未扩展 aria2、其他 HLS 入口或操作系统级限速。

## 适配层

每个平台实现 `CrawlerAdapter`，并通过插件加载器注册。适配器承担以下工作。

- 判断输入是否属于当前平台；
- 把用户名、作品 ID、章节 ID或网址转换为规范目标；
- 返回结构化预览；
- 接收 `TaskManager` 创建的统一 `DownloadTask`；
- 调用平台爬虫并返回文件记录。

任务执行通过适配器提供的名称、能力和回调协调；当前界面还包含平台选项、登录和个别平台辅助函数，尚未完全与平台实现解耦。`TaskManager` 创建 `DownloadTask`，适配器负责目标预览和执行下载。

`core/error_policy.py` 按异常类型、HTTP response 与至多 12 层异常链输出 `ErrorInfo(code,label,retryable)`，防止包装后的 404/403 被任务层当作普通异常反复执行；不靠错误文字正则推断类别。文件重名、磁盘/权限、TLS、非法请求/数据及明确的永久 HTTP 错误停止任务层重试，超时/代理/连接/暂时 HTTP 错误保留有限重试；未分类插件异常保留原有限重试兼容行为。进度事件附带 error_code/retryable，SQLite 日志与任务错误展示中文类别。平台自行吞掉的失败与浏览器字符串提示不保证获得结构化分类；JM 的 HTTP 包装异常保留状态分类。

## 任务与事件

`core/mixed_batch.py` 提供纯本地链接识别、条目计划、独立入队和 TXT 汇总；`ui/mixed_batch.py` 提供独立 Tk 窗口。识别按精确域名及受支持路径分发，不调用宽松的 `can_handle`，不发资料请求或 DNS 查询；保留大小写敏感的 shortcode 和普通网页查询，不把 URL 内的分隔符拆成目标。输入上限为 100 行/200000 字符，单链接最多 8192 字符。预览使用显式平台/范围及设置快照构造参数，避免改变当前平台 UI 或带入收藏页临时过滤条件。

SQLite 新增 `batches`、`batch_items`。批次先登记全部选中条目，创建任务时同一事务绑定对应条目；重复绑定会回滚任务插入。独立批次目录中每个条目有自己的子目录，避免回退扫描或归档混入同批其他任务。后台逐项入队允许部分失败及停止后续入队；已创建任务沿用 TaskManager 的平台/类别并发和原回调。重试剥离批次绑定，作为独立任务执行，`discovery_source=mixed_batch` 阻止网页重试被历史 Google 候选启发式误判。

`批次汇总.txt` 使用输出锁和原子 UTF-8 BOM 替换，锁内读取最新 SQLite 快照，减少并发写入产生的陈旧覆盖。TaskManager 在阶段变化和终态更新后刷新，汇总失败记警告并保留任务终态；启动恢复后刷新未结束批次。条目缓存终态以便清理任务历史后保留汇总。未绑定条目不会在重启时自动执行；这不是重启续跑队列。

任务表新增 `owner_id`，旧表自动补列。`core/instance_lease.py` 为任务管理器生成独立标识，并在有活跃任务时持有数据库目录 `.instance-leases/` 下的内核锁；最后一项任务结束后释放，下次接收任务前重新取得锁。租约不依赖 PID、时间戳或心跳阈值；使用数据库旁的共同锁目录，避免不同 TEMP 设置导致实例相互误判。启动恢复只取消确认已失去租约的任务，探测失败或未知格式归属保持不变；存在存活任务归属时，旧版无归属记录也保守保留。

停止等待超时不再提前把仍在执行的任务标为取消；管理器在最后一项任务实际结束时释放租约。线程启动失败会登记失败并清除运行表，退出开始后禁止新建任务。删除任务记录和清理历史也会保护可确认属于存活实例的活跃任务；暂停和取消仍需在创建任务的实例操作。Twitter JSON 记录的跨进程互斥另由记录文件锁提供。

任务状态新增 `paused`。`core/task_control.py` 的 `TaskControl` 保持 `threading.Event.is_set()` 非阻塞，只在显式 `task_cancelled` / `task_wait` 检查点等待恢复；取消会同时唤醒所有暂停等待，重试等待的计时排除暂停时长。任务管理器用 SQLite 条件更新保护暂停/恢复，启动转换和终态登记与管理操作串行，防止迟到请求重开终态；排队检查点在全局槽位条件锁之外，避免暂停一个队列任务阻塞其他任务。运行暂停保留槽位及可能持有的输出锁；无法撤回正在执行的网络、浏览器或外部进程操作。内置爬虫和公共传输/归档接入检查点，外部适配器可复用检查函数或进度回调。

队列提供批量暂停/恢复，暂停状态可取消、可随退出正常停止；进度聚合保留暂停任务的数值，批次监视不会把全暂停视作完成。界面每轮事件泵按任务缓存读取一次当前数据库状态，避免延迟到达的 running 事件覆盖 paused/cancelling/终态。重启时仍将遗留暂停任务标记为取消，不自动执行网络任务。

任务表增加 `recovery_status`。正常退出前只标记 queued/running/paused；启动恢复在确认实例已退出后为这些状态保留恢复标记，主动 cancelling 不新增标记。“恢复中断任务”经确认后由 `restore_interrupted_task` 在实例租约保护下、通过 SQLite 条件更新接管原任务；保留 ID、参数、日志、文件索引和批次绑定，paused 保持暂停。缺少适配器、参数损坏或命中黑名单时不启动；线程启动失败登记 failed 并释放空闲租约。恢复重新执行目标解析及下载，借助现有成品/HTTP 状态继续，未保存浏览器现场；启动不自动续跑。

`core/file_conflict.py` 提供 reuse/overwrite/error/rename 四种冲突决策，TaskManager 创建任务时保存设置快照。`media_output` 对原名、候选名及关联输出/源文件按规范路径排序加锁，锁内重新检查重名，并保持锁直到提交，不创建空文件预占位。rename 保留所有已有路径，依次添加 ` (2)` 等后缀，最多尝试 10000 个候选。公共媒体下载、Twitter 媒体、Pixiv 图片/小说/动图、FANBOX/Sketch、Bluesky 图片/HLS、Instagram、EH 展示图、JM 章节/封面及合成、网页媒体和公共 ZIP 创建已接入；独立元数据、外部插件和解压目录仍有自己的处理规则，未提供逐项询问。

`build_image_artifacts` 在源文件与输出组锁内预检冲突，PDF/长图全部生成到同目录唯一 `.convert` 临时文件后，逐个调用 `replace_output` 提交。渲染失败、提交前取消均清理临时文件并保留旧成品；路径冲突不能覆盖源图片。合成检查点支持协作暂停/取消，不能中断正在执行的 Pillow 保存调用；两个文件的替换不是一笔整体原子事务。

`create_verified_zip` 锁定实际输出与精确源文件集合；源文件拒绝通过链接或链接父目录读取/删除。压缩时检查 lstat/fstat 的文件身份、大小和纳秒时间，分块计算 SHA-256，提交前复核，ZIP 仍执行 CRC 与成员数校验。清理前逐个核对当前身份及内容摘要，整组预检失败则不删除任何源；删除期间再次检查身份，变化、缺失或权限失败仅记录警告并保留索引。复用旧 ZIP 后清理还须比对成员名及解压内容摘要。归档结果只返回实际删除列表，TaskManager 据此删索引，并将清理警告写入任务日志。额外校验增加磁盘读取；锁只协调遵守协议的程序，外部程序在最后检查与 unlink 之间的改动仍非文件系统事务。

公共媒体返回 `MediaDownloadResult`，继续兼容 size/reused 二元组解包，并额外提供实际 `path`；各调用端必须用该路径生成 FileRecord。小说与动图原始文件的关联元数据随组选择新基名；Twitter GIF/MP4 和可选原始副本也按组分配。自动改名后的 ugoira ZIP 仍不会进入普通 ZIP 自动解压流程。FANBOX 元数据刷新使用文件锁及原子替换，但不因媒体冲突策略停止刷新。

Twitter 成功/失败、账号下载历史及隐藏历史使用完整读改写事务；先获取路径内核锁，再获取进程内缓存锁，锁内强制读取磁盘记录并深复制后修改，原子替换成功才发布缓存。格式损坏阻止更新或清空；历史清理先验证选中记录文件，JSON 失败时不继续删除数据库历史。单文件原子性不等于多个 JSON 与 SQLite 的整组事务。锁依赖当前版本进程共用的输出锁目录，旧版及外部程序不遵守该锁时不受保护。

`TaskManager` 管理排队、运行、取消、重试和完成状态。平台通过 `CallbackSet` 上报日志、进度与文件，公共存储层把任务、历史和文件索引写入 SQLite。

批次监视由任务队列界面维护目标顺序：优先显示正在运行的批次成员，否则显示下一项排队任务。手动选择其他任务会暂停该批次的自动聚焦。任务取得平台并发槽位时，管理器先更新 SQLite 状态并发出 `running` 事件，再执行可能较慢的目标预览；释放槽位后的最终状态由存储和 `done` 事件更新。状态轮询读取全部最近任务并逐行更新；列表的“当前操作”列也按 `task_id` 保存与刷新，因此多个并发任务能各自显示状态和最新进度。汇总栏分别统计运行、停止中及排队数量。Twitter 爬虫为每个媒体文件发送开始与结果进度事件，并在文件成功或复用时发送 `FileRecord`；选中任务的详情区显示该任务正在处理项目数和最近媒体操作，日志保留逐项完成、跳过及失败原因。UI 事件泵按数量和时间片处理队列，日志批量写入文本控件；任务状态轮询只原位更新发生变化的行，任务详情限频刷新，防止媒体事件连续到达时界面被重绘拖住。详情筛选和导出使用任务最近 500 条日志。

任务队列的日志清理使用精确任务 ID 删除 SQLite `logs` 行，不修改 `tasks` 状态、`files` 索引和磁盘媒体；运行中任务在清理后会继续写入新日志。日志表设有软保留上限（默认 20000 行），每 200 次写入清理超额旧行；删除行不会自动缩小数据库文件的物理体积。

平台可以声明并发上限。达到上限后的任务保持排队，当前任务结束后自动取得空闲槽位。取消操作会向爬虫传播 `TaskCancelled`，浏览器、网络请求和后处理都应尽快结束，并按对应传输链路清理临时文件或保留可验证的续传状态。

取消请求通过 SQLite 条件更新，仅把 queued/running 改为 cancelling，避免已结束任务在移出内存运行表之前被迟到的取消重新打开。下载后的文件补录和归档阶段结束时也会检查取消标志。

Twitter 下载链路用 `PendingMediaTracker` 追踪已发现的未完成媒体：入队时登记 URL、媒体类型和文件名基址，完成或跳过时移除，失败时记录原因。`crawlers/twitter/service.py` 的 `report_pending_summary` 在存在未完成项时输出数量，并按原因文字分类。若任务选项开启 `save_unfinished_txt`，在输出目录写入 `未完成_<任务ID>.txt`（UTF-8 BOM）；文件名按默认扩展名推导，作为恢复参考，原始下载地址和已有原因保持可用。该选项默认关闭，由 UI 新建和重试路径传入；其他平台尚未接入。它只涵盖已发现媒体，不能代表远端全部资源；TXT 中的原始 URL 不做日志式脱敏。

10-29 新增独立的 `core/media_results.py` 和 SQLite `task_media`。Bluesky/Instagram 静态链路发送一次 `media_plan`，由管理器在同一事务登记全部候选；逐项通过 `media_result` 登记 saved/reused/failed，未处理保持 pending。完整计划不重复写日志，清单不受日志保留上限影响；删除任务时同步清理。`partial` 加入公共终态集合，存在未完成项时跳过公共归档并显示数量。`supports_media_retry` 是适配器的显式接入标记，外部替换适配器不会仅凭平台名获得补下能力。

`retry_task(..., failed_only=True)` 读取未完成描述，创建独立任务并保存原目录、页面、序号、类型及媒体路径摘要。平台刷新页面后校验摘要，目录解析必须留在原输出根目录；CDN 主机和查询变化不改变摘要，路径变化则拒绝。补下任务禁用公共后处理；成功后将原记录改为 repaired，并沿仍存在的补下任务关系向前更新，保留原任务/批次终态。当前不将任意签名 URL 当稳定身份，也不允许跨刷新地址无条件续传。模块未覆盖 Twitter 原追踪器、其他平台或 Instagram 浏览器回退，本轮未运行回归。

`rename_downloads` 与 `delete_source_after_rename` 默认开启，通过界面任务选项传入 Twitter 配置，实际在 `download_pic` / `download_video` 中使用。前者控制是否采用日期、推文 ID 和序号，后者控制重命名时移动还是复制原始名文件；GIF 经视频路径时也受影响。音频及其他平台继续使用各自规则。改变设置不会迁移已有文件。

任务队列顶部的进度条采用跨任务聚合计算：UI 维护 `_task_progress_state` 字典，按 `task_id` 记录每个活跃任务的 `current`、`total` 和 `status`。进度事件支持三种格式——直接 `percent`、`current/total` 计数对、或仅 `status`（回退到 3% 排队 / 8% 运行中）。聚合值为所有排队和运行中任务的 `sum(current)/sum(total)*100`，任一任务推进都会刷新进度条。任务 `done` 事件将该任务从状态字典移除并重算：有剩余任务时显示剩余聚合进度，无剩余任务时成功设 100%、失败设 0%。Twitter 媒体回调在每个媒体处理开始时递增 total、结束时递增 done，使进度条随实际下载量移动而非停在固定值。

## 下载与文件处理

`core/network_policy.py` 的 `HTTP_BACKOFF` 在进程内按规范化 hostname/有效端口保存单调时钟期限，统一处理数字/HTTP 日期 Retry-After 与非法值回退；有效期限不再截到 300 秒，超出系统等待范围时明确失败。仅 429/503 发布共享期限，更新取较晚时间，成功响应或单任务取消不清除其他任务期限；请求耗尽本地重试也会发布。最多保留 1024 个主机，满额保留已有活动期限，新主机仍使用调用端本地等待，过期项按需回收。缓存不保存 URL 路径、查询或凭据。

公共 HTTP 传输与网页手动重定向在每一跳检查期限；Twitter 请求与公共 JSON 记录入口和可获得的最终主机，自动重定向中间跳未逐跳接入。JM `_get_response` 也协调共享期限，原有站点内部挑战回退保留。浏览器、HLS/FFmpeg、BT、其他进程及未接入的 Session 请求不受此协调控制。

`network_task_scope` 用 ContextVar 绑定当前 TaskManager 工作线程的取消控制，覆盖预览与下载中的同步元数据辅助调用，退出时还原；不会共享代理/超时配置，也不自动传入平台自建子线程。等待不持有协调器锁，每 0.1 秒重读期限，支持延长、协作暂停和取消；有显式 cancel_event 时优先使用它。直接调用辅助 API 且未提供事件/任务作用域时，同步等待不具备任务取消能力。

`core/bandwidth.py` 提供进程内唯一 `MEDIA_BANDWIDTH` 预算。`enabled` 与 KiB/s 数值分别保存，默认关闭；任务管理器启动时读取保存值，设置页整组事务提交成功后立即更新预算，失败不更新。网络代理/超时仍是任务独立快照，只有速率预算按设计共享并实时调整。

预算使用单调时钟、Condition 及最多 0.1 秒额度的桶；消费者以小额度轮转，限制所有受支持任务的累计源字节消费。关闭/调速通知等待者，取消最多等待一个短时间片；暂停任务先离开额度队列，再进入 TaskControl 检查点，避免占住队头。公共 HTTP、Twitter 图片及音频流、JM 下载图片/封面和网页直连媒体通过 limited_chunks/limited_content 计费；JM 媒体请求改为流式读取并明确关闭响应。

这是应用层读取节流，存在网络缓冲；不控制资料请求、浏览器响应、FFmpeg/HLS、BT 或其他进程。手工验收脚本 `tests/manual/verify_bandwidth_smoke.py` 只连接本机临时 HTTP 服务，生成样本并测量并发总预算、运行中关闭及取消，不访问真实平台。

公共下载能力集中在 `software_app/crawlers/common.py` 和 `software_app/core/`，包括以下内容。

- 统一请求超时、代理、重试和原子写入；
- 文件名清理与输出目录规范化；
- 图片格式转换、漫画长图和 PDF；
- ZIP 压缩、解压和路径穿越防护；
- aria2 BT 任务、取消和停止做种；
- 下载文件登记与历史索引。

`common.download_file` 委托 `core/http_transfer.py`，入口与最多 5 次重定向均执行 `validate_external_url`；`common.request_json` 仍只在入口检查并由 Session 自动跟随跳转。两者检查 http/https、主机及解析出的受限网络地址，DNS 结果带内存缓存，但无解析结果时未强制拒绝，不能当作全链路 SSRF 防护。网页模块的 `_request_public_url` 也逐跳检查；浏览器抓取和其他直接 Session 请求需分别核对。

公共 HTTP 引擎使用目标旁的 `.part` 和 `.resume` 记录传输状态，记录原始请求 URL 的 SHA-256、强 ETag 或 Last-Modified 及总长度。续传核对 Content-Range 起点、总长度、验证器及实际字节数；200 会重写临时文件，416 或错误范围会回退完整请求。可验证的部分数据在失败/取消后保留，缺少验证信息的部分数据删除；完整文件提交失败则保留 `.part`。分块循环可协作暂停，仍无重启自动恢复队列或 HLS 分片恢复。

`core/output_lock.py` 使用 Windows 字节范围锁或 POSIX flock，在操作系统解析的当前用户固定目录保存路径哈希对应的锁文件：Windows 为 Local AppData 下 `yuqiuda/output-locks`，POSIX 为系统账号主目录下 `.cache/yuqiuda/output-locks`。目录不依赖 TEMP/TMP、安装位置或数据库，解析失败不回退临时目录；不保证跨系统账号互斥。升级前须关闭所有仍使用临时目录锁的旧版实例。进程退出时内核释放锁；锁文件不删除，避免等待者持有旧 inode。多路径按规范路径排序，线程内允许重入。`download_media_file` 覆盖源文件下载、转换与成品复用；Twitter 媒体及 JSON 记录、Pixiv 动图/小说、JM 章节及合成、Bluesky HLS、网页落盘和 ZIP 创建/解压也接入输出锁。解压目标只允许新目录，提交前再次检查目标是否已出现，不覆盖新出现的目录。10-29 的目录调整尚未运行回归。

Twitter 图片、视频落盘重命名使用 `replace_with_retry`，最多尝试 5 次。视频从完整 `.part` 转为原始文件名失败时保留 `.part`；从原始名转为目标名失败时保留原始文件，日志分别说明恢复位置。

Twitter 网络参数由 `configure_downloads` 构造为不可变 `DownloadNetworkConfig`，通过函数参数传到单帖直连、浏览器媒体工作线程、CLI 并行任务和头像缓存请求，不再修改模块级配置。请求只对 408/425/429、5xx 和请求异常有限重试；Retry-After 支持数字秒和 HTTP 日期，任务事件可中断等待。

Twitter 下载浏览器从任务配置取得代理，在线资料、关注刷新与头像缓存从已保存的 GUI 设置取得代理；值在启动工作线程前读取。`initialize_driver` 传入 Chrome 的 proxy-server 参数，对 socks5h 使用浏览器支持的 socks5 表示。留空时保留 Chrome 的系统代理行为。

Twitter 成功/失败 JSON 的完整读改写过程由路径内核锁协调多个当前版本进程，进程内共用缓存。缓存通过 mtime_ns、大小和 inode 检查替换或删除，写入时仍强制重读；失败提交保留原文件与已提交缓存。默认复用策略下，历史记录与媒体文件存在分别检查，媒体已删除则允许重新下载；覆盖、报错和自动改名策略不会被成功历史提前跳过。新记录保存实际成品的绝对路径。

平台爬虫只负责生成可信媒体地址和元数据，不应绕过公共安全规则自行写入任意路径。

## 数据与安全边界

`core/library_service.py` 对完整索引提供组合筛选、流式 CSV 导出和固定清理计划。导出不读取 metadata_json，不受界面显示上限限制；临时 CSV 完整成功后原子替换，识别到的 URL 查询凭据会脱敏，并处理文本公式前缀。独立 `ui/library_tools.py` 工具窗口通过后台线程和自己的事件队列操作，Tk 控件只由主线程更新。

文件表新增 `revision` 字段，旧数据库自动补列；每次 upsert 或重命名生成新标记，清理用路径和标记共同限定目标，避免删除预览后更新或删后重建的索引。清理计划最多 10000 项，回收还核对文件大小、mtime_ns、设备及文件标识，并拒绝相对路径、符号链接及目录联接。Windows 8.3 短路径允许正常使用，不以字符串拼写差异判断链接。

原有文件选择入口使用 `plan_library_paths` 按精确索引键取得快照，不把选择扩展成搜索。`rename_library_file` 在维护门禁、源/目标锁及 BEGIN IMMEDIATE 事务内检查共享任务、索引版本、文件状态和目标占用，失败时尝试恢复文件名；选中回收复用 `execute_library_cleanup`，与新工具窗口遵守相同规则。

清理使用管理器维护门禁阻止本进程新建任务，要求当前任务（含暂停）已结束；每个项目在非阻塞输出锁及 SQLite BEGIN IMMEDIATE 事务内重新检查共享数据库中的活跃任务、索引版本及文件状态。检测到新任务停止后续清理，失败项保留索引。文件回收与 SQLite 不是同一个原子事务；文件已经回收但数据库提交失败时，仍可能留下缺失文件索引，后续预览可识别。任务/日志及平台 JSON 记录不会在此流程中删除，其他数据库或不遵守锁的外部程序不受门禁约束。

运行数据位于 `data/software_app/`，包括 SQLite、Cookie、浏览器资料、任务记录和缓存。该目录不会进入源码仓库。

SQLite 连接尝试启用 WAL、`synchronous=NORMAL` 和 `busy_timeout=5000`，不支持时忽略设置错误并继续使用可用模式。设置页通过 `set_settings` 在单个事务中保存整组配置；启动及任务参数构造通过 `get_settings` 读取配置快照，避免逐项建立连接。文件表新增 `(task_id, updated_at DESC)` 索引，加速任务详情查询。

`scan_media_files` 默认最多进入 6 层子目录；传入 `modified_after` 时逐文件检查 mtime，继续遍历旧目录，避免父目录时间不变时漏掉已修改的文件或后代目录。深度上限仍可能排除更深的产物。

外部请求应检查协议、主机、凭据和跳转目标；当前公共下载入口与网页逐跳检查的覆盖范围如上，不应据此推断所有平台的直接请求均有相同防护。EH 会话显式隔离表里站、图片和种子主机；其他平台的 Cookie 发送范围仍以各客户端实现为准。

任务异常信息在写入 `tasks.error` 前经过 `safe_error_message`，替换 URL 中命中敏感名称的 query 值，并对识别到的 Cookie/Authorization 等头值做正则脱敏；界面任务选项另用 `redact_sensitive_data` 处理。它们不保证清除任意格式的凭证、全部日志文本或原始数据库记录。Cookie、缓存、错误样本及导出文件仍需检查后再公开；未完成 TXT 有意保留原始媒体 URL。插件以当前用户权限运行，只应启用已经阅读并信任的代码。

## Windows 打包与启动兼容

PyInstaller 通过 `pyinstaller_hooks/rthook_force_stdlib_json.py` 固定 Requests 使用 Python 标准库 JSON。Requests 会把可导入的 `simplejson` 当作完整可用的可选依赖；旧版目录包若留下不完整的 `simplejson`，程序会在启动导入阶段因缺少 `JSONDecodeError` 退出。当前 spec 将 GUI 和 CLI 都构建为单文件包：Python 运行库及爬虫资源在启动时解压到系统临时目录，exe 不再依赖旁边的 `_internal`。运行数据仍以 exe 所在目录为根写入 `data/`，因此 exe 应放在当前用户可写入的位置；更新时关闭程序并替换 exe，保留 `data/`。

## Pixiv 单作品图片接续

`crawlers/pixiv/media.py` 在客户端已有作品类型、黑名单及 AI 检查后，接管单作品的普通插画/多页漫画；一次登记完整页列表后逐页传输。`_retry_media` 路径只接受原单作品描述，重新读取详情及页列表，检查当前过滤和原图路径，再复用统一冲突与图片下载器。补下元数据失败在本轮缓存，不为每个页号重复发请求；不通过循环最后一个异常文本决定错误类别。

集合任务、动图和小说等尚无完整发现计划，不能因为 `supports_media_retry` 标记为 True 就从中恢复图片子集。当前只有单作品静态路径生成清单，其他路径沿用原流程。新入口没有复制第三方实现或引入新依赖；参考了 [PixivUtil2 README](https://github.com/Nandaka/PixivUtil2/blob/master/README.md) 中的图片检查、页码和已有文件处理约定，实际策略仍由本项目四种冲突选项控制。

公共 `download_media_file(verify_image=True)` 将图片检查/转换范围中的无 errno/winerror 的解析异常包装为 `InvalidMediaError`，保留结构化 invalid_media 标签；磁盘错误和取消不改成坏图错误。新单作品路径也检查复用图片。依据 [Pillow Image.verify 说明](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.verify)，该方法不等于完整像素解码，不能据此宣称所有损坏或安全风险已排除。

`TaskManager.start_task` 与 `restore_interrupted_task` 共用 `_protect_media_retry`，对携带 `_retry_media` 的入口统一关闭归档、解压和源文件清理，防止批量重试或旧的中断参数重新带入归档选项。无效或空的显式补下计划在接管前被拒绝，保留恢复标记；有效参数与条件接管在同一 SQLite 事务中保存。执行中根据已有清单计算出的空待办列表仍可正常结束，不会重下成功项。Pixiv 声明 `reports_files=True`，成功零产出不触发兼容扫描；有清单的失败/取消任务依赖明确结果，不扫描同目录其他任务的近期文件。未被明确登记的落盘产物可以由用户主动扫描，不能把目录时间匹配当成可靠的任务归属。

用户授权测试后，首次沙箱运行受 Windows 临时目录和固定用户锁目录权限影响，不能据此判断应用缺陷。沙箱外首次完整回归运行 596 项，发现 2 项失败、6 项错误，集中在 Windows 源文件身份比较、迁移测试未关闭连接及新增设置后的数量断言。修复并新增 9 项回归后，102 项定向回归通过，605 项完整回归通过；具体耗时和最终原生桌面报告见更新日志。

本机 Python 3.12.4 的最小样本复现了路径 `lstat().st_ctime_ns` 与句柄 `fstat().st_ctime_ns` 不同，而 dev/ino/size/mtime/birthtime 相同的情况。该现象与 [CPython #157671](https://github.com/python/cpython/issues/157671) 描述的 Windows 时间语义差异一致，但上游问题中的 Python 3.14.7 不是本次运行版本。依据 [Python 3.12 os.stat 文档](https://docs.python.org/3.12/library/os.html#os.stat)，Windows 创建时间优先使用 `st_birthtime_ns`；旧版缺少该字段时保留 `st_ctime_ns` 兼容。POSIX 仍保留原 ctime 检查。

`archive_service` 跨路径/句柄比较使用文件标识、大小、mtime 和一致的创建时间；同一句柄读取前后另保留 ctime 检查，不将它与 Windows 路径 ctime 混比。归档提交前复查、内容摘要及清理前整组预检继续保留。新增回归覆盖两种 Windows 时间语义、旧版本兼容、POSIX 时间语义、压缩中变化及清理读取时变化，不通过删除安全校验来使回归通过。文件锁仍只约束合作写入者，不能承诺消除外部程序在检查与删除之间的所有竞态。

迁移测试使用 `contextlib.closing` 显式关闭手工创建的 SQLite 连接；[sqlite3 连接上下文说明](https://docs.python.org/3.12/library/sqlite3.html#how-to-use-the-connection-context-manager) 明确普通连接上下文只管理事务，不负责关闭连接。应用自己的 `AppStorage.connect` 已在 finally 关闭，本次没有更改其生命周期。

### Cookie 记录及请求策略

`core/cookie_store.py` 读取旧名称字典、JSON 数组／cookies 数组、Netscape 和请求头文本，最多 10 MiB／20000 条。记录保存域、路径、secure、httpOnly、hostOnly、sameSite 和规范化 expiry；相同名称的不同域／路径不会压平。浏览器保存和指定平台导入改写为记录列表，合并时新记录替换同名旧无域值，其他域保留。旧文件不自动重写，也不能恢复其已经丢失的属性；必要 Cookie 为空或已过期拒绝保存。

`load_cookie_file` 保留名称字典兼容视图，只供名称检查等旧接口使用。`make_session`、FANBOX 子会话、EH 客户端和 JM curl 传输使用完整 CookieJar。旧无域值依据所选平台或 Referer 提供默认范围，已有显式域／路径保持原值；HTTP 的 JM 自定义站点不被默认强制标为 Secure。JSON expiry=0 按过期处理，Netscape expiry=0 按其格式约定表示会话 Cookie。

源码核对发现，Requests `prepare_request` 会把 Session Cookie 合并进新建默认 Jar，因此仅复制原 Jar 的 CookiePolicy 并不足以让请求采用该策略。新增 `CookieSession.prepare_request` 在没有显式 Cookie 头时重新合并记录、复制策略并重新准备 Cookie 头，采用严格的 hostOnly 返回规则。显式 Cookie 头仍属于调用方责任；跨站及匿名入口继续删除它。SameSite 属性被保存，但未仿造浏览器完整的站点上下文与第三方 Cookie 行为。

依据：[Python 3.10 CookieJar 与 CookiePolicy](https://docs.python.org/3.10/library/http.cookiejar.html)、[Requests prepare_request 源码](https://requests.readthedocs.io/en/latest/_modules/requests/sessions/)。这些资料支持策略与合并机制的设计判断，不代替本项目的运行验收。

### 有界响应读取

`core/response_read.py` 流式累计解码后的字节，JSON 默认 32 MiB、HTML 默认 16 MiB、JM 域名发现 1 MiB；超限抛出 `ResponseLimitError`，不把前缀解析为成功结果。存在无压缩 Content-Length 时先检查声明值，压缩响应按实际解码后大小控制。每块前后调用请求检查点，继承任务作用域的暂停／取消；不承诺中断已进入的 DNS、连接或读取。

公共 JSON、Pixiv HTML、FANBOX/Sketch JSON、Bluesky、Instagram 静态、EH 页面／元数据、JM API 和 JM 网页读取采用该入口；EH POST 也改为 stream=True。JSON 使用标准库从完整的有界字节解析，HTML 沿用响应编码并有 UTF-8 回退。响应仍由调用方 finally 关闭。字节上限不等同于解析后对象或整个进程的内存硬上限，curl 的后台缓冲也不由消费循环直接限制。参考 [Requests 流式读取说明](https://requests.readthedocs.io/en/latest/user/quickstart/#raw-response-content)。

### JM curl 会话与关闭顺序

JM 网页和连接检查经统一逐跳 GET；`_JmCurlSession.for_redirect` 新建独立 curl Session，复制必要的浏览器指纹、CA、代理以及有域 Cookie，过滤敏感头，不共享源站客户端认证或浅拷贝句柄。配置来自应用创建的 JM 会话，不泛化为可复制任意第三方 Session 的协议。Cookie 通过完整 CookieJar 传入 curl，域／路径属性不再被名称字典丢弃。

临时会话由 `_OwnedResponse` 保持到最终流式响应关闭：先关闭原响应，再释放所属会话；跳转验证、请求及异常路径提前失败时由统一入口 finally 清理。普通 Requests 的浅视图继续共享适配器，不按此协议单独关闭。JM 初始化失败会清理已创建的 curl 与 Requests 后备会话。参考 [curl_cffi Session 源码](https://curl-cffi.readthedocs.io/en/latest/_modules/curl_cffi/requests/session.html)，并对照本机安装的 Cookies 构造／update 实现确认 CookieJar 支持；没有运行 curl 或平台请求。

刷新从请求前到提交后持有同一路径的既有内核输出锁，竞争刷新立即失败；原子替换只解决提交可见性，不能代替串行化整个读改写。写前核对当前 Cookie 账号；绑定账号缓存不向其他账号或无法识别的账号展示。错误信息经既有脱敏后保存。本地读取展示所选范围、页数、发现数量、停止原因及保留旧数量；完整性标签不再泛指全部公开和私密缓存。

缓存包含诊断偏移，但未提供分页恢复协议：没有逐页写盘，强制退出可能丢失本次发现；新的刷新仍从零偏移开始。集合逐媒体结果、补下、任务级发现身份和过滤恢复均未在本轮实现。参考文件与官方资料见 [参考源码评估](参考源码评估.md) 新增节。

`require_downloadable_discovery` 在作品／小说收藏集合传输前校验停止原因：正常结束和用户数量上限可进入下载，其余提前停止明确失败。它不把异常发现子集变成成功集合，也不增加对作者／排行等其他集合的完整性保证。自己的缓存刷新仍可保存部分发现，保持诊断与下载结果的不同语义。

仅 Ruff 基础／扩展、25 文件格式、158 份 Python 3.10 AST 及差异空白检查通过；没有新增或运行测试、临时模拟、GUI／浏览器、真实账号请求或已有数据迁移。后续验收需要覆盖重叠分页、服务器忽略偏移、半程失败、公开／私密切换、空结果、并发刷新、账号切换和原界面交互。
