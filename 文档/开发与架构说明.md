# 欲求达：内容发现与下载软件说明

这是按 `历史资料/原始需求.txt` 重新整理的一份独立软件骨架。旧脚本目录保持不动，新版软件维护自己的推特爬虫副本。

截至 2026-09-13，软件按 Twitter/X、Pixiv、JMComic、Google 相似搜索四个平台继续开发。Google 是辅助发现工具：`Google 相似图片发现候选页面 -> 用户选择 -> 软件内置网页资源爬虫下载`；网页资源模块是这条链路的执行器，不是第五个外部平台接入。

## 启动

启动桌面界面：

```powershell
python ./run_software.py
```

常用命令：

```powershell
python ./run_software.py modules
python ./run_software.py browser-driver
python ./run_software.py browser-driver --download
python ./run_software.py preview twitter '@username' -t 1,2,3,4
python ./run_software.py twitter-profile '@username'
python ./run_software.py twitter-profile '@username' --local
python ./run_software.py twitter-history --limit 50
```

## 新目录

- `software_app/core/`：模块接口、任务管理、SQLite、事件模型、全局 ChromeDriver、所有平台复用的普通 Chrome 登录资料根目录与 Cookie 读取/解密能力、Bluesky 临时认证账号操作，以及公共安全压缩/解压后处理。普通 Chrome 共用同一个已安装 Chrome 和底层代码，但每个平台/账号使用隔离资料目录；已有 JMComic 旧资料原地兼容，不复制凭据。
- `software_app/adapters/`：轻量站点边界，负责统一任务模型转换；内置平台也通过统一插件注册器加载。
- `software_app/crawlers/twitter/`：软件内置 Twitter 爬虫；原始 `推特爬虫/` 只作更新参考。
- `software_app/crawlers/pixiv/`：软件内置 Pixiv 平台插件，标记为可用，包含作品/ugoira、作者、系列、小说、排行、新作、收藏、FANBOX、Sketch 和分页关注画师；登录、付费和地区网络限制仍按具体任务提示。
- `software_app/crawlers/jmcomic/`：软件内置 JMComic 爬虫，当前标记为可用；登录、Cloudflare 和站点结构变化仍按具体任务提示。
- `software_app/crawlers/google_image/`：Google Lens 相似页面发现模块，只提供候选 URL，不直接下载候选站点内容。
- `software_app/crawlers/webpage/`：软件内置网页资源爬虫，接收用户选中的候选页面，提取并下载其中的图片、视频和音频。
- `software_app/ui/`：Tkinter 桌面骨架。
- `run_software.py`：新版程序入口。
- `data/software_app/content_downloader_v2.db`：新版 SQLite 数据库。
- `data/software_app/browser/chromedriver.exe`：源码模式下所有需要 Chrome 的爬虫共用的全局 ChromeDriver。检测会实际执行驱动读取版本；缺失、损坏或与 Chrome 主版本不符时，自动安装流程从 Chrome for Testing 精确选择匹配版本并原子替换。
- `data/software_app/json/<platform>/`：按平台保存结构化运行数据；Pixiv 的 Cookie 与关注缓存从该目录读取。Cookie 文件受 `.gitignore` 保护，不应提交或分享。
- `data/software_app/twitter/`：推特 Cookie、配置、下载记录、关注列表、下载作者历史和主页预览缓存。

Windows 发行版采用 PyInstaller `onedir`：桌面版和诊断 CLI 共用 `_internal` 依赖，内置 FFmpeg 与经过固定 SHA-256 校验的 aria2 官方 ZIP，但明确排除构建机 ChromeDriver。冻结运行时把 SQLite、Cookie、浏览器资料和外部工具写入 `%LOCALAPPDATA%\YuqiuDa\data\software_app`，默认媒体输出到用户 `Downloads\欲求达`；`YUQIUDA_HOME` 与 `YUQIUDA_OUTPUT_DIR` 可覆盖两处位置。安装说明见 [Windows 打包与安装](Windows打包与安装.md)。

桌面端源码发布在 [fast-get-it](https://github.com/xiaohaoyiqu/fast-get-it)。`油猴脚本/` 是 [tempermonkey-scripts](https://github.com/xiaohaoyiqu/tempermonkey-scripts) 的独立工作副本，主仓库会忽略它。目录和提交边界见 [仓库与目录说明](仓库与目录说明.md)。

## 桌面界面布局

桌面 UI 已按页面职责拆分：`tk_app.py` 负责主窗口、平台工作台和跨页面事件协调；`library_tab.py`、`google_search_tab.py`、`settings_tab.py`、`task_queue_tab.py`、`following_tab.py` 分别负责下载库、Google 相似图片、设置、任务队列，以及各平台关注/候选和历史。页面模块通过 Mixin 组合到主窗口，且不反向导入主窗口，后续修改某一页不必继续扩大单个近 5000 行文件。

候选页的操作区按职责分行：更新、本地读取、单项操作、范围说明、选择状态、批量操作、关注进度分别占独立行。只有 Twitter“关注账号”和 Pixiv“关注画师”显示关注进度，普通作者/作品搜索与收藏不会被无关进度条向右挤动。说明文字和动态状态横跨整行并按容器宽度换行。左侧资料卡把外链下拉框与“打开外链 / 复制地址”拆成两行，简介固定四行并带滚动条，因此长简介、长链接和新增按钮都不会超出 330 像素侧栏。

右侧“相似搜索”页签提供当前主流程：选择单张本地图片，或递归读取文件夹内最多 20 张图片，设置每张图片的候选数，再执行 Google 相似搜索；结果会按 URL 去重，并以带查询图片来源的多选表格显示。用户可以全选、取消选择、在系统浏览器打开候选、检查 HTTP 状态、手动标记客户端页面失效、导出候选，或把选中的页面批量加入下载任务。404/410 失效项不会建立下载任务；登录受限和临时网络错误不会误判为删除。原查询图片不存在时保留旧候选但禁止直接重新搜索。所有候选都保持“网页详情页”语义并交给网页资源爬虫，不根据域名擅自切换到 Twitter/Pixiv 下载器；Google 搜索不会自动下载未选择的结果。

界面采用深蓝侧栏、中性浅色工作台和靛蓝主操作色。左侧目标搜索、目标/历史列表和结构化预览会跟随顶部平台切换：Twitter 显示关注与下载作者，其他平台显示自己的最近任务与使用说明，不再固定显示 Twitter。右侧候选与历史页签也会同步改名并换数据，例如“推特关注/候选、Pixiv 作品候选、JMComic 漫画候选、Google 页面候选”以及各平台自己的历史；切到 Google 时会自动进入保留的相似搜索页。

左侧搜索框在 Twitter 下支持 `@用户名`、用户名或昵称。本地记录没有精确用户名时，也会生成可在线刷新的主页候选。Pixiv 和 JMComic 走各自软件内置搜索器；Google 不复用这个搜索框，避免与相似搜索页发生入口冲突。

页面头部集中显示当前状态和“开始任务、本地预览、在线获取资料、打开网页、取消”操作。“本地预览”只读已经保存的资料；“在线获取资料”是自动资料抓取，抓取完成后自动化浏览器会关闭并把资料渲染回软件；“打开网页”使用系统浏览器并保持页面，供用户继续浏览或手动操作。`https://x.com/home` 会先识别当前登录账号，不再误判为名为 `home` 的作者。下面的手动任务参数区分为两行：

- 第一行：平台、保存路径、浏览。
- 第二行：目标 / URL、下载类型。

“相似搜索”页采用三步工作流提示。左侧显示查询图片、尺寸和文件大小，右侧显示候选网站与 URL、结果总数和已选数；没有候选时预览和爬取按钮会明确禁用。选图对话框在存在 `D:\img_download` 时优先从该目录打开，但不会复制或修改里面的原图。

Google 页可设置“验证等待（秒）”，范围 0–300，默认 60。搜索使用可见浏览器；遇到人机验证时用户可在浏览器里手动完成，工作台会显示倒计时，检测到候选结果后会提前结束等待。
验证页中的 `schema.org`、W3C 等页面结构地址不会被当成搜索结果；用户手动关闭浏览器会作为正常结束处理。
文件夹批量搜索按文件名稳定排序，单批最多读取 20 张、最多保留 1000 个去重候选；停止或后续图片搜索失败时保留前面已经取得的结果。候选可导出为 CSV、JSON 或纯 URL 文本，CSV 会防止名称等外部文本被表格软件当成公式执行。

任务队列增加状态汇总、进度条、中文状态名和完成/失败/取消背景提示。任务可用 Ctrl/Shift 多选后批量重试、取消或删除记录；删除运行中任务会先正常停止浏览器/下载线程，完成收尾后再删除数据库记录，本地文件始终保留。单选时下方详情区会显示原始输入、规范化目标、输出目录、参数、错误、按时间排列的日志和该任务已入库文件，还可重新填入工作台或打开输出目录。窗口退出时如有活动任务会先提示，确认后统一取消并等待资源释放；异常退出遗留的假运行状态会在下次启动恢复为已取消。候选表格、任务详情与其他长列表均保留水平和垂直滚动条。

“设置”页已接入 SQLite 全局设置：默认保存目录、无凭据代理 URL、失败自动重试次数、Google 每张候选数/人工验证等待、Pixiv 单任务作品上限/明确 AI 过滤/公开私密范围/日期/最低收藏数/R18 分区、公共 ZIP 压缩/解压，以及网页爬虫每页文件上限和 30–600 秒读取超时会跨启动保留，并进入之后创建或重试的任务。普通网页默认 HTML 读取 60 秒、媒体读取 120 秒。设置内容区带垂直滚动条和鼠标滚轮支持，小窗口仍能操作底部选项。设置页还显示每个平台接入插件的用户用途、来源、状态和接管关系，并提供“检查 Pixiv 连接/头像”、插件目录和 Chrome/ChromeDriver 检测；平台 Adapter 与公共压缩后处理会在界面中明确分区。`core/browser_cookie_capture.py` 为 Twitter/X、Pixiv、FANBOX、Instagram 提供临时可见浏览器登录；JMComic 与 EH 使用普通 Chrome 两阶段流程，登录期间不连接自动化，关闭专用窗口后才读取本机 Cookie 数据库并在线验证。EH 表站/里站各自拥有独立 Chrome 资料和正式 Cookie 文件。所有流程均不接收或保存账号密码，也不会输出 Cookie 或代理凭据；任务详情展示参数前会递归隐藏 Cookie、token、密码、密钥和含凭据 URL。

对于 Twitter，“本地预览”只读取本地结构化资料，不打开主页浏览器。资料来源优先级是：主页缓存 `profile_previews/` > 关注列表 `following_accounts.json` > 下载历史 > 手动输入。若关注资料已经带有 Twitter 官方头像 URL，界面会在后台只下载并缓存该头像，完成后立即显示；这不重新抓取主页。需要最新简介、Skeb 或其他主页外链时，再点“在线获取资料”，这个按钮才会启动浏览器访问 X。

“推特关注”和“推特历史”页都有明确的“填入上方目标框”/“填入目标”操作，候选页会显示当前选中项。“在线获取资料”可继续抓取并把资料渲染到左侧目标浏览区。历史页支持多选清理选中项和清理本平台全部，只移除历史/数据库索引，不删除本地媒体。

左侧列表点击后会显示持久高亮和“已选中 · 来源 · 名称”。点击本身不触发列表刷新或跳回顶部；后台资料更新确实重建列表时，会恢复同一目标与原滚动位置。列表支持多选“加入选中到下载队列”，所以搜索、关注和历史结果都可直接下载，不必先逐条填入工作台。简介区固定为 4 行高并带滚动条，避免长简介遮住主页和外链控件。

推特关注页支持导入和导出。导入接受软件原生 JSON、CSV，以及每行一个账号的 TXT/LIST；按不区分大小写的用户名与本地缓存合并，非空的新字段更新旧资料，不因导入清空已有关注。导出支持 JSON 和带 UTF-8 BOM 的 CSV。

关注列表提供“更新新的”和“更新全部”。“更新新的”利用 X 关注页从新到旧的顺序，从顶部按不区分大小写的 handle 与旧缓存匹配；连续命中 30 个旧账号后停止，只把真正的新 handle 插到旧列表顶部。判断不依赖行号，因此取关造成后续账号整体移位不会被误报为新关注；增量更新也不会删除无法确认的旧记录。“更新全部”持续滚动到底，以页面完整现状替换缓存，并同步移除已取关账号。旧缓存少于 30 条时，增量重叠阈值自动缩小到旧缓存实际数量；没有旧缓存时，“更新新的”自动执行首次全量同步。

关注采集器在进程内同时读取 X 虚拟列表 DOM 和 Following GraphQL 响应；除账号、显示名、简介和头像外，也会合并 GraphQL `legacy.entities` 与懒加载行中显示的外链/Skeb。首批账号尚未显示时主动滚动，之后持续触发下一批懒加载。新账号会立刻保存并同步渲染到左侧目标浏览区和关注表。默认不按总耗时截断，全量模式只有账号数与滚动位置/页面高度连续 15 轮都没有推进才判定列表到底并自动关闭。运行时“更新新的”按钮变为“停止更新”；手动停止、显式兜底时限、浏览器关闭或页面暂未加载出内容时，不会用不确定的空数据覆盖上一次有效列表。

Twitter 下载历史会用关注缓存和主页缓存补齐头像、简介和外链。只有文件夹显示名唯一对应一个已知 handle 时才合并旧记录，避免同名作者串号。媒体下载开始前还会复用该次登录浏览器尝试刷新作者主页资料，因此从关注、历史或直接目标开始下载后，都可以继续使用本地预览；主页资料失败不会阻断媒体下载。

本机安装 Skeb 官方 “Skeb Button” 扩展时，Twitter 临时浏览器会只读加载扩展目录，并等待它向主页插入 `.skeb` 组件。软件从该组件读取经过 Skeb 官方确认的账号链接和状态；没有扩展时不构造 `https://skeb.jp/@handle`，避免把非 Skeb 用户误标为已接入。

候选页支持 Ctrl/Shift 多选、全选当前页和取消选择。“加入下载队列”会为每个预选目标建立任务并进入“任务队列”页；并发由 adapter 的平台上限控制，Twitter 当前最多 5 路，多出的任务显示为排队并在槽位释放后自动启动。

## 下载库布局

下载库按 `软件显示2.txt` 调整：顶部是平台/作者/文件夹列表、Unicode 多关键词搜索、“刷新/扫描”和“打开所选文件夹”；中间是可多选文件信息表，支持打开、复制一个或多个绝对路径、单文件重命名、把选中文件移到 Windows 回收站；底部是本地图片/文件显示区域。搜索覆盖平台、路径、文件名、类型、标题、作者、章节和标签，全角/半角与大小写统一，多个空格关键词同时满足才显示。扫描和缩略图解码均在后台运行；文件表单次只渲染 500 条，索引达到 100000 条时界面提示，以免低配置电脑被大量控件和图片解码拖慢。重命名会同步更新 SQLite 路径，移到回收站后只移除对应文件索引，不清空下载任务和平台历史。

手动扫描只为新发现的文件补索引，不再把已有文件改标成当前所选平台。清理平台历史与删除本地资源是两个独立操作：前者默认不删除媒体，后者必须在下载库明确选择文件并确认。

## HTML/Vue 渲染说明

左侧目标浏览区已经抽出 `TargetPreviewRenderer`。安装 `tkinterweb` 时会用 `TkinterWeb.HtmlFrame` 渲染软件自己生成的 HTML/CSS 目标卡片；没有安装时会自动退回 Tk 文本显示，不影响基础启动。

2026-09-12 已增加外部页面静态 HTML 快照管线：平台客户端可通过 `TargetPreview.metadata["page_html"]` 返回 HTML，在线预览会在后台获取并交给渲染器。外部 HTML 会移除脚本、表单、iframe、嵌入对象、事件属性和 `javascript:` URL 后再显示。该功能是安全静态快照，不等同于运行目标网站的 React/Vue 和登录会话。项目虚拟环境已安装并验证 `tkinterweb 4.25.4`；其他未安装该依赖的环境仍会自动使用文本回退。

渲染仍然分两档：

- 只渲染软件自己生成的 HTML/CSS 卡片：当前已经接入可选 `TkinterWeb.HtmlFrame`，适合头像、昵称、简介、主页、Skeb/外链这类静态预览。
- 运行完整 Vue/React 前端：应使用 `pywebview`、WebView2 或 CEF 这类真实浏览器内核。它能跑现代前端，但会引入浏览器运行时、依赖安装和窗口嵌入问题。

不建议直接抓目标平台的页面 HTML/Vue 源码来解析成相同界面。X/Twitter 这类站点是动态 React 页面，HTML 里大多是脚本和运行时状态；要复刻主页布局，更稳的是用采集到的结构化字段生成自己的 HTML 卡片，或者直接用 WebView 打开真实页面。

本地前端/UI 设计参考已记录在 `设计/界面设计记录.md`。
## 推特下载

界面顶部保留精确标签“下载类型”，旁边增加“说明”按钮。该选项当前用于 Twitter，支持用英文逗号分割：

```text
1       图片
2       视频
3       GIF
4       音频
1,2,3   图片+视频+GIF
1,2,3,4 全部
```

命令行也支持同样写法：

```powershell
python ./run_software.py download twitter '@username' -t 1,2,3,4
```

下载记录继续使用：

```text
data/software_app/twitter/downloaded_urls.json
data/software_app/twitter/failed_urls.json
data/software_app/twitter/downloaded_users.json
```

同一作者重复下载时会按下载记录跳过已下载内容。新下载完成后会额外记录目标作者到 `downloaded_users.json`。

## 推特主页预览

- 候选页排除屏蔽账号并显示排除数量；任务管理器在创建任务前拒绝已屏蔽的账号及可从 URL 直接识别作者的 Twitter/Bluesky 帖子。Pixiv 作品、FANBOX/Sketch 帖子在拿到作者资料后再次检查并跳过，避免作品 URL 不带作者 ID 时漏过。候选 CSV 导出也应用黑名单；原始收藏缓存、关注缓存和已下载文件不删除。
- 资料卡“管理黑名单”可按来源组移除。Bluesky handle 可变，DID 是长期标识；当前记录外链 URL 中实际出现的 handle 或 DID，不联网推断两者等价。Bluesky 原生下载器会在公开接口返回作者 DID 后保存到文件元数据。通用网页爬虫遇到作品详情 URL 时，如果页面未提供可识别作者，不能保证按作者屏蔽；这类目标应使用站点原生下载器或先提供作者元数据。
- 所有桌面新建任务、候选批量任务、Google 转交任务和批量重试都会携带当前公共归档设置。归档过程通过原任务日志和进度显示，取消与失败不会被记录为下载成功。

## 2026-09-18 黑名单管理与作品规则

- 黑名单仍自动保存在 `data/software_app/blocklist.json`。资料卡可直接“屏蔽作者”或“屏蔽作品/页面”；候选列表可批量屏蔽选中作者或作品；Google 相似图片候选可直接屏蔽、解除具体页面或作品。作者规则与作品规则相互独立：屏蔽某件 Pixiv 作品不会屏蔽作者的其他作品。
- “管理黑名单”现在列出作者组与作品/页面规则，支持按平台和文字查找、添加、修改、删除。选择具体平台后可读取或保存该平台的 JSON 名单；导入合并到公共黑名单，导出包含该平台的账号和作品，保留现有跨平台关联组。作者主页外链仍需手动确认关联，不依据作品外链推断同一作者。
- “读取平台名单”也接受 UTF-8 `.txt` 作者名单，一行一个账号、用户 ID 或作者主页 URL，`#` 开头为注释。旧 Pixiv 插件的 `blacklist_members.txt` 可直接按 Pixiv 平台读取；旧目录只包含相关代码，当前工作区没有实际名单文件。X 归档的 `block.js` 通常只有数字账号 ID，不能直接当作 `@用户名` 导入；纯数字 X 文本条目会被拒绝，需先取得对应的主页 URL。
- 平台 JSON 名单是本软件的本地规则文件，不会同步到网站账号，也不是网站原生格式。X 官方已停止网页端旧式屏蔽列表 CSV 导入/导出功能；Pixiv 网站的“屏蔽用户”主要限制互动，不能阻止查看资料或内容。因此软件内的下载过滤必须独立执行。参考：[X 官方屏蔽列表说明](https://help.x.com/en/using-twitter/advanced-twitter-block-options)、[Pixiv 官方屏蔽功能说明](https://www.pixiv.help/hc/en-us/articles/235644767-What-is-the-block-feature-in-pixiv)。
- 作品规则按站点 ID 匹配 Pixiv 插画/小说、Twitter 帖子、FANBOX 帖子、Sketch 作品、Bluesky 帖子和 Instagram 帖子/Reels；其他网站仅按规范化的具体页面 URL 匹配。创建任务时拦截直接命中的目标；Pixiv、FANBOX、Sketch 在逐件下载前再次检查；Twitter 时间线在识别到帖子 ID 时跳过该帖媒体。
- Google 相似图片列表保留命中的候选并显示“黑名单屏蔽”，批量抓取与明确交给 Pixiv 的操作跳过它们。CSV/JSON 候选导出含 `blocked` 字段；纯 URL 文本导出仍只包含地址。Pixiv 作品 URL 本身没有作者 ID；选中候选后可点“核对 Pixiv 作者”，读取作品详情并显示作者，随即按作者黑名单重新判定。未核对的作品仍只能按单件作品规则判定，进入 Pixiv 原生下载器后会再次检查作者规则。

## 2026-09-18 取回平台原有拉黑和静音记录

- “管理黑名单”下方提供三个取回入口，均先预览来源、条数与示例，确认后一次性合并，重复导入去重，原规则与下载记录不删除。
- “X 数据归档”接受完整 ZIP 中的 `data/block.js`、`data/mute.js`，也接受单独的同名文件；只读取这两个文件，不解压归档其他私人数据。归档的 `accountId` 保存为独立的 `twitter_id` 规则，管理表显示“待匹配 ID”。Twitter 媒体接口返回作者 ID 时可直接过滤；仅能看到 `@用户名` 的候选或页面，可选中该 ID 点击“核对并绑定 X 用户名”，核实打开的账号主页后输入 `@用户名`。不能把数字 ID 当成用户名。静音也按本软件下载黑名单处理；若只需拉黑，单独选择 `block.js`。
- “Pixiv 在线静音”使用软件现有 `PHPSESSID` 只读请求 Pixiv 静音设置页；Pixiv 官方说明设置页中的静音列表可能要求 Premium。也可在浏览器把静音/屏蔽设置列表保存为 HTML 后通过“Pixiv 设置页 HTML”读取作者主页链接；已拉黑用户可从桌面版用户设置查看。若网站改版后页面不含可识别作者链接，会报错而不是声称已同步成功。标签静音不会被误认成作者。旧版 `blacklist_members.txt` 仍可通过“读取平台名单”导入。
- “Bluesky 账号”调用官方 `createSession`、`getBlocks` 和可选的 `getMutes`，逐页读取并以 DID 为主键、当前 handle 为别名。应用密码只保留在本次读取内存中，不写入设置、任务或日志；目前使用 `bsky.social` PDS。账号 handle 改名后再次取回会更新别名，避免旧 handle 被转给别人后仍误屏蔽。
- 平台原生“拉黑/静音”与本软件的下载过滤是不同操作：取回只影响本地规则，不修改任何网站账号的屏蔽设置。参考：[X 账号数据归档](https://help.x.com/en/managing-your-account/accessing-your-x-data)、[Pixiv 静音设置](https://www.pixiv.help/hc/en-us/articles/236081388-What-is-the-Mute-feature)、[Bluesky getBlocks](https://github.com/bluesky-social/atproto/blob/main/lexicons/app/bsky/graph/getBlocks.json) 与 [getMutes](https://github.com/bluesky-social/atproto/blob/main/lexicons/app/bsky/graph/getMutes.json)。
