# 开源下载器对比与扩展建议

核对至 **2026-10-31**。下表是结合官方资料与本地源码的设计判断，不是上游的兼容保证。没有安装、测速或接入新引擎；当前欲求达的验证结果统一见 测试报告（本地记录，不随仓库上传）。固定快照与采用细节见 [参考源码评估](参考源码评估.md)。

## 已落实的恢复边界

- 收藏先保存版本化作品 ID 范围，自动重试／恢复／原设置重试沿用；当前设置重试重新发现。保存与复制使用现有事务，不能覆盖成不同清单。作品收藏按普通图片页、动图组补下，过滤记日志；没有给所有集合新增分页断点。
- HLS 只支持已结束、未加密、单路 TS／fMP4；缓存以资源身份、摘要及条件请求核对，FFmpeg 只读本地资源。有限结构检查不是完整逐帧证明。
- 公共 HTTP 版本 3 同时核对入口／最终 URL 指纹、服务端验证器和本地前缀摘要。累计 4 MiB 或两秒提交检查点，强退后只认已提交前缀，未提交尾部重取；旧版本记录不直接追加。
- 本地 SHA-256 检查的是缓存一致性。有可信来源校验值时才可能证明对应来源内容；同时恶意改写记录和字节不在本地检查点保证范围。
- 输出锁、凭据隔离、账号策略和独立任务参数继续由本项目实现；引用一个引擎的功能不代表共享这些控制。

## 下一步优先级

1. **其他 Pixiv 集合精确补下。** 漫画系列、作品搜索及排行榜已接入固定作品范围、逐页结果和原目录身份；后续评估新作／作者标签等集合，避免站内变化导致重试选中别的作品。
2. **可信来源与成品关系。** 已有手动本地成品清单和只读核验；来源校验值验证、下载时自动基线及源到转换／压缩产物的完整关系仍待接入，本地摘要不能替代来源校验。
3. **跨进程引擎预算。** HTTP 实例内预算和每个 aria2 进程预算已存在；统一预算、动态 RPC 仍未实现。
4. **队列时间窗口。** 定义时区、起止、错过时间策略、用户暂停优先级和重启行为，不默认访问账号或自动关机。
5. **可预览的本机任务草稿协议。** 先做统一解析与回执，远程控制／插件市场暂不作为必需功能。

这些候选不是已经确认的产品故障。实际平台验收、持续压力和多版本运行仍需各自证据，后续开发按最新接续确定范围。

## 搜索／排行扩展后的复查（2026-10-31）

**后续实施状态：** 下表保留修复前的评估证据。通用转换已接入共享可取消进程入口，长 Retry-After 已移除 300 秒截短；本地成品清单和只读核验也已接入下载库。当前支持范围及验收以开发接续／测试报告顶部为准。可信来源校验、完整产物关系及其他候选仍未实现。

本轮只做源码、资料与本地纯函数核对，不修改产品实现或运行新全量回归；964 项仍是前轮源码基线。在线资料为读取时内容，本地 Ghost 快照仍为 `ee0cb1aa5325960e6a2584b4c3029982e288c7a3`，没有更新或运行参考工程。

| 优先级 | 本项目证据与判断 | 建议及验收方式 |
| --- | --- | --- |
| 先处理 | `core/network_policy.py` 的解析及协调器均将等待限制在 300 秒。本机调用 `retry_after_seconds('3600', 1)` 实得 `300.0`，已确认此行为，未做真实站点限流试验 | 保留有效的服务端期限，以短片段等待或延期队列响应取消；超长／异常值需明确策略，不能静默提前请求。用本机时钟与 HTTP 样本验证 429／503 长期限、HTTP 日期、同主机协调及取消 |
| 先复现再修 | `crawlers/common.py` 的通用转换仍用 `subprocess.run(capture_output=True, timeout=1800)`，转换入口没有传入任务取消事件；HLS 与 Pixiv ugoira 已用 `core/media_process.py`。这是源码确认的覆盖差异，未模拟真实卡住引擎 | 接入统一可取消进程入口、有界诊断和成品提交前取消检查。验收转换中取消、超时、大量 stderr、旧成品和源文件保留；不能把已有两个入口的测试当作通用转换已覆盖 |
| 高 | 有续传／HLS／归档局部摘要，但下载库没有统一成品摘要、校验状态及源文件到转换产物的关系清单 | 先实现可选成品清单与只读核验，报告缺失、变化、读取失败、无基线；再接可信来源校验值。验证不能改变任务历史或自动删除文件，导出不携带账号和签名 URL |
| 高 | `core/preflight.py` 显示当前可用空间，下载遇到磁盘错误会停止；缺少按在途任务、转换临时成品、HLS 缓存估算的运行中空间准入 | 对同卷任务协调预算，未知总长保留底线；转换考虑源和临时成品共存。用生成文件验证低空间停发、取消及已有成品保护，不预留真实大文件 |
| 中 | 队列查询最新 200 条；下载库界面聚合最多 100000 条并逐文件 exists/stat，完整导出／清理筛选在 Python 侧扫描。已有索引和后台刷新，不能据源码断言当前机器卡顿 | 先做数据库筛选、分页和全库计数，再按数据规模评估全文检索；减少无变化文件重复 stat。验收旧任务可查、筛选完整性、中文匹配和 1 万／10 万样本耗时，保持显示上限与导出范围区别 |
| 中 | HTTP 实例预算与每进程 aria2 限速分开，aria2 无动态 RPC；没有队列时间窗口 | 先做所属 aria2 的运行中调速及退出回收，再协调引擎预算；定时队列另行定义时区、错过窗口、手动暂停优先和重启规则。两项不要捆成大规模引擎替换 |
| 后续 | 已有混合 URL 批次，但缺少浏览器／命令行提交到现有桌面窗口并预览的统一回执协议 | 参考 Ghost 本地 argv 转发模型做可预览草稿，保留本项目多实例边界；不直接照搬 Qt 单实例选举，也不在收到链接后无确认立即启动网络任务 |

下一轮建议先复现并补齐通用转换取消，再修长退避，随后做成品清单／只读核验。继续铺开其他 Pixiv 集合的收益暂低于这几项公共链路工作。

### 本轮新增一手资料及采用限制

- [RFC 9110 §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3)：Retry-After 是服务端要求客户端等待的时长依据；本项目应区分完整期限与等待线程每次休眠的长度。
- [rclone check](https://rclone.org/commands/rclone_check/)：比较大小和摘要并只输出差异报告；借鉴只读核验及相同／缺失／不同／读取错误分类，不引入云端同步或自动删文件。
- [gallery-dl 元数据后处理](https://gdl-org.github.io/docs/configuration.html#metadata-mode)、[yt-dlp 元数据选项](https://github.com/yt-dlp/yt-dlp#filesystem-options)：可参考 JSON／JSONL 与旁文件输出；本项目使用字段白名单和版本，不直接导出引擎全部内部信息。
- [RFC 9530](https://www.rfc-editor.org/rfc/rfc9530.html)：Content-Digest 校验消息内容，Repr-Digest 校验表示。206 范围响应的内容摘要不能直接当作整文件摘要，压缩／解码也要明确计算对象；摘要本身不等于可信来源证明。
- [FFprobe](https://ffmpeg.org/ffprobe.html)：可读取容器、轨道和错误并输出结构化结果。建议可选快速探测和单独的深度解码；探测成功不保证逐帧完整，也不把 yt-dlp `--check-formats` 的可下载性检查当作成品解码校验。
- [SQLite FTS5](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)：trigram 可支持子串匹配，但需验证短词、中文、现有规范化规则及打包环境支持，不直接替换现有筛选语义。
- [AB Download Manager](https://github.com/amir1376/ab-download-manager#features)：官方列出队列与调度器；本轮未审查其调度实现，不能据 README 推断错过窗口或重启行为。
- Ghost 本地 `docs/adr/0012-thread-ownership.md`、`0020-argv-to-primary-instance-over-local-socket.md`、`0017-runtime-install-is-not-a-task.md`：核对线程状态归属、单入口解析／回执、只管理工具安装自身文件。只借鉴责任边界，不迁移 Qt、单实例锁或其他项目安装替换假设。
