## 2. 产品边界

第一目标是本地桌面内容下载器，不是云端账号系统。

核心流程：

```text
输入目标或网址
    -> 识别平台和目标类型
    -> 查询/预览目标状态
    -> 加入任务队列
    -> 下载并显示进度、日志、失败原因
    -> 转换、压缩或合成
    -> 写入下载库和历史记录
    -> 在本地下载库预览、打开、清理
```

暂不作为第一阶段目标：

- 云端账号和多用户共享服务。
- 手机端直接运行 Selenium 或各站点爬虫。
- 自动绕过验证码、风控或登录限制。
- 一次性把所有外部工具完整 GUI 化。

## 3. 统一功能层

### 3.1 目标和任务

所有平台都应支持以下输入形态，具体平台按能力实现：

- 用户名、作者 ID、作品 ID、漫画 ID。
- 平台主页、作品页、推文/帖子页、媒体页 URL。
- 搜索词、标签、收藏夹或导入的目标列表。
- 多平台混合 URL 批量任务。

统一任务阶段：

```text
解析 -> 预览 -> 排队 -> 下载 -> 后处理 -> 入库 -> 汇总
```

任务需要支持：

- 当前实现状态为 queued、running、paused、cancelling、cancelled、completed、failed；支持进程内协作暂停/恢复，`finished` 不是当前完成状态名。
- 进度、速度、成功数、跳过数、失败数和当前目标。
- 日志、失败原因、重试和必要时停止整轮任务。
- 平台级并发限制和全局硬件占用监控。

### 3.2 统一预览

预览不是直接下载文件。预览结果至少可以包含：

- 平台、目标类型、标题、作者、作者 ID。
- 头像、简介、主页地址、外链和可下载媒体。
- 作品封面、第一页预览图、章节/页数。
- 收藏状态、发布时间、更新时间、热度字段。
- 是否需要 Cookie、代理或特殊下载方式。

本地已有缓存时优先使用缓存；只有用户主动刷新时才访问网站。

### 3.3 统一后处理

后处理是所有平台共用的服务，不放在单个平台适配器里重复实现：

- 图片格式转换：JPG、JPEG、PNG、WEBP。
- GIF 保持 GIF；X 等平台返回的 GIF 视频需要按媒体元数据识别，并可转换为真正的 GIF。
- 视频统一优先输出播放器兼容的 MP4，需保留音频；具体编码采用 H.264/AAC 等稳定组合。
- 音频提取默认支持 MP3、M4A。
- 图片合成长图或 PDF，每组最多 30 张，超出后继续生成下一组。
- 漫画支持按整本或章节合成。
- 手动压缩、解压缩，压缩后可选择清理源文件。
- 压缩包或合成文件可通过 QQ 邮件发送。
- 收藏夹和下载库导出 CSV。

原需求中把 `mp4`、`avi`、`wmv` 与音频支持写在同一段。本文暂按“视频容器兼容性”理解，音频仍以 MP3/M4A 为默认；如果需要输出 AVI/WMV，应作为单独的视频格式选项确认。

截至 2026-09-13，参考 PixivUtil2 ZIP 行为的第一轮公共归档调试已接入：普通 ZIP 安全解压、按任务/资源文件夹压缩、校验成功后可选清理，以及任务进度和 SQLite 同步已经完成。当前只支持 ZIP；7z/RAR、整本/章节之外的结构化归档策略和邮件发送仍在后续范围。

### 3.4 统一下载库、清理和历史

SQLite 是新软件的主索引，平台 JSON 只作为兼容层或可导出的明细。

建议的资源字段：

```text
platform
task_id
source_url
source_id
author_id
author_name
title
chapter
media_type
published_at
downloaded_at
local_path
relative_path
file_name
tags
is_favorite
size_bytes
metadata_json
```

每个平台保留独立历史记录；如果继续写 JSON，按平台和日期分文件，例如：

```text
data/software_app/history/twitter/2026-08-07.json
data/software_app/history/jmcomic/2026-08-07.json
```

清理功能应先选择平台，再使用约束条件：

- 社交平台：作者、作品日期范围、资源类型。
- 漫画：漫画 ID、标签精确匹配、标题模糊匹配、作者或出版社。
- Pixiv：作品 ID、日期范围、标签、作品类型。
- E-Hentai：画廊 ID、标签、日期和下载方式。

清理历史记录和删除本地资源可以同时执行，也可以只清理索引。删除后重新下载默认允许覆盖，但必须在设置中明确覆盖策略。

## 4. 统一目录和命名规范

默认下载目录建议按以下结构：

```text
downloads/
  <platform>/
    <download-date>/
      <target>/
        images/
        videos/
        gifs/
        audio/
        documents/
```

漫画和章节型内容：

```text
downloads/
  jmcomic/
    <download-date>/
      <author> - <title>/
        <chapter>/
          001.jpg
          002.jpg
```

Pixiv 目标目录需要同时保留作者名和作者 ID。E-Hentai 下载需要保留原始 `.torrent`、`.eh` 或其他下载凭据/元数据文件，不要只保存解压后的媒体。

通过网址批量下载时：

```text
downloads/
  website/
    <batch-start-date>/
      twitter/
      jmcomic/
      pixiv/
      ehentai/
```

同一批次可以混合平台，但每个平台仍使用自己的目标目录规则，并生成一份 TXT 汇总日志。

命名原则：

- 文件名不能依赖随机媒体 ID 作为唯一可读名称。
- X/Twitter、Bluesky、Instagram：优先使用作者、发布时间、推文/帖子 ID、资源序号。
- X/Twitter 按最新到最旧发现资源，但历史记录必须保证同一资源不会因重复扫描改变名称。
- 如需按作品时间重新编号，应提供独立迁移/整理操作，不在普通重复下载时自动重命名。
- Pixiv：标题加序号，并保留作品 ID。
- 漫画：作品目录使用作者和标题，章节目录使用章节名，图片使用稳定页码。
- 文章和小说：使用标题或章节名；超长文本拆分时追加 `-1`、`-2` 等序号。

## 5. 平台需求和优先级

### 5.1 X/Twitter：当前第一优先级

现有下载功能继续保留，并补齐以下统一软件能力：

- 关注列表刷新、全部读取、模糊筛选，列表最多展示 100 个结果。
- 关注列表导出 TXT，格式包含显示名、`@用户名`、主页地址。
- 导入只含 `@用户名` 的 TXT，并与已获取列表合并。
- 预选列表和已选下载列表之间可以添加、取消和回显。
- Twitter 平台总并发默认 5，作者/范围默认 1；设置可分别调整，最终受平台总上限约束。
- 单用户输入仍可使用数字下载类型，如 `1,2,3,4`。
- 用户搜索最多显示 20 个候选，候选可直接加入预选列表、预览或下载。
- 支持推文 URL 下载，必须依据结构化媒体信息区分 GIF 和普通视频。
- 一轮下载成功后清理对应预选项；失败项保留，并在汇总中列出成功/失败用户。
- 主页预览显示 Skeb 和其他外链，可复制简介或推文文字，并支持从链接加入下载任务。

### 5.2 JMComic：第二优先级

- ID、章节 ID、作品链接下载。
- 名称精确搜索和模糊搜索。
- 作品详情、封面/第一页预览和预览图下载。
- 最多 15 个候选加入任务队列，同时最多下载 3 个漫画。
- 复用作者/作品预选列表，支持添加、删除和标签。
- 作品名后可以附加最多 5 个标签。
- 支持裁剪提示、章节目录、图片排序和 PDF/长图后处理。
- 检测到无法获取、站点拦截或明显限流时提示用户并允许停止整轮任务。

### 5.3 Pixiv / PixivUtil2：第三优先级

- 继续支持画师 ID、作品 ID、标签、收藏夹和 FANBOX 等已有方式。
- 增加收藏夹内按作品 ID、作者名、标签、标题搜索。
- 支持按发布时间和收藏/添加时间筛选。
- 支持作者 ID 加标签的组合查询。
- 区分插画、漫画和小说下载。
- 增加 AI 内容过滤配置，并在预览和下载结果中保留过滤原因。
- 第一阶段仍优先通过无 Docker 子进程接入，稳定后再抽常用 API。

### 5.4 Google 相似图片搜索：辅助模块

- 保持单图、文件夹批量、递归、TXT/CSV 输出。
- 搜索结果只作为 URL 线索，不直接把图片投射到界面。
- 用户手动选择结果后，交给软件内置网页资源爬虫；不选择就不抓取。
- 网页资源爬虫先处理候选页静态 HTML 中的图片、视频和音频；后续再按需要增加动态页面和站点专用解析。
- 无法正常解析的 URL 仍可保留在候选列表或导出，不自动转交其他平台。

截至当前源码，单图/文件夹批量搜索、人工验证引导、带来源候选列表、多选/全选、CSV/JSON/TXT 导出、候选网页预览和批量创建网页爬取任务已经接通。普通网页已有浏览器动态媒体发现，更多动态站点兼容和跨页递归仍待开发。

### 5.5 E-Hentai / ExHentai：后续独立模块

- 表站和里站分开配置，收藏夹不假设共通。
- 支持关键词搜索、日期排序和按年/年月/年月日筛选。
- 支持收藏夹下载、下载前预览和预览后收藏；单项加入、改分类/注释和移除已完成，批量管理待实现。
- 预览中明确显示可用下载方式：压缩包或种子。
- 支持过滤 AI 内容。
- 保留种子文件、`.eh` 文件和必要的原始元数据。
- 启动前显示代理/网络环境提示，并允许用户确认后继续。
- 需要独立设计种子解析器、种子下载器和压缩包下载流程，不直接套用普通图片下载器。

### 5.6 Bluesky、Instagram 和油猴脚本

Bluesky 已接入公开用户、公开关注、用户/帖子搜索、作者动态、单帖和媒体下载，并支持用临时应用密码单项关注/取消关注。Instagram 已接入精确账号、帖子、Reels 页面及登录 Cookie 页面媒体读取，并在静态资料缺失时自动切换浏览器渲染；普通账号关注列表仍待实现。

油猴脚本属于浏览器侧工具，与桌面下载器共享命名和格式约定。当前脚本仓库已独立维护在 `油猴脚本/`，并同步到 GitHub 仓库 `xiaohaoyiqu/tempermonkey-scripts`；根目录保留当前推荐安装版本，`1.0版本/` 和 `1.1版本/` 保存版本归档。

- 图片默认 PNG。
- 视频默认 MP4。
- GIF 需要保持 GIF，不要误保存为普通视频。
- Instagram 1.1：帖子操作栏下载入口；点击后选择立即下载或加入队列；队列最多 30 项，支持选择、删除、按类型下载、下载全部和清空；图片不参与视频转 GIF 或抽音频。
- Bluesky 1.1：帖子媒体按钮和页面级入口；通过公共 API 补全媒体；队列最多 30 项；图片 PNG、普通视频 MP4、GIF 转换和音频 MP3 抽取。
- Zhihu 1.1：右侧按钮轮；历史固定和清空未固定记录；当前可见/全页分范围收起；展开/阅读全文仅问题详情页可用；轮盘避开右下角“看山”和回到顶部按钮。

油猴脚本后续只记录轻量浏览器侧能力，不作为桌面下载器的核心任务队列替代：

- Zhihu 问题页阅读进度，例如当前第几个回答。
- Zhihu 隐藏相关推荐、热榜或侧栏的开关。
- Bluesky/Instagram 油猴脚本继续作为浏览器当前页面的轻量入口；桌面端统一承担任务队列、下载库、历史和黑名单。

Rule34、Rule34Video 暂不进入当前开发阶段。

## 6. 分阶段路线

### 阶段 A：统一核心

1. 固定新版 `software_app/` 为主架构。
2. 完成统一模块、任务、事件和 SQLite 模型。
3. 保存路径、无凭据代理、重试和 Google/网页限制已接入全局设置；Cookie 状态、可调并发和媒体格式继续完善。
4. 先支持 URL 识别、任务队列、取消、重试、日志和下载库。

### 阶段 B：X/Twitter 完整化

1. 保持现有下载、主页预览、关注列表和历史页。
2. 关注列表导入/导出已完成；继续完善搜索候选和预选列表状态流转。
3. 接入推文 URL 下载和媒体类型判断。
4. 将用户级成功/失败结果写入统一任务汇总。
5. 统一输出目录、历史记录和资源入库。

### 阶段 C：公共后处理和清理

1. 缩略图和本地预览。
2. 图片、视频、音频格式转换。
3. PDF、长图、压缩/解压缩。
4. 按约束条件清理资源和历史。
5. CSV 导出与可选邮件发送。

### 阶段 D：JMComic

1. 按 ID/章节 ID 下载。

## 7. 当前未决事项

## 8. 本地版本管理和上传边界

桌面端主仓库为 `https://github.com/xiaohaoyiqu/fast-get-it`，本地 `origin` 已指向该地址。浏览器用户脚本继续使用独立仓库 `https://github.com/xiaohaoyiqu/tempermonkey-scripts`，本地目录不作为主仓库子模块或普通目录提交。

约束如下：

- 本地仓库默认分支为 `main`。
- Cookie、数据库、下载记录、本地媒体和虚拟环境不进入版本库。
- `data/software_app/` 作为运行数据整体忽略；`油猴脚本/` 由自己的仓库管理。
- 配置远程不等于发布。执行 `git push` 前仍要检查待提交文件和远端历史。
- Git 提交应在功能完成并通过必要检查后，由使用者明确确认再执行。
- 后续如需接入 CI/CD，应单独确认平台、触发方式、依赖缓存和敏感变量。
