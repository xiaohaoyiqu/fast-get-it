# E-Hentai / ExHentai 使用与登录

## 当前接入范围

- 识别 `e-hentai.org` 表站和 `exhentai.org` 里站画廊链接。
- 使用 E-Hentai 官方元数据 API 读取标题、上传者、发布时间、页数、文件大小、标签、评分和种子数量。
- 支持表站/里站关键词候选，以及登录后的表站/里站收藏夹候选。
- 单选具体画廊后可加入、改分类/注释或移出所属站点账号的收藏；写入后会重新读取状态核验。
- 下载任务固定保存一份 UTF-8 JSON 元数据，并逐个打开画廊提供的 `/s/...` 阅读页，从 `<img id="img">` 保存页面正常展示的图片。
- 设置页可手动开启“同时保存 `.torrent`”；默认关闭。种子会经过有界 bencode 解析、路径安全检查、分片数量校验，并记录原始 `info` 字典的 SHA-1 info-hash。
- 可另行开启“使用 aria2 下载种子内容”；同样默认关闭。软件支持检测 PATH 中的 aria2；Windows 安装版优先使用随包提供的官方 ZIP，源码版可使用项目根目录 ZIP，固定 SHA-256 校验后只安装允许的程序和许可文件，本地包不存在时才从官方 Release 下载。任务取消时会终止子进程，完成后不继续做种；DHT、IPv6 DHT、PEX 与本地节点发现默认禁用。
- aria2 可单独开启下载／上传上限，单位 KiB/s，每个进程分别生效，与 HTTP 总预算分开。保存后用于新任务；任务运行中不动态调整，原设置重试和恢复沿用原值，当前设置重试重新取值。不会读取外部 aria2.conf，详情见 [用户手册](../用户手册.md#aria2-下载上传限速)。
- 官方 Archive Download 可能消耗 GP 或 Credits。当前版本不会自动申请或购买 ZIP，避免在后台产生站内消费。

当前模块为 `alpha`。官方原图/归档二次确认和收藏批量管理仍未接入。

## 表站与里站账号隔离

E-Hentai 表站和 ExHentai 里站按两个独立登录身份处理，账号可以不同，也不会互相回退或复用：

| 登录入口 | 保存文件 | 必需 Cookie | 使用范围 |
| --- | --- | --- | --- |
| `E-Hentai 表站` | `data/software_app/ehentai/e-hentai-cookies.json` | `ipb_member_id`、`ipb_pass_hash` | 仅 `e-hentai.org` 与表站收藏夹 |
| `ExHentai 里站` | `data/software_app/ehentai/exhentai-cookies.json` | `ipb_member_id`、`ipb_pass_hash`、`igneous` | 仅 `exhentai.org` 与里站收藏夹 |

未区分站点的 `cookies.json` 不会自动读取，以免把表站账号误用于里站。缩略图主机 `ehgt.org` 和种子主机 `ehtracker.org` 也不会收到登录 Cookie。

文件导入会分别保留 `e-hentai-browser.json`、`exhentai-browser.json` 中的浏览器 User-Agent，后续请求按账号复用；手动填写保留已有 User-Agent。文件不包含密码，表站与里站不会共用另一个账号的 User-Agent。

## 登录步骤

表站公开搜索与公开画廊通常不要求登录。收藏夹需要：

- `ipb_member_id`
- `ipb_pass_hash`

里站还需要浏览器会话中的 `igneous`，并且所登录账号本身必须具有 ExHentai 访问权限。只有 Cookie 名称存在不代表会话一定有效，软件会在实际访问时验证；里站返回空白正文会明确报为权限/会话问题。

EH 仅支持手动填写或文件导入，自动启动 Chrome、读取专用浏览器资料的实现和界面入口已移除。

1. 在日常浏览器自行登录，确认表站或里站可正常访问。
2. 在设置页“浏览器登录与 Cookie”选择 **E-Hentai 表站** 或 **ExHentai 里站**。
3. 点击 **手动填写 EH Cookie**，将下述浏览器存储列表中的各字段值分别粘贴，点 **保存到本机**。输入框遮挡内容，不预填已有凭证；留空或格式无效不覆盖旧 Cookie。
4. 也可用 **导入 Cookie 文件** 导入 JSON、Netscape `cookies.txt` 或 Cookie 请求头文件。**请求头 TXT → JSON** 仍仅用于真实请求头文本。
5. 保存只检查必需字段、域、到期时间等本地规则，不进行网络请求；保存成功不代表会话有效。需要检查时单独点击 **验证 EH 登录（联网）**，使用当前代理访问表站设置页或里站首页。验证失败不会改写已保存的 Cookie。
6. 登录、验证和下载应保持同一代理出口；修改代理后保存设置。遇到 `uconfig.php` 连接超时应检查网络／代理，不必反复获取 Cookie。

**连接诊断：** 验证开始和结束都会显示本次使用直连还是已填写代理。EH 的代理 URL 留空表示直连，不自动使用 Windows 系统代理；浏览器可访问而软件超时时，应核对两者实际出口。验证使用输入框当前值，下载使用已保存设置。连接超时尚不能判断 Cookie 是否有效；HTTP 401／403 则表示登录或访问被拒绝，需要检查 Cookie、权限或站点保护。

设置页 EH 卡片现会固定显示上述操作步骤，验证结果不会替换说明。代理地址可参照 `http://127.0.0.1:6987` 的格式，端口应以自己代理软件的 HTTP 监听配置为准；填入后点击“保存设置”，再开始下载。

### 手动查看浏览器中保存的 Cookie

在已登录且能正常访问对应站点的页面按 **F12 → Application（应用/应用程序）→ Storage（存储）→ Cookies**，展开后选择 `e-hentai.org`（表站）或 `exhentai.org`（里站）。找不到 Application 面板时，可在开发者工具顶部 `»` 菜单中查找。

这里查看的是 Cookie 存储列表中的 **Name（名称）／Value（值）**，不是 Console（控制台）或 Network（网络）列表。表站需 `ipb_member_id`、`ipb_pass_hash`；里站还需 `igneous`，须先确认里站页面正常。把对应名称和值保存成 JSON 名称字典，或使用浏览器导出的 Cookie JSON／Netscape `cookies.txt`，再在软件选择相同站点，点击 **导入 Cookie 文件**。直接复制存储表格不等于上述文件格式；**请求头 TXT → JSON** 用于 Cookie 请求头文本，不能转换 Cookie 存储表格。

表站和里站分别填写／导入，保存时不联网，联网验证单独执行。不要把 Cookie 内容发给他人。

软件不会保存账号密码，也不会把 Cookie 值写入任务日志。

“导入 Cookie 文件”的本地处理在后台运行；单独的登录验证也在后台运行，不阻塞界面。验证使用设置输入框的当前代理，后续下载使用已保存设置，因此更改代理后应先保存，再创建下载任务。已有 Cookie 文件和旧专用浏览器资料目录保留，不自动删除用户数据。

## 单项收藏管理

在候选页单选一个具体画廊后，可使用 **加入 EH 收藏** 或 **移出 EH 收藏**：

- 加入时软件会先从账号收藏弹窗读取 `0`–`9` 的当前自定义分类名称和该画廊现有分类/注释，再让用户选择；可填写 UTF-8 编码后最多 200 字节的注释。
- 操作前会显示画廊与所属站点并要求确认。表站目标只使用表站会话，里站目标只使用里站会话，禁止跨站写入。
- 软件先读取现状，避免重复写入；提交后再次读取分类、注释或移除状态。只返回 HTTP 200 但状态未生效时会报告失败。
- 当前只开放单项操作，不提供无确认的批量导入或批量删除。

## 网络与限流

- 网络只使用设置页显式配置的代理；留空表示直连，不继承启动器环境代理。
- 登录和访问 ExHentai 时尽可能使用非亚洲代理/VPN；登录与后续请求应保持同一网络出口。实际可用性仍取决于当前出口、账号权限和站点策略。
- 官方搜索限制要求搜索之间至少间隔约 3 秒；模块会串行化搜索并自动等待。
- 模块任务并发上限为 1。不要用外部工具同时高频访问同一账号。

## `uconfig.php` 站点设置

请在自己的浏览器打开 `https://e-hentai.org/uconfig.php` 修改账号设置。官方页面包含图片加载、默认分辨率、标题语言、搜索分类、收藏分类名称、缩略图、语言/上传者排除、My Tags 和 MPV 等设置。

软件暂不自动提交该表单：未取得真实登录页面前无法确认当前字段、防伪参数和账号权限，猜测提交可能误改 H@H、原图、Archive 或其他涉及配额/GP/Credits 的选项。后续只会对白名单中的低风险显示/搜索/收藏分类设置提供“读取当前值 → 显示差异 → 单次确认 → 写后复读”；额度重置、Archive 消费、Hath/GP/Credits/捐赠不会接入。

## 下载目录

```text
<保存目录>/ehentai/<日期>/<画廊ID - 标题>/
  documents/<画廊ID>.json
  images/0001.<图片格式>
  images/0002.<图片格式>
  torrents/<种子哈希>.torrent
  bt-content/<info-hash>/<种子内容>
```

画廊详情页本身主要提供缩略图 CSS 地址和 `/s/...` 阅读页链接；正文展示图地址位于每个阅读页的 `<img id="img" src="…">`。软件只接受官方 `hath.network`/`ehgt.org` HTTPS 图片节点，验证文件确实为图片后再入库；不会请求 `fullimg.php` 原图入口。元数据记录来源站点、画廊 ID/令牌、标题、分类、上传者、发布时间、页数、大小、评分、标签和下载方式可用性。直接图片 CDN 与种子 URL 可能包含临时或个性化参数，因此不会写入元数据或日志。

BT/P2P 与普通 HTTP 代理不是一回事。启用 aria2 后，Tracker 和其他节点可能看到公网 IP，下载过程中也可能产生上传流量；`seed-time=0` 只表示完成后停止做种，不能保证下载阶段零上传。软件不会把 aria2 控制台中可能含作品名的内容写入日志。请只下载自己有权使用的内容。

## 关于 `.eh` 文件

旧需求提到保留 `.eh` 文件，但 E-Hentai 官方 Wiki 当前没有定义通用 `.eh` 下载格式。本模块不会自行编造扩展名；先保留官方 JSON 元数据和 `.torrent`。以后若确认 `.eh` 来自某个具体客户端，应先确定格式、用途和兼容目标，再增加导入/导出。
