# JMComic 功能、登录和测试说明

## 预览能读取什么

| 操作 | 是否访问网站 | 当前能得到的内容 |
| --- | --- | --- |
| 本地预览 | 否 | 目标类型、漫画或章节 ID、按当前设置生成的目标网址，以及“打开网页”将进入的页面类型 |
| 在线获取漫画资料 | 是 | 漫画标题、作者名、标签、章节目录、封面、第一章可用时的第一页 |
| 在线获取章节资料 | 是 | 章节标题、图片文件列表、第一页和分割图参数 |
| 搜索 | 是 | 最多 15 个漫画候选，包括漫画 ID、标题、详情页和封面地址 |
| 分类 / 排行 | 是 | 按分类、排序、时间取得漫画候选 |
| 漫画收藏夹 | 是，需要登录 | 指定用户名和漫画收藏目录中的候选 |
| 小说收藏夹 | 是，需要登录 | 指定小说收藏目录中的候选；当前只读，正文下载尚未接入 |
| 追更连载 | 是，需要登录 | 从个人主页 `tracking` 分页读取追更漫画候选 |
| 漫画观看记录 | 是，需要登录 | 从个人主页 `favorite/watchlist` 只读获取；不会删除站内记录 |
| 小说观看记录 | 是，需要登录 | 从个人主页 `favorite/novel_watchlist` 只读获取；小说正文下载尚未接入 |
| 站内屏蔽标签 | 是，需要登录 | 从个人主页 `tag_block` 取回，审阅后合并为本地 `jmcomic_tag` 规则 |

JMComic 的“作者”来自漫画详情页文字。当前页面没有提供类似 Pixiv 用户 ID 的稳定作者标识，因此软件不会把作者名声称为站点账号资料，也不会获取作者头像、个人简介、关注关系或主页外链。

## 哪些内容需要登录

- `cf_clearance` 是 Cloudflare 通行 Cookie，只说明浏览器通过过验证，不能证明 JMComic 账号已登录。
- 账号功能需要 `AVS` 登录会话。检测到 `AVS` 只表示已经配置候选会话，是否仍然有效会在读取收藏夹或历史时在线验证。漫画收藏夹还要填写收藏夹用户名和漫画目录 ID；小说收藏夹填写单独的小说目录 ID。
- Cookie 已失效、缺少 `AVS` 或接口返回登录提示时，软件会停止并要求重新导入。
- 普通搜索、漫画详情、章节和下载是否要求登录，由当前站点域名、内容权限、地区和验证状态决定。
- 软件只保存导入的 Cookie、收藏夹用户名和目录 ID，不保存 JMComic 密码，也不会自动提交登录表单。
- Cookie 保存在本机 **data/software_app/jmcomic/cookies.json**，日志和界面不会显示 Cookie 值；该路径已由 `.gitignore` 排除。

上游 Python 项目将登录和个人漫画收藏夹作为独立能力，并明确用 `AVS` 保存登录会话。较新的 Java API 项目还确认了站内浏览历史 `watch_list` 与小说收藏 `novel_favorites`。参考：[Python 上游收藏夹说明](https://github.com/hect0x7/JMComic-Crawler-Python/blob/master/assets/docs/sources/tutorial/0_common_usage.md)、[Java API 功能与接口](https://github.com/JUKOMU/JMComic-Api-Java)。

### 获取可用 Cookie

推荐使用软件内的普通 Chrome 两阶段流程：

1. 在 **设置 → JMComic · 可用 → 站点与登录资料** 确认站点域名、代理和账号用户名。
2. 点 **打开普通 Chrome 登录**。这个阶段不启用 WebDriver 或远程调试，专门用于通过 Cloudflare 验证和账号登录。
3. 登录后打开自己的漫画收藏页，确认页面内容可见。
4. 关闭这个专用 Chrome 的全部窗口，回到软件点 **登录完成后获取**。专用资料已设置为保留会话；软件直接读取资料目录，不会用 WebDriver 访问 JMComic，也不会再打开空白读取页。
5. 软件确认取得当前域名的非空 `AVS` 后，才会原子更新 Cookie 和 User-Agent；未取得时保留原有文件并提示继续登录。
6. 读取漫画收藏、追更或观看记录做在线有效性检查。登录已过期时，账号页面会明确报错。

若 JMComic 仍在第 2 步循环验证，问题发生在完全普通的 Chrome 会话或当前代理出口；此时更换可用代理/域名后重新打开。获取前必须关闭该专用 Chrome 的全部窗口，否则 Windows 会锁住 Cookie 数据库；软件已为这个专用资料启用会话恢复，以便正常退出后保留 `AVS`。

也可以手动导入：

1. 在浏览器中打开 JMComic 入口并完成登录。入口可能跳转到另一个镜像，以登录后浏览器地址栏最终显示的域名为准。
2. 按 `F12`，进入 **Application（应用）→ Cookies → 地址栏最终显示的 JMComic 域名**。
3. 确认列表中至少有 `AVS`。只有 `cf_clearance` 时，需要回到网站重新登录，并确认检查的是登录后的同一域名。
4. 可以用浏览器 Cookie 导出扩展导出 JSON 或 Netscape `cookies.txt`。也可以在开发者工具的 **Network（网络）** 中选中同域名请求，把完整请求标头复制到 TXT；软件会提取 `Cookie`，并单独保存复现 Cloudflare 会话所需的请求头。
5. 在浏览器控制台执行 `navigator.userAgent`，把返回内容填入 **设置 → JMComic User-Agent**。User-Agent 应与导出 Cookie 时使用的浏览器一致；复制的请求标头已包含它时仍可直接导入。
6. 打开 **设置 → JMComic · 可用 → 站点与登录资料**，点 **导入完整请求标头**；候选页也提供导入入口。导入结果只显示 Cookie 数量、是否检测到 `AVS` 和请求头数量，不会显示值。
7. 设置页和 JMComic 候选页都会显示本机登录资料状态。该状态不代表会话一定有效，账号页面会在实际读取时在线验证。

`cf_clearance` 会与取得它时的域名、代理出口及浏览器特征关联。出现 HTTP 403 时，应在软件配置所用的同一代理下重新通过验证，再一起更新 Cookie、请求标头和 User-Agent。

已经在聊天、截图或日志中公开的 Cookie 应立即从浏览器删除并重新登录生成。

## “打开网页”会去哪里

- 漫画 ID 或 /album/{id}：打开漫画详情和章节目录页。
- 章节 ID 或 /photo/{id}：打开章节正文阅读页。
- 搜索词：打开搜索结果页。
- 该按钮不会直接打开下载目录或本地图片。网站仍可能根据当前浏览器会话跳到登录、地区限制或人机验证页，软件不会绕过这些页面。

## JMComic 黑名单

- 漫画规则：按漫画 ID 屏蔽，镜像域名变化后仍然生效。
- 章节规则：按章节 ID 屏蔽，只影响该章节。
- 作者规则：在线读取漫画详情后，按规范化作者名屏蔽；同名作者可能冲突，作者改名后需要更新规则。
- 小说规则：按小说 ID 屏蔽，来源可以是小说收藏夹；规则类型为 `jmcomic_novel`。
- 搜索候选会排除已屏蔽的漫画。直接任务在创建前检查漫画或章节规则；漫画详情取回作者后再次检查作者规则。
- 规则只保存在本机跨平台黑名单 JSON，不会修改网站账号的屏蔽状态。

## 设置对应关系

| 设置 | 生效位置 |
| --- | --- |
| 站点域名 | 本地预览网址、搜索、详情、章节、封面和图片请求 |
| 排序、时间 | 综合搜索、作品搜索、作者/标签/角色搜索和分类排行 |
| 分类 | 分类 / 排行路径 |
| 收藏夹用户名、漫画目录 ID | 网页漫画收藏夹请求，例如 URL 中 `albums?folder=...` 的数字 |
| 小说收藏目录 ID | 账号小说收藏请求，例如 URL 中 `novels?folder=...` 的数字 |
| JMComic User-Agent | 与 Cookie 和浏览器请求头一起复现取得 Cloudflare 通行 Cookie 时的浏览器环境 |
| 名称匹配 | 综合搜索和作品搜索的标题精确匹配；作者等模式保持站点原始匹配 |
| 章节后处理 | 每章下载结束后生成 PDF、长图或两者；每组最多 30 张 |
| 下载作品封面 | 漫画目录中是否额外保存封面 |
| 公共图片格式、代理、重试 | 由通用任务设置传入 JMComic 下载任务 |

## 历史记录的区别

- **JMComic 历史页签**：软件自己的任务和文件记录，创建任务后自动保存，不要求网站登录。
- **搜索种类 → 漫画观看记录 / 小说观看记录**：从当前 JMComic 个人主页读取网站记录，需要用户名和 `AVS`。读取是只读操作，不会清除网站记录。
- **浏览器历史**：浏览器本地保存的访问网址，当前软件不读取浏览器数据库。这样可以避免混入验证页、广告页和其他隐私记录。
- 站点原生屏蔽若要求账号达到 8 级，低等级账号无法从站点取回原生屏蔽清单。软件的本地跨平台黑名单不受账号等级影响，也不会冒充或修改站点原生屏蔽状态。
