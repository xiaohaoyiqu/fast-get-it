# 平台接入方案

欲求达通过统一适配器接入平台，目标是让界面、任务队列和下载库依赖公共模型，网站请求、登录方式、分页规则和媒体解析由平台模块负责。当前界面仍保留平台选项与个别辅助调用，尚未完全解耦；以下约定用于接入和维护，不代表所有历史实现已满足全部要求。

## 1. 模块结构

```text
software_app/
  adapters/          # 平台识别、预览和任务转换
  crawlers/          # 页面、接口与媒体处理
  core/              # 任务、存储、安全和公共服务
  ui/                # 桌面界面
```

新增平台时，通常需要一个 `adapters/<platform>.py` 和一个 `crawlers/<platform>/` 模块。简单平台也可以使用单文件爬虫。

## 2. 统一适配器

平台适配器实现 `CrawlerAdapter`，并提供以下能力。

- 识别网址、用户名、作品 ID 或其他目标；
- 将用户输入规范化为稳定目标；
- 返回标题、封面、作者和媒体摘要等预览数据；
- 将 `DownloadTask.options` 转换为平台爬虫需要的参数；
- 调用平台爬虫并返回下载结果；
- 按需提供搜索、关注、收藏或历史候选。

适配器通过 `ModuleInfo.capabilities` 声明能力。界面根据能力显示入口，不为单个平台写独立任务流程。

## 3. 平台实现

| 平台 | 状态 | 接入重点 |
| --- | --- | --- |
| Twitter/X | 可用 | 用户、单帖、关注与媒体下载 |
| Pixiv | 可用 | 作品、画师、系列、小说、排行、收藏、关注、FANBOX、Sketch 与 ugoira |
| JMComic | 可用 | 搜索、详情、章节、收藏、观看记录与图片还原 |
| Bluesky | 可用 | 用户、关注、搜索、图片与 HLS 视频 |
| Instagram | 可用 | 账号、帖子、Reels、图片与视频 |
| E-Hentai / ExHentai | 可用（alpha） | 双站点会话、搜索、画廊、收藏、元数据与可选种子 |
| Google 相似图片 | 可用 | 单图、文件夹、候选检查与导出 |
| 普通网页 | 可用 | 静态资源与浏览器页面媒体发现 |

平台爬虫应返回结构化数据，不直接操作界面。所有进度、日志、文件记录和错误都通过公共回调上报。

## 4. 登录与会话

登录流程由 `core/browser_cookie_capture.py`、`core/browser_driver.py` 和平台会话模块统一协调。

- Twitter/X、Pixiv、FANBOX 和 Instagram 可以打开可见浏览器完成登录；
- JMComic 使用普通 Chrome 资料读取 AVS 与相关 Cookie；
- E-Hentai 表站与 ExHentai 里站使用独立账号资料和 Cookie 文件；
- 请求头 TXT 导入会提取允许的 Cookie、User-Agent 与必要请求信息；
- Cookie 发送范围应按站点隔离。EH 已分别限制表站、里站、图片与种子主机；其他平台的实际覆盖以各客户端为准，不把统一要求当成所有历史请求均已满足的保证。

ChromeDriver 根据 Chrome 主版本选择，并在启用前核对驱动版本。

## 5. 搜索、关注与收藏

搜索结果、关注账号、收藏和浏览记录统一转换成候选项。候选项至少包含平台、稳定 ID、标题、目标地址和可选封面。

平台支持哪些列表由自身能力决定。界面可以刷新、筛选并批量加入任务，但列表请求仍由平台模块执行。需要登录的列表在会话失效时返回明确提示，不降级为匿名结果。

## 6. 下载流程

```text
用户输入
  -> 平台识别与预览
  -> 创建下载任务
  -> 平台发现媒体
  -> 公共下载与进度事件
  -> 转换、合成或压缩
  -> 文件登记与历史记录
```

`TaskManager` 负责排队、并发、取消和重试。平台模块负责发现可信媒体地址，公共服务负责文件名、目录、原子写入、压缩与后处理。

并发按平台总量、作品/单项和作者/范围分组限制，默认作者/范围为 1；实际任务状态使用 `queued`、`running`、`cancelling`、`cancelled`、`completed`、`failed`。平台取得槽位后先发布运行状态，再做目标预览。取消只对排队或运行状态执行条件更新，后处理结束时再次检查取消信号，避免把已结束任务重新写成“停止中”。2026-10-28 本地工作区的具体实现与限制见 [开发与架构说明](../开发与架构说明.md)。

任务配置应在创建时确定并沿调用链传递，网络参数不得靠可变模块全局状态在不同任务之间切换。Twitter 当前使用不可变网络快照，包含媒体冲突策略；成功/失败及账号历史记录使用跨进程读改写锁、进程内缓存和原子替换。这些是已完成的具体修复，不代表其他平台也已统一采用相同记录实现。

BT 下载由用户手动开启，默认关闭。开启后由 aria2 服务接收种子或磁力任务，并支持进度、取消和停止做种。

## 7. 安全要求

- 通用网页抓取拒绝回环、内网和保留地址；
- 下载路径必须位于任务输出目录；
- 解压前检查路径穿越、文件数量和总大小；
- 日志和界面隐藏 Cookie、token、密码和含凭据网址；
- 请求头导入只接受明确允许的字段；
- 临时文件应避免不同任务写入同一路径，完成后按所属任务清理；当前公共下载和 Twitter 部分路径仍使用目标文件旁的 `.part`，主要媒体路径由输出锁保护，并按任务的复用/覆盖/报错/自动改名策略处理重名。适配器必须使用实际返回路径登记文件及交给后处理，不能继续引用原计划名。未覆盖的独立链路见用户手册。完整下载后的重命名失败可能有意保留 `.part`，不能作为垃圾文件无条件删除。

## 8. 外部插件

外部平台插件放在 `data/software_app/plugins/<plugin-id>/`，通过 `plugin.json` 声明入口和 API 版本。插件不会因文件存在而执行，只有明确启用后才会加载。

插件可以增加平台，也可以通过 `replaces` 显式接管同 ID 的内置平台。接管失败时保留内置实现，避免影响其他功能。详细格式见 `../插件开发.md`。

## 9. 接入检查项

新增或扩展平台时需要确认以下内容。

- 输入识别和规范化结果稳定；
- 匿名与登录状态的行为清晰；
- 搜索、分页、预览和媒体发现使用统一模型；
- 取消信号能够结束网络请求、浏览器和后处理；
- 文件名、目录和媒体类型符合公共约定；
- 敏感字段不会进入日志、历史或导出文件；
- 关注、收藏和历史入口只在平台支持时显示。

平台接入检查还应覆盖不同代理任务并发、删除本地文件后的重新下载、重试等待取消和后处理期间取消。纯排版检查、自动化回归与真实站点验收应分别记录，命令见 [开发检查](../开发与架构说明.md#开发检查)。
