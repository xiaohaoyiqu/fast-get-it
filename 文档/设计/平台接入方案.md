## 1. 总体架构

不要让界面直接调用某个脚本的内部细节。统一接口仍然保留，但平台实现必须归软件自身所有：旧项目用于研究解析规则、下载流程和异常边界，不能成为运行时依赖。

推荐分层：

```text
crawler_app/
├── app_core/                    # 通用核心，不依赖具体 UI
│   ├── models.py                # TargetPreview、DownloadTask、ProgressEvent 等数据模型
│   ├── adapter.py               # CrawlerAdapter 基类
│   ├── task_manager.py          # 任务队列、取消、重试、状态流转
│   ├── storage.py               # SQLite 下载库、任务记录、日志
│   ├── settings.py              # 全局配置、路径、代理、Cookie 文件位置
│   └── events.py                # on_log/on_progress/on_file/on_error 回调结构
├── adapters/
│   ├── twitter_adapter/         # 接当前 推特爬虫
│   ├── jmcomic_adapter/         # 接 JMComic
│   ├── pixiv_adapter/           # 接 PixivUtil2
│   ├── google_image_adapter/    # 接 谷歌图片搜索工具
│   ├── bluesky_adapter/         # Bluesky 公开 API
│   ├── instagram_adapter/       # Instagram 页面媒体 alpha
│   ├── document_adapter/        # 后期接 LiteParse
│   └── web_adapter/             # 后期接 crawl4ai/browser-use
├── desktop_ui/                  # PySide6 桌面界面
├── local_api/                   # 后期给手机端/Web 端用的本地 HTTP API
└── resources/                   # 图标、样式、默认配置
```

第一版不需要一次性创建完整目录，可以先在当前项目下建：

## 2. 统一 Adapter 接口

每个站点都实现同一套方法。这样 GUI 只关心“模块列表、目标预览、下载任务、进度事件”，不关心具体站点怎么爬。

建议接口：

```python
class CrawlerAdapter:
    id: str
    display_name: str

    def validate_config(self) -> list[str]:
        """返回配置问题列表。为空表示可运行。"""

    def can_handle(self, text: str) -> bool:
        """判断输入是 URL、用户名、ID、图片路径，是否属于本模块。"""

    def preview_target(self, request, callbacks):
        """输入目标后获取目标状态：标题、作者、头像、数量、是否需要登录等。"""

    def start_download(self, task, callbacks, cancel_event):
        """开始下载。通过 callbacks 回传日志、进度、文件结果。"""

    def cancel(self, task_id: str):
        """可选。无法硬取消时至少设置 cancel_event。"""
```

通用数据模型：

```python
@dataclass
class TargetPreview:
    adapter_id: str
    target: str
    normalized_target: str
    title: str = ""
    author: str = ""
    avatar_url: str = ""
    description: str = ""
    status: str = "ok"          # ok / login_required / not_found / blocked / error
    message: str = ""
    extras: dict = field(default_factory=dict)

@dataclass
class DownloadTask:
    task_id: str
    adapter_id: str
    target: str
    output_dir: str
    options: dict

@dataclass
class ProgressEvent:
    task_id: str
    status: str                  # queued / running / downloading / finished / failed / cancelled
    total: int | None = None
    done: int | None = None
    percent: float | None = None
    speed: str = ""
    message: str = ""
```

回调约定：

```python
callbacks.on_log(task_id, level, message)
callbacks.on_progress(ProgressEvent(...))
callbacks.on_file(task_id, file_info)
callbacks.on_error(task_id, error_message)
callbacks.on_finished(task_id, summary)
```

## 3. 推特爬虫接入

当前入口：

```text

```

- `load_config(path)`

- `prepare_targets(args, config, default_types)`

- `download_one_target(driver, target_url, output_dir, user_choice, config, record, failure_record)`

- `DownloadFailureRecord`

### 3.1 当前软件内置实现方式

当前实现位于：

```text
software_app/crawlers/twitter/service.py
```

服务层不弹 `input()`，不依赖命令行参数，直接接收普通 Python 参数和统一任务对象。`TwitterNativeAdapter` 已不再启动 `twitter_Crawler_2.py` 子进程。

主页预览和关注采集也位于 `software_app/crawlers/twitter/`。关注采集由 adapter 进程内调用，接收 `update_mode=new|all`、增量重叠阈值、`cancel_event`、状态回调和实时账号回调。增量模式按 handle 集合和连续旧账号重叠判断新数据，不按易受取关影响的位置或总数判断；只前置新增账号，不删除旧缓存。全量模式滚动到底后替换列表并计算移除数。超时、主动停止或浏览器被关闭时返回部分结果；未得到任何新账号且页面状态不确定时保留原有缓存。主页头像保存为本地 PNG，主页展开外链、简介文本外链、关注 GraphQL `entities` 和关注行可见链接会去重合并后交给左侧资料卡。下载服务复用已登录 driver，在媒体发现前尝试写入对应主页缓存；历史适配器再用关注/主页缓存补全旧作者记录。

跨平台关注同步统一暴露“更新新的/更新全部”，但不能统一假设展示顺序：Twitter 已确认按新到旧并以 handle 重叠停止；Pixiv 接入时按稳定用户 ID 和真实分页排序验证；Bluesky 按 DID/游标和旧集合重叠；Instagram 明确不依赖顶部位置，只做稳定 ID 集合增补，全量分页完成后才允许计算取关。任一平台的部分/受限响应都必须保留 `partial` 状态，禁止据此删除旧账号。

Twitter 的 Skeb 状态来自 Skeb 官方浏览器扩展：驱动发现已安装且 manifest 校验通过的扩展后加载到独立临时 profile，等待 `.skeb` 账号链接出现再采集。不要在软件里复制扩展私有 API 请求，也不要只按 Twitter handle 推测 Skeb URL。关注列表已有的头像 URL 则可作为资源直接缓存，但必须限制到 `https://pbs.twimg.com`、验证图片 Content-Type/大小，并使用统一代理和重试策略。

批量候选不需要另造一套下载线程：UI 把多选目标逐项转换为 `TaskManager.start_task`，正式任务队列负责 queued/running/cancelled 状态，`adapter.max_concurrency` 的 `BoundedSemaphore` 负责平台并发上限。这样 Twitter 5 路并发和其他平台自己的限制共用同一套状态、取消、日志与历史入库。

### 3.2 必须先修的路径问题

当前推特爬虫默认从“当前运行目录”找：

- `X_cookie.json`
- `downloaded_urls.json`
- `failed_urls.json`

桌面软件里不能依赖用户 `cd` 到目录。需要改成：

```python
BASE_DIR = Path(__file__).resolve().parent
DEFAULT_CONFIG_PATH = BASE_DIR / "config.json"
DEFAULT_COOKIE_PATH = BASE_DIR / "X_cookie.json"
```


它不是必须 Docker。Dockerfile 只做：

```text
python:3.11

```

### 5.1 无 Docker 准备

Windows 本地运行准备：

```powershell
cd .\Pixiv爬虫
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

还需要：

- `ffmpeg.exe` 放到项目目录，或配置到 PATH。
- `config.ini` 配好下载目录和 Cookie。
- Pixiv 登录建议用浏览器 Cookie 中的 `PHPSESSID`。

### 5.2 第一阶段接入方式

PixivUtil2 主入口是交互式菜单，大量 `input()`。不建议第一步直接深度改源码。

推荐先做“子进程适配”：

```python
subprocess.Popen(
    [pixiv_python, "PixivUtil2.py", ...],
    cwd=pixiv_root,
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
    text=True,
)
```

GUI 只做：

- 启动任务。
- 捕获输出显示到日志面板。
- 任务结束后扫描下载目录入库。

### 5.3 第二阶段再抽 API

等本地软件任务系统稳定后，再把 PixivUtil2 常用模式抽成服务层：

- 按画师 ID 下载。
- 按作品 ID 下载。
- 按标签下载。
- 按收藏下载。
- FANBOX 下载。

不建议一开始全量搬 PixivUtil2 的菜单，因为它功能很多，容易拖慢第一版。

## 6. Google 相似图片搜索与网页爬取

当前项目：

```text
谷歌图片搜索工具/googlesearchpicture.py
```

当前能力：

- Tkinter GUI。
- CLI。
- 单图搜索。
- 文件夹批量搜索。
- 输出 TXT/CSV。
- Selenium + ChromeDriver。

### 6.1 当前实现

新版软件不启动旧目录 CLI。`software_app/crawlers/google_image/` 在进程内使用 Selenium 上传图片并提取外部候选页面；桌面端“相似搜索”页签支持单图和文件夹批量，显示查询图片来源与候选表格：

```text
输入：图片文件 / 图片文件夹
输出：相似页面 URL 列表
下一步动作：多选 / 全选 / 预览网页 / 爬取选中页面
```

选中结果通过统一任务系统交给 `software_app/crawlers/webpage/`。网页爬虫只处理用户明确选择的 HTTP/HTTPS 页面，提取静态 HTML 中的图片、视频、音频、`srcset` 和 Open Graph 媒体，并写入 SQLite 下载库。它限制 HTML 大小、每页文件数和单文件大小，拒绝本机及内网 IP 字面量地址。

### 6.2 当前限制

- Google 页面可能要求人工验证，当前不尝试绕过。
- 手动验证等待默认 60 秒且可调；验证页的协议/结构 URL 会被排除，只有有效外部页面会进入候选。用户关闭浏览器不作为需要弹窗的故障。
- 动态 JavaScript 延迟加载、登录页和站点专用反爬可能导致资源不完整。
- 文件夹递归批量搜索与 CSV/JSON/TXT 候选导出已接入；单批限制 20 张图片、1000 个去重候选，停止或后续图片失败时保留部分结果。跨页递归仍待后续补充。
- Google 是辅助发现模块，不负责直接下载候选页面内容。

```text
- task_id
- level
- message
- created_at

settings
- key
- value_json
```

现有 `downloaded_urls.json` 和 `failed_urls.json` 可以先保留，SQLite 作为新软件层的主索引。

2026-09-12 文件操作约定：爬虫任务逐文件上报时可以更新文件的平台和任务归属；用户手动扫描目录只补充新文件，不得把已索引文件改标成当前平台。打开、复制路径不修改索引；重命名成功后同步更新 `files.path/title`；移到 Windows 回收站成功后只删除对应 `files` 行，任务与平台历史是否清理由独立操作决定。

2026-09-12 搜索种类约定：桌面端把所选平台搜索种类同时写入任务 `options_json.content_scope` 和 `options_json.search_mode`。适配器只做参数转换：Pixiv 标签搜索转换为 `all`、`illust_and_ugoira`、`manga`，标题简介搜索使用 `s_mode=s_tc`；JMComic 综合、作品、作者、标签、角色搜索转换为 `main_tag=0..4`。历史页优先读取该字段，旧任务没有字段时再按目标 URL 推断。旧爬虫存在但尚未迁入的软件能力必须在界面标“规划”，不得静默换成另一种下载。

### 15.1 Adapter 和公共服务的边界

Adapter 只负责平台特有能力：

- 目标识别、登录态、搜索、预览和媒体/作品发现。
- 平台特有的请求、分页、反爬、下载方式和元数据解析。
- 把结果转换为统一的 `TargetPreview`、`ResourceInfo` 和 `DownloadResult`。

核心服务负责所有平台共用能力：

- 任务状态、队列、并发限制、取消、重试和日志。
- 目录、文件命名、历史记录和 SQLite 入库。
- 图片/视频/音频格式转换。
- PDF、长图、压缩、解压缩、CSV、邮件和资源清理。
- 缩略图、下载库预览和硬件占用监控。

### 15.2 统一任务输入

任务不能只保存一个字符串目标，至少需要区分：

```text
input_kind: username / work_id / url / search / following / imported_list
raw_input
normalized_target
adapter_id
preview_options
download_options
postprocess_options
```

这样才能支持多个平台 URL 混合下载，也能区分“搜索后选中的作品”和“直接下载指定链接”。

### 15.3 统一资源元数据

平台适配器返回的资源至少应包含：

```text
platform
source_url
source_id
author_id
author_name
title
chapter
media_type
published_at
tags
favorite
local_path
metadata_json
```

其中 `source_id`、`published_at` 和 `media_type` 用于去重、命名、清理和下载历史查询，不能只依赖本地文件名。

### 15.4 新的平台顺序

在现有 X/Twitter 之后，推荐顺序调整为：

1. 公共任务/历史/目录/后处理能力。
2. JMComic。
3. Pixiv 和 Google 相似图片搜索。
4. E-Hentai/ExHentai。
5. 完善 Bluesky、Instagram 和油猴脚本的共享导入/导出能力。

E-Hentai 不应直接套用普通图片适配器，因为它有压缩包、种子、`.eh` 文件和代理环境等独立约束。

### 15.5 Pixiv/FANBOX 和 JMComic 登录边界

- Pixiv R-18 使用 PHPSESSID 且要求用户先在 Pixiv 浏览设置开启年龄限制作品；Adapter 不猜测账号开关状态。
- FANBOXSESSID 只发送给 FANBOX 域名。支持状态接口返回日期时使用接口值，否则只展示月度计费规则推算；受限帖子不进入伪成功状态。
- JMComic 公开搜索和分类不要求 Cookie；收藏夹读取需要独立的 `data/software_app/jmcomic/cookies.json`。Adapter 只保存名称和值，不记录到日志，失效后要求重新导入。
- JMComic 继续受统一队列约束：候选最多 15，Adapter 最大并发 3；图片仍进入公共格式转换、任务历史和下载库。
- PDF/长图实现在 `software_app/core/image_postprocess.py`，不是复制进 JM Adapter；每组硬限制 30 张，JM 只通过任务选项请求公共后处理。

### 15.6 Pixiv 账号资料和历史边界

- 作者资料使用 AJAX 为主、服务端 HTML 为回退；`pximg` 图片请求必须带 Pixiv Referer，并在后台线程完成。
- 作者资料缓存只保存公开资料字段和头像文件，不复制 PHPSESSID/FANBOXSESSID；Cookie 仍只由现有凭据文件管理。
- 作者昵称搜索依据 Pixiv Web AJAX 形状封装在 `PixivCrawler.search_users`，若站点变更响应结构，只替换该边界，不改 UI/队列协议。
- 账号浏览历史属于登录且 Premium 限定能力。程序只缓存实际读取到的作品 URL；软件任务历史仍由 SQLite 管理，两者在视图层合并、在存储层分离。
- 相似搜索到 Pixiv 时必须由用户显式选择 Pixiv 处理；域名识别只用于按钮可用性校验，不能作为后台自动分流依据。

### 15.7 Pixiv 关注缓存和内容范围边界

- 关注分页的持久化边界在 `PixivNativeAdapter.fetch_following`：Crawler 返回规范化分页，Adapter 先原子写入带 `partial/complete/page/fetched_count` 的 JSON，再发 UI 回调。UI 不能承担唯一缓存职责。
- 作者本地预览依次读取 `profile_previews/{user_id}.json` 和关注缓存；只有显式 `live=True` 才访问作者接口或主页。关注缓存提供的是列表级公开资料，在线资料缓存仍用于补全外链和本地头像文件。
- “搜索范围”和“下载目标类型”分开保存。`requested_content_scope` 表示用户当时选择的发现范围，`content_scope/search_mode/input_kind` 表示具体 URL 解析出的实际任务类型。历史按实际类型显示。
- Pixiv 搜索候选至少保留 `title/author_id/author_name/published_at/tags/url/input_kind`；下载文件继续通过统一 `FileRecord` 入库，界面不另建只适用于 Pixiv 的历史数据表。
- 可见文本实体解码放在 Pixiv 边界层，最多重复三次并在稳定后停止；原始接口对象不写入日志，页面 HTML 仍由静态安全渲染器处理。

### 15.8 Pixiv 本人收藏、小说文件和网络边界

- “作品收藏 / 小说收藏”是当前登录 Pixiv 账号的资源，不是通用关键词搜索。Adapter 必须从 `PHPSESSID` 识别账号，再调用收藏分页；UI 不允许用手动输入覆盖为其他用户。成功或部分取得的规范化候选分别原子写入 `json/pixiv/bookmarked_works.json`、`bookmarked_novels.json`，本地读取不联网。
- 小说下载的稳定交付物是三份：给人阅读的 UTF-8 BOM TXT、带基础排版的 HTML、用于保留接口字段的原始 JSON。三份文件都通过统一 `FileRecord` 进入下载库和历史，不能只把 JSON 当作小说正文。
- Pixiv `requests.Session` 禁止继承系统环境代理，只接受任务/设置明确传入的 `proxy_url`；空值表示真实直连。账号资料、关注、收藏和头像使用同一显式代理来源，FANBOX/Sketch 受限会话只复制经过校验的网络设置和所属域 Cookie。
- 头像二进制读取归 Pixiv Adapter 边界：仅允许 Pixiv/pximg HTTPS 主机，设置 Referer，校验响应类型与体积后返回 UI。连接检查先验证当前账号资料，再在存在头像 URL 时验证图片响应；代理错误、直连超时、登录失效应分别给出动作建议，任何提示和日志都不得包含 Cookie 或带凭据的代理地址。
- 插件列表中的“说明”面向使用者表达插件能完成的工作；模块路径、生命周期和接管关系属于次级技术信息。内置插件不可启停，外部插件继续遵守显式启用、显式 `replaces` 和重启生效边界。

### 15.9 PixivUtil2 参考代码和公共归档边界

- “参考并优化拿来用”不等于在运行时 import 旧 `Pixiv爬虫/`。旧 Handler 可以提供接口形状、ZIP 校验、帧处理和异常边界，但正式代码必须迁入 `software_app/`，去掉 `input()`、全局配置、旧 SQLite 和平台专用通知器后再由任务系统调用。
- 公共归档所有权属于 `core/archive_service.py`，不属于 Pixiv Adapter。`TaskManager` 在 Adapter 下载结束后统一调用，因此 Twitter、Pixiv、JMComic、网页资源以及以后新增平台不需要复制压缩代码。
- 任务选项统一为 `archive_mode=none|task|folder`、`extract_archives: bool`、`archive_cleanup_sources: bool`。设置默认 `none/false/false`；重试采用当前保存值。`folder` 以本任务每个实际资源父目录为分组，可映射漫画章节；更复杂的整本/作者/日期分组以后应通过结构化元数据扩展，不能猜目录字符串。
- 普通 ZIP 解压必须限制成员数量、解压总体积、路径、链接、加密和压缩比，并使用临时目录提交。Pixiv ugoira ZIP 是动画源数据，不进入普通解压；E-Hentai 的站点压缩包和种子也应先由对应 Adapter 下载，再选择是否交给公共安全解压。
- 清理源文件是破坏性后处理，只能在新 ZIP 写入、重新打开并完成成员校验、原子提交之后执行。只能删除当前任务提供给归档器的规范化文件路径；删除后必须同步 SQLite，不能遗留下载库幽灵条目。清理开始后应完成精确集合，避免晚到取消造成半清理目录。
