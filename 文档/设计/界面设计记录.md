## 当前软件界面建议

- Tkinter 界面继续保持工具型、信息密集、少装饰的风格。
- 目标浏览卡片优先用结构化字段渲染：头像、显示名、@名、简介、主页、Skeb/外链。
- 左侧目标浏览已抽出 `TargetPreviewRenderer`，安装 `tkinterweb` 时用 `TkinterWeb.HtmlFrame` 渲染本软件生成的 HTML/CSS 卡片；未安装时退回文本。
- 左侧候选/历史列表采用持久单选反馈：点击后保留行高亮并显示选中摘要，不因填入目标或预览而重排列表；后台更新后按稳定目标键恢复选择和滚动位置。
- 简介属于长度不可控的外部文本，使用固定 4 行只读文本框和独立滚动条，不允许内容高度挤压主页、外链和主操作。按钮文案明确区分“本地预览”和“在线获取资料”，避免用户误以为预览一定会联网。
- 平台候选列表使用系统原生扩展多选（Ctrl/Shift），并提供可发现的“全选当前页 / 取消选择 / 加入下载队列”。多项选择时禁用只适用于单项的“填入目标/在线预览”，但允许一次创建多项任务；状态文案同时说明所选数量和平台并发上限。
- 若要运行完整 Vue/Nuxt 前端，应改为 `pywebview`、WebView2 或 CEF 这类真实浏览器内核承载，不建议在 Tk 原生控件里直接解析 Vue 源码。

## 2026-09-13 主题解耦与视觉整理

- 将颜色、字体、按钮、输入框、Notebook、Treeview 和进度条样式从主窗口抽到 `software_app/ui/theme.py`。页面控制器不再持有成套视觉常量，之后换主题不会影响下载、插件、任务和存储逻辑。
- 调整为中性浅灰工作区、白色内容卡、深蓝侧栏和靛蓝主操作；橙色只保留给重点执行动作。统一输入框内边距、表格行高、表头和禁用态，减少此前青绿色大面积铺陈带来的陈旧感。
- 仍保留 Tkinter 的工具型高密度布局、最小尺寸和滚动规则。若以后改用 WebView/PySide，只替换视图层，通过现有 Adapter、TaskManager、SQLite 和回调事件继续工作，不要求重写爬虫。
- 设置页的平台插件区域改为可滚动状态表，显示内置/外部、加载状态和 `replaces` 接管目标。只有外部插件可操作启停，且以“待重启”状态明确反馈，避免运行中热换 Adapter 导致任务状态错乱。
- Pixiv 年龄分区选择 R-18 时就近弹出说明并可打开官方浏览设置，保存时再次确认；这类不可由软件可靠验证的账号开关不显示虚假的“已开启”。
- FANBOX 状态按钮与结果放在同一设置卡片，区分“接口精确日期”和“官方规则推算”；无活动方案直接显示无需续费。JMComic 设置独立成卡片，集中放域名、名称匹配、分类/排行筛选、收藏夹登录信息和章节后处理；PDF/长图默认关闭，避免低配置设备在普通下载时承担额外合成负载。

## 2026-09-13 Pixiv 交互补充

- “本地预览”优先显示作者缓存；“在线获取资料”在执行时禁用并显示加载文案，结束或失败后恢复，目标切换后旧响应不会覆盖当前资料。
- 头像区域显示“头像加载中/失败”，远程图片不再让整个窗口停顿；简介继续由可伸缩区域承载，长简介不挤压主操作。
- Pixiv 内容范围加入作者搜索、小说收藏和 Premium 浏览历史；设置页提供收藏标签、作者匹配方式和历史数量。
- 相似搜索新增“交给 Pixiv 下载”作为明确的次级动作，并在确认文案中说明不会自动按网址切换平台。
- “关注画师”进度标题改为动态状态：等待接口、本页落盘、部分/完整缓存都在进度条旁显示，不能只用一个不断重复的“第 1 页、0 个”。
- Pixiv 左侧详情按目标类型组织：作者显示 Pixiv ID 和简介，作品/小说显示标题、作者、标签与发布日期，搜索类目标显示候选数量；不再把作品 ID 伪装成 `@用户名`。
- Pixiv 搜索范围提供就近说明。“标题 / 简介”和标签范围明确为发现条件；具体作品 URL 的顶部操作会说明实际下载类型。关注范围禁用容易误解的顶部直接启动按钮，下载从已选画师候选进入队列。
- 历史表固定数值列居中、文本列左对齐；作品任务优先显示下载资源的标题与作者，避免长 URL 撑乱视觉层级。账号浏览历史与软件任务同 URL 时，以包含状态和文件数的软件任务行为准。

## 2026-09-13 候选工具栏、侧栏与插件说明

- 采用现有 `ui-ux-pro-max` 记录中的“动作分组、状态靠近操作、最小窗口优先”原则，把候选区从单行堆按钮改为多行工具栏。更新、本地读取、单项操作、批量操作和进度各有固定层级；动态长文本独占整行并随容器换行，不能参与按钮所在列的宽度计算。
- 进度反馈必须与当前任务语义一致。关注分页进度只在 Twitter“关注账号”和 Pixiv“关注画师”出现；作者搜索、作品候选和本人收藏隐藏它，避免视觉上像仍在抓关注列表，也避免空进度控件把按钮推向右侧。
- 330 像素左侧栏里的不可控内容采用“内容一行、动作下一行”：外链下拉框占满一行，“打开外链 / 复制地址”放到下一行；简介保持固定高度和内部滚动。按钮文字使用短动作词，完整含义由邻近说明承担。
- Pixiv 收藏入口明确写“我的作品收藏 / 我的小说收藏”，输入框禁用并显示当前 Cookie 账号语义；“读取本地收藏”和在线更新分开，避免把本人收藏误解为任意文本搜索。
- 插件表保留适合扫描的短列，选择后在下方用多行显示“模块、用途、说明、来源、生命周期”。内置 Twitter/Pixiv/JMComic/Google/网页插件分别解释能给用户完成什么；Google 明确是发现候选，不冒充下载器。技术模块 ID 不再代替用途说明。
- “支持方案 / 支持 xxx”统一改为更准确的“订阅状态 / 付费内容 / 查看说明”，说明文字逐行展示登录、订阅和续费条件，避免长句横向越界。
- 当前 Tk 界面在 `1080x680`、`1240x780`、`1500x860` 三档进行控件边界检查。今后增加候选按钮时优先新增行或放入可滚动容器，不回到依靠扩大最小窗口来容纳单行工具栏的做法。

## 2026-09-13 公共归档调试界面

- 设置页新增“公共压缩 / 解压（调试）”卡片，并把原“平台插件”改名为“平台接入插件（与上方压缩后处理不同）”。前者是所有任务可使用的后处理，后者是站点 Adapter 生命周期，两种扩展概念不再共用一个模糊标题。
- 归档主选项使用单选下拉表达互斥范围：不压缩、按整个任务、按资源文件夹。安全解压与校验后清理是独立复选框；危险的源文件清理默认关闭，首次启用就近二次确认。
- 卡片说明明确标注来源于 PixivUtil2 行为参考、当前仅调试 ZIP、默认保留源文件，以及“资源文件夹”适合漫画章节。技术限制放在文档，界面只保留对选择有帮助的结果和风险提示。
- 压缩与解压复用任务队列的状态、进度、取消和错误区域，不另开阻塞窗口。用户退出软件时仍沿用活动任务确认和协作取消，避免归档线程成为无法管理的后台进程。
