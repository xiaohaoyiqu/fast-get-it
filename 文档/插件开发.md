# 平台插件开发说明

软件的 Twitter、Pixiv、JMComic、Google 相似搜索、网页资源、Bluesky、Instagram 和 E-Hentai/ExHentai 都通过同一 `CrawlerAdapter` 协议注册。内置模块由软件随版本维护；外部插件目录为：

```text
data/software_app/plugins/<plugin-id>/
  plugin.json
  plugin.py
```

最小 `plugin.json`：

```json
{
  "id": "sample-plugin",
  "name": "示例平台",
  "api_version": 1,
  "enabled": true,
  "module": "plugin.py",
  "factory": "create_adapters"
}
```

`create_adapters()` 返回一个 `CrawlerAdapter`，或返回多个 Adapter 的列表。每个 Adapter 至少实现 `preview_target()` 和 `download()`；支持搜索时再实现 `search_targets()` 并在 `ModuleInfo.capabilities` 中声明 `search`。

插件不会因为目录存在就自动执行，只有清单明确设置 `enabled=true` 才加载。模块文件必须位于自己的插件目录内，API 版本必须匹配，模块 ID 重复会被拒绝。确实需要替换内置模块时，清单必须增加例如 `"replaces": "pixiv"`，且插件只能返回同 ID 的一个 Adapter；这是显式接管，不允许静默覆盖。

设置页显示插件加载数量并可打开插件目录；修改清单或代码后需要重启软件。命令行可执行：

```powershell
python .\run_software.py plugins
```

## 在界面中管理

打开“设置 → 平台插件”，列表会显示插件名称、内置/外部类型、当前状态、接管模块和加载说明。

- 内置 Twitter、Pixiv 等模块作为安全回退，不能在运行中直接停用。
- 选择外部插件后，可以点击“启用（重启后）”或“停用（重启后）”。启用外部 Python 代码前会再次要求确认。
- 开关只原子修改对应 `plugin.json`，不会热替换当前下载器；重新启动软件后才应用，已有运行任务不受本次点击影响。
- “打开目录”进入插件根目录，“开发说明”打开内置说明弹窗；完整开发文档为本文。加载错误会保留在列表中，不会阻止其他平台启动。

## 接管 Twitter

外部 Twitter 插件的清单需要显式声明：

```json
{
  "id": "twitter-custom",
  "name": "自定义 Twitter",
  "api_version": 1,
  "enabled": true,
  "module": "plugin.py",
  "factory": "create_adapters",
  "replaces": "twitter"
}
```

其工厂必须只返回一个 `module_id == "twitter"` 的 Adapter。加载成功后，插件列表中的内置 Twitter 会显示“已被接管”，任务队列、历史、关注列表和界面入口仍使用稳定的 `twitter` 模块 ID；停用外部插件并重启后自动恢复内置实现。没有 `replaces` 时，任何重复的 `twitter` 模块都会被拒绝，不能静默覆盖。

外部插件以当前用户权限运行。只启用已阅读、可信来源的插件，不要把 Cookie 写进插件源码或清单。新的结构化凭据和缓存放在 `data/software_app/json/<platform>/`，尚未迁移的平台数据继续使用其现有运行目录，并通过 Adapter 选项读取。

插件应在自身目录内实现 Adapter 服务边界，不能让主窗口调用交互式菜单或依赖 `input()`。平台能力需要复用时，应通过 `software_app/crawlers/` 中的稳定接口完成。

## 任务、配置与线程约定

- `TaskManager` 创建 `DownloadTask` 并保存最终状态。平台从 `task.options` 读取任务配置，不在执行中用界面当前值替换旧任务参数，也不要改写其他任务共用的代理、超时或重试全局变量。
- 网络、浏览器和耗时文件处理放在工作线程；Tk 变量在启动工作前读取，工作结果经事件队列回到主线程。平台回调不直接操作 Tk 控件。
- `cancel_event` 应在开始请求前、循环处理中、等待重试时及后处理结束后检查。取消后抛出 `TaskCancelled`；不要以空成功结果掩盖取消或全部下载失败。管理器负责取消状态的条件更新，插件不应把已结束任务重新写成运行或停止中。
- 通过 `callbacks.on_progress` 上报日志和进度；通过 `callbacks.on_file(FileRecord(...))` 上报本任务已经落盘的文件。失败保留的产物可以继续登记，但不能把临时占位文件或仅计划生成的路径当成成品。
- 无法逐文件上报的兼容模块可实现 `fallback_scan_root(task)`，返回任务输出目录内尽量小的扫描范围；恢复扫描的深度和修改时间条件仍可能排除部分产物，不能把扫描当作完整下载证明。
- 完整使用 `on_file` 上报成品的适配器可声明 `reports_files = True`，成功零产出时不触发兼容性目录扫描。默认 False 以兼容旧模块。已有逐媒体清单时，失败/取消也不通过广扫目录猜测产物；未接入清单的兼容路径仍有原来的范围和时间边界，遗漏产物可由用户主动扫描下载库。
- 历史记录表示此前成功过，不能单凭 URL 在记录中就认定磁盘文件仍存在。并发记录写入应合并最新内容并原子替换；进程内锁与跨进程互斥要分别处理。

直接复用内置 Twitter 下载函数时，`configure_downloads(...)` 现在返回不可变的 `DownloadNetworkConfig`，不会再改写全局请求配置。调用方需要保存返回值，并沿调用链传入 `network_config=`；只调用配置函数然后丢弃结果不会应用这些自定义参数。这是内置下载辅助接口的变化，`CrawlerAdapter` 的插件 API 版本仍为 1。

新增插件至少验证目标解析、两个不同网络配置任务的并发、取消等待、失败文件登记和重复下载行为。基础检查命令与验收范围统一见 [开发与架构说明](开发与架构说明.md#开发检查)。

## 逐媒体结果与浏览器名额的可选接入

10-29 的逐媒体辅助接口仍随本项目维护，插件协议版本保持 1。外部替换适配器不会仅因平台 ID 相同就自动获得这些能力。

- 使用 `core/media_results.py` 构造描述并调用 `run_media_jobs`，由管理器接收 `media_plan`/`media_result`，持久化逐项结果；成功结果还保存实际成品路径，供恢复核对索引和文件。只登记已发现且符合任务范围的资源，未发现内容不能当成成功。
- 只有 `download` 确实处理 `_retry_media`，重新读取页面、核对媒体并使用原来的子目录时，才声明 `supports_media_retry = True`。可参照 Bluesky/Instagram 及 Pixiv 单作品普通图片路径；同平台其他类型不会因此自动获得逐媒体计划。描述中的页面/序号/类型/路径摘要不等于内容摘要。
- 管理器负责 partial 终态和统计，插件不直接把数据库任务改为完成。取消始终抛 `TaskCancelled`，已落盘文件继续用实际路径上报；不能以浏览器回退掩盖文件提交或通知错误。
- 需要共享浏览器名额时，在实际浏览器创建至退出的完整生命周期最外层使用 `BROWSER_POOL.session(cancel_event)`，不要同时在外层和底层重复申请。必须在资源清理的 finally 完成后释放；只调用 Chrome 构造函数不会自动加入名额池。

界面分页每页 100 项，选中补下会重新核对源任务的未完成记录。源任务终态保留为历史，已补全状态独立更新。相关新增功能本轮尚未运行验收。
