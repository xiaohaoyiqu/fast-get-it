# 欲求达操作与使用说明

本文说明如何启动和使用“欲求达”工作台，包括 Twitter/X、Pixiv、JMComic、Bluesky、Instagram、E-Hentai/ExHentai、相似图片搜索、跨平台黑名单、任务队列和下载库。

## 1. 启动软件

从源码运行时，首次使用先在项目目录安装依赖：

```powershell
python -m pip install -r requirements-app.txt
```

启动桌面工作台：

```powershell
python .\run_software.py
```

主界面左侧用于查找目标、查看资料和管理黑名单；右侧用于创建任务、查看平台候选、相似搜索、任务队列、下载库和设置。混合平台批量任务、人物配置、执行前检查和单次设置下载位于右上角“更多操作”。

### 人物配置与独立任务设置

右上角 **更多操作 → 人物配置** 可以为 Twitter/X、Pixiv、Bluesky 和 Instagram 的明确作者／账号保存独立配置，包括下载类型、图片／视频／动图／音频格式和可选保存目录；Pixiv 另有最多作品数和跳过 AI 开关。先填入作者主页或账号，再打开窗口；窗口始终绑定打开时显示的平台和账号。空白目录沿用当前任务目录。

匹配按平台和账号标识精确进行，不按显示昵称猜测。Pixiv 纯数字 ID 须选择作者范围；单帖、单作品、搜索词和不支持的平台不会自动推断作者并套用配置。用户名可能改名或被重新注册，仍需核对账号；Pixiv 优先使用数字作者 ID，Bluesky 可使用 DID。Cookie、登录账号和代理不存入人物配置。

目标输入框下方显示匹配情况，开始确认中列出实际人物配置、媒体类型、格式和目录。每个任务保存独立参数副本及人物配置快照；A、B 任务可以采用不同设置，修改全局设置或人物配置不会改变已经创建的任务。人物配置覆盖其保存的字段，其余字段沿用创建时的任务设置；界面全局选项不会随人物切换而被反写。混合批次保留批次独立子目录，逐媒体补下保留原目录。

**配置总览** 可按平台、账号或名称查询，每页最多 100 项，显示保存目录、状态和 UTC 修改时间；旧记录没有时间时明确标注。支持编辑、重设和确认删除。损坏配置不会静默回退：创建任务时仍报错，编辑时先显示读取错误，再经确认打开重设窗口；也可在总览中直接确认删除。窗口打开后若配置被另一窗口或实例修改，保存／删除会拒绝旧版本并提示重新打开。

**单次设置下载** 在普通任务创建流程中打开本次覆盖窗口。先列出目标及其继承设置，可仅为这批新任务覆盖下载类型、四类格式和保存目录；空白表示沿用。优先级为当前设置 → 人物配置 → 本次覆盖，只改变本次新任务，不保存人物默认值，也不改变工作台的默认目录。多目标使用相同覆盖值、分别保存快照。之后仍需确认才能入队，取消窗口不创建任务。混合平台批次和媒体补下不通过这个入口改变目录。

队列的 **按原设置重试** 默认沿用各自原任务的参数、人物配置快照、本次覆盖和输出目录。只有明确选择 **按当前设置重试**，才清除旧人物快照及单次覆盖，更新当前保存的格式、后处理、媒体类型、代理、重试及已覆盖的平台过滤选项，并重新匹配最新人物配置；人物保存目录也可能随之变化。两种操作均新建任务，不改写原任务；旧相似图片发现任务保留网页下载语义并记录原任务关联。中断恢复继续沿用原任务参数和快照；损坏参数或目标与快照不匹配时拒绝启动。

### 请求与账号资料的后续维护

后续源码已让指定平台的新导入和浏览器登录保存使用 Cookie 记录列表，保留同名 Cookie 的不同域／路径，以及 Secure、HttpOnly、SameSite、hostOnly、过期时间。继续支持旧名称字典、JSON 导出、Netscape 与请求头文本，现有文件不会自动重写；旧资料已经丢失的属性无法恢复，会按所选平台或当前站点限定默认范围。Cookie 文件最多 10 MiB、20000 条；必要登录 Cookie 为空或已过期会拒绝保存，不覆盖旧文件。旧资料限定范围后若不再适用于实际登录，可重新从对应站点获取带属性的浏览器导出。

JSON 默认最多读取 32 MiB、HTML 默认 16 MiB，JM 域名发现最多 1 MiB，均以分块解码后字节计数；超过会报错，不将截断内容作为有效结果。读取之间可以暂停／取消，已进入的 DNS、连接或读取仍受底层返回或超时控制。JM curl 网页与连接检查现也采用逐跳处理，跨站使用独立临时会话，最终响应关闭后释放；这些新边界尚未经过运行验收。

公共请求已将公共 JSON 及指定平台 GET 纳入逐跳地址检查和跨源凭据隔离；最多 5 次跳转，禁止 HTTPS 降级，跨源去除无域 Cookie、源站认证和常见认证／CSRF 头。域 Cookie 按 CookieJar 策略匹配，不会把 FANBOX 域内的必要会话直接去掉。该覆盖包含 Pixiv HTML、FANBOX/Sketch、Bluesky、Instagram 静态、EH 页面、JM 账号接口和后续接入的 JM curl_cffi 网页；浏览器直连与外部引擎不属于此覆盖范围。

Pixiv 的普通图片、逐页补下、ugoira、预览图与头像请求使用不含账号 Cookie 的视图，下载保留固定 Pixiv Referer；作品资料 API 仍使用登录会话。FANBOX 的付费媒体保持其域内账号访问方式。EH 收藏提交不随跳转重新发送 POST，会重新读取收藏状态确认结果；网络中断后结果不确定时应先刷新状态，再决定是否手动操作。

当前设置重试会先解析人物目录和实际参数，再检查重复／活跃任务，并按同一快照入队。新建人物配置的修改时间已补齐迁移数据库情形；旧记录未修改前仍标为未记时。

### 执行前检查与 Driver 结果

右上角 **更多操作 → 执行前检查** 按当前工作台目标逐项匹配人物配置，后台检查各自实际目录和磁盘空间，一次最多 100 项；配置读取失败的目标会单独标明未检查。报告包含起止时间和设置来源，同一实际目录只探测一次。浏览器、FFmpeg 和 aria2 按当前任务类型／参数判断是否需要检查；动态发现的媒体仍可能改变实际工具需求。

默认不写文件。勾选 **试写现有目录** 后点 **重新检查**，才会创建、写入并清理临时文件；目录不存在时只试写最近现有父目录，不提前创建目标目录，也不保证稍后逐层创建或执行时仍可写。关闭窗口会停止后续目标检查，已进入的本机调用仍等待返回。检查不验证网站登录、远程账号或真实下载，也不会安装工具；单次覆盖窗口内尚未确认的值不属于工作台检查范围。

设置页底部的 **检测浏览器驱动** 和 **安装／更新驱动** 仍独立保留。检测结果显示在按钮下方，包含 Chrome 版本、Driver 版本、来源和路径；缺少 Chrome 时不会仅凭已有 Driver 宣称兼容。只检测不复制或安装驱动，安装／更新才会执行相应操作。

ChromeDriver 更新先在独立临时文件中验证运行及主版本，成功后才替换旧驱动；aria2 安装同样先验证能否运行。验证失败、中断或文件占用导致替换失败时，保留原可执行文件。首次安装失败不会留下未验证的正式工具。Windows 仍可能拒绝替换使用中的程序；请等相关任务及工具进程退出后重试。安装不会强制结束浏览器或下载进程。

### 浏览器关闭或会话中断

Windows 版新创建的 Selenium 会话现在使用独立进程组：Twitter、Google 搜索、动态网页、自动登录捕获和 JM 读取资料所创建的驱动，在打开 Chrome 会话前绑定；退出时先正常关闭，再回收该组残留。绑定依据是本次创建进程的系统句柄，不按 Chrome 名称扫描，也不接管你平时打开的浏览器。系统限制导致绑定失败时，会停止本次启动并报告“浏览器进程管理失败”。非 Windows 保持原有 Selenium 退出方式。

Twitter 自建临时资料目录在退出后有最多两秒的占用重试，清理前复核目录位置、身份及链接属性；变化或持续占用时保留并提示。若直接强制结束软件，Windows 会关闭本次进程组，但临时资料可能来不及删除；程序不会在下次启动时猜测归属并批量清理历史目录。JM 手动登录浏览器及其长期资料不因此自动关闭或删除。

Twitter 媒体扫描、Google 相似图片搜索及动态网页下载发现浏览器会话失效时，会报告“浏览器会话中断”，不会因扫描线程结束而误记下载完成，也不会按任务的自动重试次数反复重新打开窗口。检查 Chrome／驱动及运行环境后，可在队列手动重试；若已点击取消，仍按取消处理。无法仅凭会话断开判断是手动关窗还是进程崩溃。

Twitter 页面扫描遇到其他连续错误，最多尝试五轮，仍失败会把原错误传回任务；普通瞬态错误仍可恢复。中断前已经排队的媒体先完成现有传输收尾，已保存文件及记录保留，因此报错可能需要等待下载请求返回。此过程不表示全部作品已发现，手动重试继续使用原有去重／冲突策略，不新增浏览器分页断点或未发现作品清单。

## 2. 首次配置

打开右侧 **设置** 页面，至少检查以下项目：

1. **默认保存目录**：新任务保存到这里。在工作台或设置中点击“浏览”选择目录后立即记住；手动输入的有效目录在离开输入框、开始任务或正常退出时记住。重启优先使用上次目录，尚未选择时才使用程序默认目录；取消选择或输入无效路径不会覆盖上次有效目录。
2. **代理 URL**：可留空，也可填写 `http://127.0.0.1:端口`、HTTPS 或 SOCKS 代理。不要填写带账号密码的代理地址。
3. **失败自动重试**：适合临时断网或单个媒体请求失败。
4. **统一输出格式**：分别选择图片、视频、动图和音频格式。
5. **公共压缩 / 解压**：默认关闭；需要时可按整个任务或资源文件夹生成 ZIP。
6. **任务结束时保存未完成文件清单**：默认关闭。当前由 Twitter 单帖直连和浏览器扫描链路使用；存在已追踪但未完成的媒体时，在输出目录生成 `未完成_<任务ID>.txt`，列出参考文件名、原始下载地址和已有的失败原因。其他平台尚未接入该清单。
7. **Chrome / ChromeDriver**：Twitter、Google Lens 和部分网页登录需要浏览器自动化。先点检测；驱动缺失、损坏或主版本不匹配时点 **安装 / 更新驱动**，软件会按 Chrome 版本自动选择，不需要用户手动找版本。

除保存目录外，其他选项修改完成后点 **保存设置**，整组设置会一次性写入。媒体 HTTP 总限速、受管理浏览器会话上限及内存保护保存后立即生效；其他任务选项影响之后创建的任务或明确选择“按当前设置重试”的任务。Pixiv 日期必须是真实日期，开始不能晚于结束；代理端口须有效。连接检查使用当前输入框中的代理，下载任务仍使用创建时保存的参数。

**媒体 HTTP 总限速**默认关闭，初始数值为 1024 KiB/s（1 MiB/s）；可填写 1–1048576 的整数。所有受支持的 HTTP 媒体下载共用本实例总预算，不是每个任务各自获得相同上限。保存后可调整运行中任务的限速，关闭后保留数值；保存失败不会改变正在使用的预算。等待期间可以暂停或取消，暂停任务不会阻塞其他任务分配预算。

覆盖公共 HTTP 下载器、Twitter 图片/视频/GIF/音频源、JM 图片及随任务下载的封面、普通网页直连媒体；经公共下载器的 Pixiv、FANBOX、Sketch、Instagram、Bluesky 图片及 EH 展示图也参与。Bluesky HLS 的分片和初始化数据也计入预算；按传输源字节节流，不按转换后的成品大小计算。资料接口、播放列表、在线预览/头像、普通网页 HTML、浏览器直接接收的媒体、其他外部引擎和 BT 暂未覆盖。底层网络缓冲可能造成短时突发，不能当作操作系统网络限速；多个 exe 实例各有独立预算，其他已打开实例不会自动同步本实例的即时修改。

Twitter 的下载浏览器、在线资料、关注刷新和头像请求均传递已保存的代理配置；修改代理后先保存，再重新启动相应操作。

### aria2 下载／上传限速

设置页 **E-Hentai / ExHentai 下载** 区域提供“启用 aria2 下载／上传限速”，默认关闭。下载初始值 1024 KiB/s，上传初始值 128 KiB/s；两项均接受 1–1048576 的整数。修改后点击 **保存设置**，用于之后创建的 EH 任务。

这是每个 aria2 进程自己的上限，与上面的 HTTP 共享预算分开；多个 BT 任务同时运行时，各自获得设置的上限。启用时下载和上传两项均生效；关闭表示 aria2 不设置这两项速度上限，不能通过填写 0 表示禁止上传。限速数值保存到任务参数，运行中的任务不动态调速；原设置重试／中断恢复沿用原值，当前设置重试采用当前值。没有这几项参数的旧任务按旧行为不限速。

执行前检查和 BT 任务日志显示该任务的限速状态。软件通过 aria2 官方命令行参数设置进程总体下载／上传上限，不读取外部 `aria2.conf`，以免用户全局参数改变本任务行为。BT/P2P 的网络路径仍不等于 EH 图片 HTTP 代理；限速也不表示下载阶段零上传。本轮已用本机生成种子和 HTTP webseed 实测下载限速及取消，上传仅验证参数接入，未测真实 P2P 上传吞吐。

### 续传缓存预览与清理

在设置页默认保存目录旁点击 **续传缓存清理**：

1. 选择要检查的下载根目录，点击 **预览缓存**。扫描在后台执行，不改变缓存；默认不选中任何项。
2. 查看 HTTP／HLS 类型、缓存目录、文件数、字节数和检查结果。可多选具体目录，或点击 **选择全部可清理项**。
3. 点击 **清理所选缓存**，确认数量与字节范围后执行。清理会失去所选目录的续传进度，后续重试可能需要重新下载。

只接管带有匹配归属记录的 `.yuqiuda-http-<摘要>/` 与 `.yuqiuda-hls-<摘要>/`。目录中出现未知文件、子目录、链接／重解析点、硬链接或无效归属时整项跳过；旧 `.part/.resume`、`.part.mp4` 附件不会自动清理。正式成品、Cookie、任务、日志和下载库索引保留。本轮只在生成样本中验证清理，没有清理你的现有下载缓存。

开始清理前需结束本实例任务（含暂停任务）；共享数据库有未结束任务时也会停止。每个缓存使用与下载相同的跨进程输出锁，被其他实例占用时跳过。执行前重新核对目录及文件的身份、大小、时间和清单；预览后变化的项保留，需要重新预览。该检查不逐个重算大分片的内容摘要，也不是对外部程序任意修改的原子文件系统快照。

清理只逐个移除确认过的内部普通文件，不递归删除目录；归属标记最后移除。可以停止当前操作，已删除的缓存不能撤销，未完成部分保留；结束后需要重新预览。一次最多预览 1000 个缓存目录，过大的扫描范围需要缩小目录后重试。

公共压缩卡片还提供 **下载时重命名文件** 和 **重命名后删除源文件**，默认均开启。当前开关接入 Twitter 的图片、视频及经视频下载路径处理的 GIF，不会统一修改其他平台的命名策略，也不迁移已下载文件。开启重命名且取得来源信息时，使用日期、推文 ID 和序号命名；关闭后按媒体 URL 生成原始名称。关闭删除源文件时，会复制出目标名称并保留原始名副本，增加磁盘占用；图片仍会按所选格式转换。Bluesky、Instagram 继续使用自身的日期/来源命名，Pixiv、JMComic、EH 按各自作品和页码规则保存。

### 通过浏览器获取登录 Cookie

“导入 Cookie 文件”的文件处理在后台运行，完成后恢复导入按钮并显示结果。EH 的联网验证需要单独点击，不影响离线保存。

设置页的 **浏览器登录与 Cookie** 支持 Twitter/X、Pixiv、FANBOX、Instagram、E-Hentai 表站和 ExHentai 里站。普通平台可点击 **打开登录浏览器并获取**；EH 仅 **手动填写 EH Cookie** 或 **导入 Cookie 文件**，自动浏览器流程已移除。在日常浏览器登录后，从 F12 → Application → Storage → Cookies 选择对应站点，复制各字段值填写；本地保存检查必需字段和格式，不联网，也不代表登录有效。需要时单独点 **验证 EH 登录（联网）**，连接超时不会改写已保存资料。各平台仍可用 **请求头 TXT → JSON** 转换真实 Cookie 请求头；该按钮不支持直接复制的 Cookie 存储表格。JMComic 另外保留原 TXT 中允许的安全请求头。软件不保存账号密码；TXT 和 JSON 都是明文凭证，切勿分享。

Pixiv 与 FANBOX 需要分别获取，保存时会合并到同一个文件。JMComic 在自己的设置卡片中使用 **打开普通 Chrome 登录 → 关闭登录窗口 → 登录完成后获取**，避免验证阶段出现自动化参数。Bluesky 公开接口不需要 Cookie，账号黑名单仍使用临时应用密码。详细步骤见 [浏览器登录与 Cookie](平台/浏览器登录与Cookie.md)。

## 3. 通用下载流程

### 单个目标

1. 在顶部选择平台。
2. 选择该平台的搜索种类或目标类型。
3. 在 **目标 / URL** 输入用户名、作品 ID、章节 ID、关键词或链接。
4. 点 **本地预览** 检查目标识别结果；此操作优先使用本地资料。
5. 需要最新信息时点 **在线获取资料**。
6. 确认保存目录和下载类型后点 **开始任务**。
7. 到 **任务队列** 查看进度、日志和已下载文件。

### 多个候选

1. 在平台候选页执行搜索、读取关注、读取收藏或导入名单。
2. 使用 Ctrl、Shift 或 **全选当前页** 选择多个候选。
3. 可点 **批量填入工作台** 把同平台目标填回输入框，或点 **批量获取资料** 逐项查看资料；这两项都不会启动下载。
4. 点 **加入队列** 才会创建下载任务；新任务按平台并发上限排队执行。

**填入目标** 和 **获取资料** 是当前单项操作；使用对应的“批量”按钮处理多选。候选、历史、相似图片和下载库文件列表支持双击当前行执行单项操作；即使此前选中过多行，也会使用鼠标所在行。相似图片预览一次只允许选中一项，批量下载和导出仍可多选。

顶部目标框也支持一次输入多个目标，使用 `/`、反斜杠 `\` 或顿号 `、` 分隔；点击 **开始任务** 后每个目标会成为独立队列任务。完整 URL 内部的 `/` 会保留，多条完整 URL 请用 `\` 或 `、` 分隔。搜索词输入时 `/` 会保留为搜索内容；斜杠分隔只在作品、作者、章节、账号、帖子和画廊等具体目标类型中启用。E-Hentai 单个画廊 ID/Token 格式中的 `/` 也会保留。单个输入最多加入 100 个目标。

点击 **批量获取资料** 会依次在线读取输入中的作者或作品目标，并把结果放入左侧列表；单击一项可在资料卡查看完整资料，卡片一次只显示一项。每次最多获取 50 项；获取失败的目标也会留在列表中并显示错误。获取过程中按钮会变为 **取消资料获取**，停止会在当前网络请求结束后生效。点击 **开始任务** 则会把目标分别加入下载队列。**本地预览**、**在线获取资料** 和 **打开网页** 是单目标操作，多目标时只处理第一个目标。平台搜索框和其他左侧候选列表仍按各自的查询与选择工作；候选列表可多选后一次加入下载队列。

平台并发彼此独立。在 **设置 → 下载任务并发上限** 可以分别调整每个平台的总并发、作品/单项并发、作者/范围并发；后两项还会受该平台总上限约束。默认作品/单项并发跟随平台总上限，作者/范围并发为 1。作者、关注、搜索和范围类任务有单独的较低上限，多个作品任务可以使用更高上限。设置只影响之后加入队列的任务。默认平台总上限为：Twitter/X 5、Pixiv 2、JMComic 3、Bluesky 3、Instagram 2、E-Hentai/ExHentai 1、Google 相似图片 1、普通网页 3。

### 混合平台链接批次

1. 在主窗口确认保存目录、下载类型，并保存需要使用的各平台设置。
2. 点 **更多操作 → 混合平台批量任务**，每行粘贴一个完整 HTTP(S) 链接，最多 100 行；数字 ID、用户名、关键词仍使用原平台输入框。
3. 点 **识别并预览**。此时不联网、不创建任务；表格显示平台、下载范围、标准化链接，以及重复、无效或回退普通网页的说明。修改输入会使预览失效，需要重新识别。
4. 默认选中所有可用项，可用 Ctrl / Shift 调整选择。点 **确认选中项入队**，核对目录、媒体类型、格式、归档和 EH 种子/BT 开关，再确认执行。
5. 到主窗口 **任务队列** 管理已经创建的任务；各平台使用自己的并发上限。某项启动失败会记入汇总，其他项继续入队。

每批创建 `批次_日期_时间_标识/`，各条目进入 `001_twitter/`、`002_website/` 等独立子目录，平台自己的目录结构保留在其中。批次根目录的 **批次汇总.txt** 包含逐项状态、任务 ID、链接、目录和错误，随运行、暂停、恢复、取消及结束更新；能识别的敏感查询值会隐藏。重启会刷新尚未结束批次的汇总，但不会自动执行下载。

**停止后续入队** 只停止创建剩余任务；已创建任务继续运行，可在队列中暂停或取消。任务失败后的重试会创建独立任务，原批次汇总保留原任务结果。清理任务历史保留批次快照及 TXT，不删除本地文件。

混合识别支持 Twitter/X 账号/帖子、Pixiv 作品/作者/系列/小说/收藏/历史、当前解析器支持的 FANBOX 与 Sketch 链接、JM 漫画/章节、Bluesky 账号/帖子、Instagram 账号/帖子/Reels，以及 EH 画廊/搜索/收藏。JM 域名按已保存配置及内置 `18comic.vip` 识别；其他镜像地址需要先更新设置。已知平台的不支持路径会显示无效，不会自动转成网页任务。FANBOX 创作者使用 `/@创作者` 路径，Sketch 帖子目前支持数字 ID。

未知公网链接会明确标成 **普通网页**，使用静态 HTTP 媒体提取和已保存的每页文件上限；需要浏览器渲染的页面可改用原网页流程。Google 相似图片候选仍按原候选页面流程处理，不受混合批次路由影响。

## 4. Twitter/X

### 下载用户内容

1. 选择 **Twitter/X**。
2. 输入 `@用户名` 或主页地址。
3. 在 **下载类型** 中填写需要的类型：

   - `1`：图片
   - `2`：视频
   - `3`：GIF
   - `4`：音频

4. 多种类型用英文逗号分隔，例如 `1,2,3`。
5. 在线获取资料可读取名称、头像、简介、主页和可识别的 Skeb、FANBOX 等外链。需要有效的 X 登录 Cookie（`auth_token`、`ct0`）和本机 Chrome；exe 直接使用软件内置运行环境，不要求另装 Python。ChromeDriver 缺失或不匹配时，可在设置页检测并安装/更新驱动。
6. 点 **开始任务**，会弹出确认窗口显示当前下载设置（统一输出格式、公共压缩/解压、当前平台设置、保存目录等），确认后开始下载。

媒体页若明确显示 X 的临时加载错误并提示重新加载，软件会自动刷新一次并重新等待媒体列表；登录失效或账号限制仍会直接提示，不会靠重复刷新处理。

Twitter 作者主页属于“作者 / 范围”任务：虽然平台总并发默认是 5，作者任务默认只同时运行 1 个。需要同时下载多个作者时，在设置中调整 Twitter 的作者 / 范围上限，总并发仍是共同约束。

如果运行数据中没有 `config.json`，软件会在 Twitter 数据目录生成默认配置；已有配置会保留。

### 下载单条帖子

把 `x.com/用户名/status/帖子ID` 或 `twitter.com/用户名/status/帖子ID` 填入目标框。单帖任务只处理目标帖子本身的媒体，会排除同页推荐、回复中的其他帖子媒体。

### 使用关注列表

1. 打开 **推特关注/候选**。
2. **读取本地关注** 不访问网站，直接加载缓存。
3. **更新新的** 从顶部扫描，发现与旧缓存重叠后停止，适合日常增量更新。
4. **更新全部** 读取完整关注列表，可核对新增和已取关账号。
5. 更新过程中可以停止；已经取得的分页会保留为部分缓存。
6. 可多选账号批量填入工作台、批量获取资料或加入队列；批量填入仅填写目标，不会直接启动下载。Twitter 平台总并发默认 5，作者/范围并发默认 1，可在设置中分别调整。

各平台历史页支持多选清理和批量填入工作台。清理只移除任务、日志和文件索引，不删除本地媒体；非 Twitter 历史批量填入要求所选记录属于同一内容种类，避免按错误类别解释 ID。

### 导入和导出关注

- 导入支持 JSON、CSV、TXT 和 LIST。
- TXT 可每行写一个 `@用户名`。
- 导入只合并，不会凭离线文件删除已有关注。
- 导出支持 JSON 和 CSV。

## 5. Pixiv

### 登录 Cookie

Pixiv 公开内容可能不要求登录。作品收藏、小说收藏、私密关注、R-18、Premium 历史和 FANBOX 登录内容需要对应 Cookie。推荐直接使用设置页的 **浏览器登录与 Cookie**；以下导出文件方式继续保留。

1. 在浏览器登录 Pixiv。
2. 导出当前域名 Cookie 为 JSON。
3. 在 Pixiv 候选页点 **导入 Cookie**。
4. 回到设置页点 **检查 Pixiv 连接/头像**。

Cookie 至少应包含 Pixiv 使用的 `PHPSESSID`；FANBOX 登录内容通常还需要 `FANBOXSESSID`。

### 查找和下载

Pixiv 可选择以下目标或搜索种类：

- 作品 ID、作者 ID、漫画系列。
- 小说 ID、作者小说、小说系列。
- 标签、标题 / 简介、作者 + 标签。
- 排行榜、新作。
- 作品收藏、小说收藏和浏览历史。
- FANBOX、Sketch。

设置页可以配置日期、最低收藏数、公开/私密范围、年龄分区、单任务作品上限和 AI 作品过滤。选择具体 Pixiv URL 时，软件会按 URL 的实际类型创建任务。

### 关注和收藏缓存

- **更新新的 / 更新全部** 用于关注画师。
- **更新我的作品收藏 / 小说收藏** 会按所选公开／私密范围分页更新本地缓存，并记录是否读到末尾；达到数量或分页上限时保留为部分发现。
- 候选页可再按作品 ID、作者、标签、标题和日期筛选本地收藏。
- 本地筛选不会改写网站收藏，也不会删除完整缓存。

收藏分页按唯一作品计数，重复页、无新增内容、格式异常、无法识别的条目及读取期间网站总数变化均会留下停止原因；异常返回不会按空收藏清理缓存。读取本地收藏时可查看本次范围、读取页数、已发现数量、停止原因及保留的旧条目数。“所选范围完整”只说明本次所选范围已读到末尾，不代表全部公开和私密收藏都是同一时刻的完整快照。

只刷新公开收藏会保留此前的私密条目，反之亦然；旧版没有范围标记的条目也保守保留。因此本地候选可能包含其他范围或上次留下的内容。部分刷新不删除未重新发现的条目，完整刷新只更新此次确认完成的范围；本次全空而同账号已有缓存时仍保留旧内容待复核。

中途请求失败会保存已发现内容与失败记录，然后继续显示错误，可通过“读取本地收藏”查看；不会将失败当成功。相同缓存同时只能由一个本软件窗口／实例刷新，其他刷新会提示占用。提交前重新核对账号；无法识别当前账号或账号不匹配时，不展示已绑定其他账号的缓存。

直接创建作品／小说收藏集合下载时，若发现因重复页、异常条目、网站总数变化或分页安全上限而提前停止，会在下载前报错，避免只下载异常子集却显示整个集合完成。用户主动设置的作品数量上限仍正常生效，不要求每次下载全部收藏。

这些记录在正常结束或捕获到异常时写入，不是逐页事务日志。强制结束进程可能丢失此次未提交的发现；下一次刷新仍从第一页开始。不能把发现缓存的分页位置当作可靠续传游标。作品收藏的逐媒体补下依赖另一份完整媒体计划，按下文专用规则处理；小说收藏尚未接入逐媒体补下。

### 其他集合的分页完整性

漫画系列、小说系列、作品／小说搜索、排行榜、新作和作者标签按唯一作品计数。漫画系列缺少总数 `total` 时，会继续翻页直到明确的空页或本次数量上限，不再在第一页提前结束；对带有已知总数的列表，短页不直接表示末尾。排行核对下一页标记，新作检查后续游标及循环，避免静默漏页。

缺少列表字段、无法识别的条目、重复页没有新增作品、网站总数变化、数量矛盾、异常游标或分页安全上限会明确报错。集合下载先读取选定列表，再传输作品；发现阶段异常不会先下载此前发现的部分作品。网络错误保留原错误分类，取消保持取消。作者普通作品及小说索引也检查必要字段和 ID 格式，异常索引不按空作者处理。

用户设置的 **最多作品数** 仍正常生效。任务日志会区分“已读到本次列表末尾”和“达到本次数量上限，后续作品未读取”；不要求每次读取网站全部作品。当前这些集合最多选择 100 项，漫画系列最多 100 页、小说／作品搜索最多 10 页、排行最多 20 页；其他循环有 100 页安全上限。支持按接口短页或结束标记判断末尾的路径，没有宣称网站提供同一时刻的原子快照。

这是发现阶段的检查。漫画系列、作品搜索和排行榜进一步支持以下持久范围和逐媒体补下规则；小说系列／搜索、新作及作者标签等集合仍没有作品 ID 持久快照或逐媒体精确补下，重试时站内增删可能改变范围。尚未完成发现的任务仍需重新读取列表，没有持久分页游标。

### 收藏、漫画系列、作品搜索与排行榜的作品范围

通过任务队列下载作品／小说收藏、漫画系列、作品搜索或排行榜时，发现检查通过后会先保存本次有序作品 ID 清单，最多 100 个，再开始下载。之后站内增删不会改变这项任务的原清单；自动重试、恢复同一中断任务和“按原设置重试”都沿用它。“按当前设置重试”会重新发现集合，可能得到不同的作品。任务详情可查看固定的 ID。

作品搜索的范围适用于“标签（全部）／标签（插画）／标签（漫画）／标题 / 简介”及默认作品搜索，不包括作者或小说搜索。搜索词、搜索类型、日期、年龄范围及最低收藏数参与范围校验；排行榜绑定完整输入中的榜单、内容类型及可选日期。修改选择条件时请对原任务选择“按当前设置重试”，不要将新条件套到旧清单上。

快照会检查原目标、集合类型、目标账号或系列 ID 和选择参数；损坏或不匹配时明确失败，不悄悄换一批作品。原设置重试的清单与新任务在同一事务创建，清理日志不删除清单，删除任务会清理其清单。没有快照的旧任务、或发现未完成便中断的任务，仍按原发现流程处理。

作品 ID 快照本身只固定作品范围。每次完整执行仍读取最新详情、地址和过滤规则；作品收藏、漫画系列、作品搜索和排行榜进一步完整解析后另存逐媒体计划，支持精确补下并保留该计划中的原目录。小说收藏仍只保存作品范围，作者、小说系列等其他集合未接入此快照。主动取消与中断恢复的规则不变，软件不会因此自动启动网络任务。

## 6. JMComic

本节用于日常操作；Cookie 类型、页面去向和账号功能边界可继续查看 [JMComic 使用与登录](平台/JMComic使用与登录.md)。

### 登录与 Cloudflare 配置

JMComic 的普通页面和登录页面都可能要求 Cloudflare 验证。只导入 `cf_clearance` 不能代表账号已登录；收藏、追更、观看记录和站内屏蔽标签还需要 `AVS`。

推荐配置方法：

1. 让浏览器使用与软件相同的代理，打开当前 JMComic 域名并完成验证和登录。
2. 按 F12 打开开发者工具，进入 **Network（网络）**。
3. 选择一个当前 JMComic 域名下成功返回的请求。
4. 复制完整请求标头到 TXT。可直接点 **请求头 TXT → JSON** 自动转换并导入；软件也支持 Cookie JSON 和 Netscape `cookies.txt`。
5. 在浏览器控制台执行：

   ```javascript
   navigator.userAgent
   ```

6. 把返回的一整行内容填入 **设置 → JMComic · 可用 → 浏览器 User-Agent**。
7. 在 **站点与登录资料** 中填写当前域名、账号用户名、漫画收藏目录 ID 和小说收藏目录 ID。
8. 点 **导入登录资料**，选择刚才的 JSON 或 TXT；候选页也提供同一入口。
9. 查看登录资料状态，再点 **检查连接**。登录资料状态分别说明 AVS、Cloudflare 请求头和账号用户名；连接状态只说明当前站点能否返回网页。

如果返回 HTTP 403，应在相同域名、代理出口和浏览器环境下重新完成验证，并一起更新 Cookie、请求标头和 User-Agent。

JMComic 会优先使用显式代理；留空时尝试读取 Windows 系统代理，未找到才直连。清空软件代理不一定能禁用系统代理。**检查连接** 使用不重试的短超时请求（连接 8 秒、读取 12 秒）并检查首页片段，区分代理错误、超时、403/503、地区限制和服务器错误；实际耗时还受 DNS、重定向及响应方式影响。连接成功只说明站点可访问，账号有效性应通过读取收藏或观看记录确认。

### 搜索种类

- **综合搜索、作品搜索、作者搜索、标签搜索、角色搜索**：输入关键词。
- **分类 / 排行**：使用设置中的分类、排序和时间范围。
- **漫画收藏夹**：读取个人主页中的漫画收藏目录；按钮会显示为 **读取漫画收藏**。
- **小说收藏夹**：只读显示小说候选；当前不下载小说正文。

## 11. 任务队列

任务队列上方显示所有任务及各任务实时状态、当前操作和更新时间；汇总栏分别统计运行、停止中和排队任务。任务取得平台并发槽位后立即显示“运行中”，等待槽位的任务保持“等待中”；多个作者同时运行时，每一行会分别显示自己的最近进度或媒体操作。下方详情区显示当前选择任务的参数、错误、日志和文件，批量跟踪时会自动跟随当前运行项。

- **按原设置重试**：用于失败、取消或支持修复重试的旧任务，保留每个任务自己的配置与目录。另有 **按当前设置重试**，用于明确更新参数后重试。
- 批量重试前会列出平台、目标和数量并要求确认；确认后会为可重试项新建任务，按各平台并发设置排队。取消确认不会创建任务。
- **批量暂停**：暂停选中的排队或运行任务。排队任务暂停后不会开始读取资料；运行任务会在下载分块、循环或进度回调的检查点停下，已发出的网络请求、浏览器操作或转换可能继续至检查点。运行任务暂停后仍占用并发槽位，并可能保留正在写入的文件锁。
- **批量恢复**：继续选中的暂停任务，沿用原任务 ID、已有进度和文件，不创建重试任务。所有任务都暂停时仍保留进度条数值；暂停任务也计入聚合进度。
- **批量取消**：停止排队、运行或暂停中的任务。取消会唤醒暂停的工作线程，退出和删除任务记录也使用此停止路径。
- **删除任务记录**：删除数据库中的任务、日志和文件索引，不删除本地媒体。
- **填入工作台**：单条选择时恢复目标、下载类型、目标类别和输出目录。可多选同一平台任务，把去重后的目标用 `/` 填入顶部输入框；点击开始任务时会按所选目标逐项建立任务。多选时目标类别和下载类型只有在所选任务一致时才恢复，输出目录使用工作台当前设置。跨平台多选不能填入工作台，请先只选一个平台；所有已接入下载平台均可使用同平台批量填入。预填目标会精确保留，因此搜索词或本地路径中已有的 `/` 不会被拆错；手动编辑输入框后按通常的多目标规则解析。
- 多选预填只填入工作台，不会立即下载。检查目标、下载类型、目标类别、保存目录和后处理设置后，再点 **开始任务**；开始任务仍会显示原有确认窗口。
- 双击任务列表中的某一行时，会以鼠标点击的那条记录为准；已有多选状态不会让它误填列表首项。
- **打开输出目录**：打开任务保存位置。
- 任务详情显示并筛选每项最近 500 条日志；支持按 INFO、WARNING、ERROR 筛选和关键词搜索，可导出当前筛选结果为 TXT 或 JSON。导出会对可识别的敏感字段做隐藏。
- 任务列表的“当前操作”会为每个任务分别显示最近进度；Twitter 任务还会显示正在下载/处理的媒体数和最近媒体文件。选中单个任务后，详情区也会显示该任务的媒体活动，日志保留逐项完成、跳过或失败原因。批量跟踪任务会自动聚焦当前运行项，并在任务结束后跟进下一项。日志默认跟随到底部；按住右侧滚动条时暂停，松开后继续跟随。
- **清理日志**：选择一项或多项任务后清理其数据库日志；任务记录、任务状态、文件索引和本地媒体都会保留。运行中的任务会继续产生新日志。
- 任务失败或取消时保留已写入的文件；有逐媒体清单的任务依据明确结果入库，不广扫目录猜测成品。其他兼容任务会尝试补录，错误详情显示补录数量；扫描有深度和修改时间筛选，未显示的文件可在下载库主动扫描。任务仍可能标记为失败，表示后续内容没有完整完成。
- Twitter 历史记录对应的媒体文件已删除时，可以重新创建下载任务，不会仅凭旧记录跳过。网络请求对资源不存在或登录拒绝停止逐次重试，限流和临时错误按有限次数等待重试；等待期间可取消任务。

- 任务层识别到 HTTP 401/403、404/410、TLS 错误、文件重名、磁盘空间/配额不足和文件权限错误后，不再自动重跑整个任务；超时、代理/连接故障及站点暂时错误仍遵循有限重试。任务详情和日志显示中文错误类别，修复 Cookie、目录或网络后仍可手动重试。分类依据异常类型、HTTP 状态和异常链；只返回文字提示或自行处理失败的平台入口可能仍显示“未分类错误”，并保留原有限重试行为。

- 公共 HTTP、Twitter 图片/音频等请求、公共 JSON（含部分 Pixiv API）、普通网页直连、JM 及 Bluesky HLS 请求，在收到 429/503 后共享**本实例内同一主机与端口**的退避期限。不同子域、端口及软件实例独立；Retry-After 支持秒数和 HTTP 日期，保留有效的完整期限，不再截到 300 秒。非法值回退为有限等待；超出系统支持范围的期限明确报错，不提前重试。新的较短等待不会缩短已有期限，即便某个请求已用尽重试次数，其他任务仍会遵守共享期限；取消一个任务不会清掉其他任务的等待。已发出的请求不会撤回，任务的等待可在检查点暂停/取消。浏览器直接请求、其他外部引擎、BT 和未接入的独立平台请求不因此获得限流协调。
- 公共 HTTP 下载器和 Twitter 视频/GIF 会在独立内部目录中保留可验证的传输数据与续传记录。取消或失败后重试相同目标、使用相同输出位置，服务端返回相同 URL、验证器和总长度时会尝试接着下载；临时签名 URL 变化、缺少验证器、不支持 Range 或资源变化时从头下载。成功后删除续传记录。公共图片格式转换前的源文件为隐藏临时名，续传目录也位于该源文件同级；不要单独移动或删除其中一项。HLS、JMComic 图片请求和浏览器直接提取链路不因此获得网络续传能力。软件不会在启动时自动执行网络任务；遗留任务先标为取消并保留可恢复标记，再由用户点击“恢复中断任务”。
- 同一媒体输出的下载和转换会使用输出锁，等待期间可以取消。设置中的“媒体文件重名时”支持**复用已有文件**（默认）、**覆盖已有文件**、**遇到重名时报错**和**自动改名保留两者**，新建任务时保存策略，运行中的任务与恢复任务沿用原参数。已接入 Twitter 图片/视频/GIF/音频、Pixiv 普通图片/小说正文/动图、FANBOX/Sketch 媒体及附件、Bluesky 图片与 HLS 成品、Instagram 媒体、EH 展示图、JM 章节图片/封面及 PDF/长图、普通网页直连/浏览器媒体，以及公共 ZIP 创建。复用/覆盖/报错策略不把零字节占位视为成品，也不覆盖目录及符号链接；自动改名会保留任何已有同名路径，依次尝试 `文件 (2).扩展名`、`文件 (3).扩展名` 等名称。选择和提交期间持有文件锁，下载库、历史及后处理使用实际保存路径。重复执行同一目标也可能产生新副本。独立元数据刷新、外部插件仍使用各自规则；ZIP 解压仍只进入新目录，尚无逐文件询问。Pixiv 小说仍逐篇执行黑名单和 AI 过滤。

- 自动改名时，Pixiv 小说的 HTML/TXT/JSON、动图原始 ZIP/帧元数据，以及 Twitter GIF/MP4 等关联输出按同一组基名选择，避免一组文件覆盖另一组。Twitter 开启保留原始副本时，新副本使用所选基名加 `.original`，已有原始名文件保持不动。失败或取消不会预留空成品占位；符合 HTTP 校验条件的传输临时文件仍按原续传规则保留。单个原名最多尝试 10000 个候选，超过后报告错误。

- 公共 HTTP／Twitter 视频的新续传资料改放在成品同级的 `.yuqiuda-http-<64 位摘要>/` 内，含归属标记、`payload.part` 和 `resume.json`；完成后清理空内部目录，取消或网络中断时保留可验证资料。目录名称是内部保留名称，不可作为普通下载目标；既有目录缺少或损坏归属标记时拒绝覆盖，下载库扫描跳过此目录。旧版成品旁的 `.part/.resume` 无法可靠区分真实附件，因此保留原样、不自动接管或删除，升级后旧任务可能重新传输；确认无需旧续传后可自行清理。升级前关闭旧版下载实例，避免旧实现继续操作旁文件。

- HTTP 续传还会核对重定向后的最终资源地址。即使入口相同、文件长度及 ETag 相同，最终域、路径或签名查询变化也会保守从头重取，避免拼接不同文件。新续传记录仅保存地址摘要，不保存最终签名 URL 原文；旧内部记录缺少此身份时会重新下载，现有成品及旧同级附件不因此改动。地址摘要不能证明来源内容正确，也不能检测所有本地缓存字节被改写的情况。

- 新版还保存**本地前缀摘要检查点**。恢复前按块读取已记录部分并核对 SHA-256，可暂停／取消；损坏、截短或旧记录缺少内容摘要时从头重取。异常退出可能留下超过检查点的尾部，这部分不被当成有效进度，验证后截掉并重新获取。每累计 4 MiB 或两秒（收到数据块时检查）保存一次，正常取消、网络失败和完成前补存最新进度。只在服务端总长度及有效验证器已知时提供这种续传；大文件恢复前需要读取一遍已保存前缀。

- 检查点记录升级为版本 3，版本 1／2 的内部进度不能直接追加，下一次重新传输；不修改已有成品或旧同级附件。摘要检查用于发现本地缓存变化，不等于来源内容可信，也不保证抵御同时改写缓存和摘要记录的行为。检查点先刷写数据再原子保存状态，仍不承诺任何硬件故障下都保住最后一段进度。

- Bluesky HLS 本地封装和 Pixiv 动图转 MP4 的 FFmpeg 错误输出在运行中持续读取，仅保留末尾最多 64 KiB 供失败诊断；取消／超时会终止并等待本次子进程退出。Pixiv 转换仍有 30 分钟上限，Bluesky 不新增固定时长上限。Bluesky 的网络分片由 HTTP 入口控制，FFmpeg 只读取本地文件；其他 FFmpeg 入口不因此获得网络限速或分片恢复。

- 重启后可点队列顶部的**恢复中断任务**，确认后重新接管正常退出或意外退出时未完成的任务。沿用原任务 ID、输出目录、参数、日志、文件索引和已绑定的批次条目；原暂停任务保持暂停，再点“批量恢复”继续。主动取消的任务不作为中断任务恢复，可用“批量重试”另建任务。存活实例的任务不会被接管，同一中断任务只能被一个实例成功接管；缺少平台模块、参数损坏或目标已在黑名单时保留记录并报告原因。恢复会重新解析目标，按原策略处理已有成品，并在可验证时使用续传文件；不恢复浏览器现场，Bluesky 符合条件的完整 HLS 分片可重新校验后复用。旧版已取消且没有恢复标记的历史任务仍使用重试。
- Twitter 任务在有已追踪的未完成媒体时输出数量与失败分类。视频临时文件已下载完成、但转为原始文件名失败时会保留 `.part`；从原始名改为日期名失败时保留原始名文件。先关闭占用文件的预览或程序，再根据日志处理。开启“保存未完成文件清单”后会另存 `未完成_<任务ID>.txt`；尚未发现的媒体不会出现在清单中，参考文件名也可能与最终格式不同。
- 顶部进度条汇总当前活跃任务上报的进度；尚无明细的平台使用排队/运行占位值。Twitter 边扫描边发现媒体，总数可能增加，百分比不等于完整账号已经下载的比例。
- 任务详情和日志导出只取最近 500 条；数据库日志全局约保留 20000 条，每 200 次写入检查并清理超额旧行。需要保留排错记录时及时导出。
- 左侧运行日志文本框只保留最近约 5000 行，并对直接写入的错误信息脱敏；这一显示限制不改变数据库日志保留规则。
- 任务正常完成后会弹出提示窗口，显示下载文件数、总大小和保存目录；失败时也会提示查看日志。

退出软件时如果仍有任务，会先询问是否停止。已经下载完成的文件会保留。

多个当前版本实例可以查看同一个数据库中的任务；启动恢复会根据实例归属和操作系统锁检查存活状态，不会把另一个存活实例的运行或暂停任务改为取消。活跃实例的任务记录不会被另一个实例删除；暂停、恢复和取消仍需在创建该任务的实例中操作。退出等待超时的任务继续显示取消中，直到实际停止或所属实例退出后被下一次启动恢复。旧版任务没有实例归属，升级前先关闭旧版实例，避免新旧版本混跑。

输出锁使用当前系统用户的固定目录，使不同临时目录启动的实例使用相同锁位置；升级前需要退出所有旧版实例，新旧锁目录不会互相协调。

同站点因 429/503 等待时，管理器工作线程会在任务当前操作和日志显示主机、端口及大致剩余秒数，等待期间最多每 5 秒更新一次；等待结束后显示继续请求。Bluesky API、Instagram 静态页面及 FANBOX/Sketch JSON 入口也已接入共享等待。平台自行创建的工作线程尚未自动继承该提示；浏览器直接请求、外部引擎和其他实例仍不共享退避期限。

### 任务的部分完成与补下

Bluesky、Instagram 静态下载，以及 Pixiv 单作品普通插画/多页漫画、作品收藏、漫画系列、作品搜索和排行榜会在任务详情显示“保存 / 复用 / 失败 / 待处理 / 已补全”数量。有成功项也有未完成项时，任务显示“部分完成”；全部失败仍显示失败，取消保持取消。统计只涵盖已登记媒体，不代表已扫描远端全部作品。Pixiv 作品收藏、漫画系列、作品搜索和排行榜的图片按页记录，动图按转换组记录；其他集合、小说收藏、单作品动图等仍走原流程。Twitter 自动未完成 TXT 仍独立，Instagram 浏览器回退和其他平台尚未接入这套清单。

选中已结束的任务，点击 **仅补未完成媒体**，软件会为已记录的失败和待处理项创建独立任务，重新读取原页面、核对原媒体序号、类型和路径摘要后下载，沿用每项原来的子目录。它不会重新下载清单中的成功项；如果原媒体路径变化或页面不再返回它，记录失败原因，需人工检查后重新创建任务。路径摘要不等于文件内容摘要，无法据此识别同一路径上的内容替换。地址刷新只更新后续请求，不保证旧 HTTP 数据能跨地址续传；Bluesky HLS 分片按下节的独立规则恢复。每个任务的逐媒体计划最多 10000 项，重复媒体按记录键去重。

补下成功后，原清单对应项标为“已补全”，再次补下不会选中它；原任务及批次状态作为执行历史保留。补下任务新建、重试或中断恢复时，均关闭公共压缩、解压和源文件清理；旧补下任务携带的归档选项也会在恢复时修正并保存。无效补下计划不会被接管，仍保留中断记录并报告原因。有未完成媒体的普通任务也会保留源文件并跳过公共归档。

点击 **导出失败清单** 可将所选任务的未完成记录保存为 UTF-8 BOM 的 TXT 或 CSV，包含页面地址、媒体序号、类型和已有原因，一次最多 10000 项，不导出原始签名媒体地址。导出在后台执行，显示进度，按钮变为“取消清单导出”；取消或写入失败保留旧清单。导出内容取自读取时的统一快照，之后补下完成不会回写已导出的文件。CSV 对可能被表格程序当成公式的文本加前缀处理。清理日志不会清理逐媒体记录；删除任务记录会一并删除逐媒体清单，不删除本地媒体。

逐媒体下载遇到明确的磁盘空间或本地文件权限等错误时，会停止继续尝试后面的媒体，保留为待处理；先解决磁盘问题，再使用补下。已落盘文件发生通知错误时，软件仍会尝试记住成功结果；如果数据库本身也无法写入，记录仍可能不完整。

### 最近保存目录

工作台和设置页的保存目录旁都有 **最近目录** 菜单，最多记录 10 项。选择后立即记住，并刷新下载库；已删除或不可写的目录不可选择。清空最近目录只删除菜单记录，默认保存目录和磁盘文件保持原样。手动输入目录的记忆与默认回退规则保持原有行为。

### 查看媒体明细和选择补下

在任务队列选中一个任务，点击 **查看逐媒体结果**。窗口每页显示 100 项，可按失败、待处理、已保存、已复用或已补全筛选；选中后可查看完整原因或打开原页面。多选当前页的未完成项后，点击 **仅补所选（当前页）**，为这些项创建独立任务。翻页不保留前一页的选择。

记录会随下载和补下变化；每次补下都会重新核对所选记录，已经补全或不再是未完成状态时会提示刷新。原任务正在执行、相同目标已有运行任务或内容类型未接入时，不能从这里创建补下。明细覆盖范围以本节开头说明为准。

### Pixiv 图片与集合补下

普通插画和多页漫画可按作品 URL 或作品 ID 创建任务，每一页独立记录结果。某页失败时会继续处理其他页，缺少原图地址也会显示为失败。通过“仅补未完成媒体”或明细窗口选择页补下时，会重新读取作品及原图列表，检查当前黑名单和 AI 过滤，并核对原页序及路径；作品变成动图、路径发生变化或被过滤时，保留失败原因，不下载其他内容。

补下沿用原来的子目录和页码，作者名、标题或日期变化不会把文件转移到新目录。新链路会检查图片内容；复用策略遇到已有坏图时会报告失败并保留它，检查后可改用覆盖策略重新创建任务。图片格式检查不等于所有像素完整性验证。

作品收藏、漫画系列、作品搜索和排行榜支持普通图片和动图混合任务。先保存本次最多 100 个作品的 ID 范围，再完整解析其中每个未被过滤的作品；图片按页、动图按整组生成媒体项，合计最多 10000 项。全部解析成功并提交清单后才开始传输。被 AI／黑名单过滤的作品记录在任务日志，不生成待下载页。任一作品的详情或页列表解析失败／取消，尚未完整登记的媒体不会提前下载；此时应使用“按原设置重试”或恢复中断任务，沿用原作品清单重新解析。这里没有分页游标恢复，也不会重新选择新的集合作品。

已登记后，每页失败不会阻止其他页或作品继续下载（磁盘等致命错误除外）。任务详情和“查看逐媒体结果”可按作品页面地址查看各页状态，选择未完成页补下；动图原始 ZIP 及其元数据等伴随输出作为一个转换组补下，不做逐帧恢复。补下会刷新源地址，重查过滤、作品类型、页码和路径身份，沿用原目录与设置；标题／作者名／日期变化不改目录。成功项不重新传输，原记录标“已补全”，原任务终态保留。动图组已提交后发生入库通知错误时，也会尽力保留已提交状态，避免因自动改名再次下载；数据库写入失败时仍可能需手动检查索引。

对原收藏、漫画系列、作品搜索或排行榜任务执行“按当前设置重试”会重新发现范围；精确补下沿用原范围。补下任务不接受“按当前设置重试”，避免将所选子集扩大；如需重新发现，请回到原集合任务操作。没有逐媒体记录的旧收藏、漫画系列、作品搜索或排行榜任务应先按原设置完整重试，不能凭空推断哪些页失败。作者、小说搜索、小说系列等其他集合，以及小说收藏、单作品动图、FANBOX 和 Sketch 尚未扩展到本轮精确补下。单作品没有返回页列表时，也不会凭空生成失败页记录。

### Bluesky HLS 分片恢复

Bluesky 已结束的未加密点播视频支持 TS 和带初始化片段的 fMP4。主列表选择当前带宽最高的变体；直播、加密、字节范围、独立音轨／视频轨和低延迟增量布局明确报为暂不支持，不会悄悄下载缺少音轨的版本。需要本机 FFmpeg，网络资源由软件 HTTP 下载，FFmpeg 只读取生成的本地播放列表封装 MP4。

取消、网络失败或封装失败后，已完整下载的分片保留在输出文件同级 `.yuqiuda-hls-<摘要>/` 中。重试或恢复到相同输出文件时，先重新读取播放列表，再验证本地大小和 SHA-256，并使用强 ETag 或 Last-Modified 作条件 GET。仅服务器返回相符的 304 且最终地址一致时才复用；缺少验证器、缓存损坏或不支持条件请求时重新传输。未完成的单片从头下载，不做片内 Range 续传。

播放列表、变体或完整资源地址（含签名参数）改变时重新建立缓存；同地址分片内容发生变化时清掉本代旧缓存并完整重抓一次，避免拼接已知不同版本。状态文件不保存播放／分片 URL 明文，只保存指纹、摘要和服务器验证器。初始化数据独立校验，序号、不连续标记和初始化片段映射保留到本地列表。

分片和初始化数据使用任务代理、公开资源凭据隔离、逐跳目的地址检查、HTTP 总限速及主机共享退避；播放列表不计入媒体字节预算。任务当前操作显示资源进度和条件复用数量（含初始化数据）。视频仍是逐媒体清单中的一个视频项，补下该项会尝试复用内部完整分片。

新成品仅在 FFmpeg 成功且文件非空后提交，失败时保留旧成品。最终改名被占用时保留封装结果，再次校验资源后可直接重试提交。成功后清理自己的内部文件；任务失败／取消或删除任务记录不自动删除分片缓存。不再需要时，可先结束相关任务，再用设置页的 **续传缓存清理** 预览并选择清理。旧版 `<文件>.part.mp4` 保留、不自动接管。内部目录保留名称不能作为普通下载目标，下载库扫描跳过这些目录。

下载和复用前会检查 TS 的 188 字节包边界及同步字节，或 MP4 初始化／媒体盒的必要类型与长度，拒绝明显的 HTTP 200 错误页和截断容器，避免引擎跳过坏分片后仍提交缺片视频。此检查不等于完整解码、采样表审计或逐帧时长验证；SHA-256 也只用于本地一致性和变化检测，不能证明来源正确或所有内容完整。

当前上限：播放列表 2 MiB、10000 个分片、主列表最多四层，每个资源 512 MiB，单视频累计 64 GiB。不保证跨输出路径、地址轮换或服务器验证器不可靠时继续复用，也不宣称服务器在下载期间提供原子快照。

### 浏览器会话总上限

设置中新增 **浏览器会话总上限**，默认 3，可设为 1–10。Twitter 桌面下载、动态网页采集/预览和 Google 相似搜索在本进程内共用名额；任务队列和 Google 状态回调可显示等待，取得名额后提示正在启动。暂停中的等待任务先让其他任务入场，恢复后重新排队；任务可按原入口取消，独立预览线程尚未自动接入等待提示。保存更小的上限不会关闭已有会话，只控制后续入场。

登录窗口、Twitter 独立资料/关注查询与独立 CLI、外部插件以及其他软件实例不自动受此设置控制。它也不是系统中所有 Chrome 进程的数量限制；浏览器退出失败时仍可能有残留进程。

同一区域可启用 **浏览器内存保护（Windows）**，默认关闭。默认在系统物理内存使用率达到 85% 时等待，降至 75% 或以下才继续，最多等待 120 秒。暂停阈值可设 50–99%，恢复阈值可设 10–98% 且必须低于暂停值，等待上限可设 10–3600 秒。修改后点“保存设置”，只影响之后的新会话入场，不会关闭已有浏览器。

内存等待支持取消，任务队列和 Google 搜索会提示当前比例、恢复条件及剩余等待时间。暂停任务的检查点内时间不计入预算；持续处于阻塞状态达到上限时报告失败，可释放内存后重试，不会因此自动反复重跑整个任务。关闭保护或修改保护参数会重新计算等待预算。读取系统内存失败会明确报错，不静默放行。

该选项只对前述受管理会话生效，按需每秒采样，不能预知新浏览器的内存消耗，也不保证防止系统内存不足。非 Windows 系统应保持关闭。长时间压力场景仍需根据机器配置验证。

Twitter 初始化现使用 Chrome 默认的证书校验。中断的逐媒体任务继续后，公共归档会合并此前已登记的成品；发现这些成品缺失，或者新记录对应的文件索引已清理/归属变化时，会停止并报告，需检查文件或重新创建完整任务。旧逐媒体记录没有保存成品路径时，恢复范围依赖仍保留的任务文件索引。

真实平台账号下载仍需单独验收。

## 12. 下载库

下载库包含三部分：

1. 平台、作者和文件夹列表。
2. 所选文件夹的文件列表。
3. 当前图片或文件预览。

可用操作：

- 多关键词搜索平台、路径、文件名、类型、标题、作者、章节和标签。
- 刷新数据库索引或扫描保存目录中新出现的文件。
- 打开文件、打开文件夹、复制绝对路径。
- 重命名单个文件。
- 把明确选中的文件移到 Windows 回收站。
- 小窗口下点 **显示预览** 展开图片预览区。

点击下载库顶部的 **筛选 / 导出 / 清理**，可打开针对完整数据库索引的独立工具窗口，不受当前保存目录、文件表 500 条或普通界面索引数量上限限制。综合关键词默认带入当前下载库搜索词；可再组合平台、资源类型、作者 ID（精确）或作者名（包含）、标题、精确标签和日期。日期支持入库日期或发布日期，包含起止当天；没有相应日期的记录不会命中日期条件。入库日期指该条索引首次建立的时间，不等同文件实际下载时间。

- **导出匹配 CSV**：后台逐条导出所有匹配索引，包括本地文件已丢失的记录，并提供 `local_exists` 字段。CSV 使用 UTF-8 BOM，包含来源、作者、标题、章节、标签和日期；识别到的敏感 URL 查询值会隐藏，文本单元格处理常见表格公式前缀，不导出原始 metadata。已有导出文件只在完整成功后替换；不能覆盖运行数据库或已登记的资源。
- **预览匹配**：显示匹配数量、现有文件总字节数、缺失文件数量及最多 50 条示例路径。单次清理最多 10000 条；超过时必须缩小条件，不会只清理截断的一部分。改变任何条件都会使清理预览失效。
- **仅清索引**：确认后删除该批下载库文件索引，保留本地文件、任务、日志及平台 JSON 历史。再次扫描本地目录会重新收录仍在磁盘上的文件。
- **移到回收站并清索引**：确认后逐项重新核对索引版本及文件状态，回收成功才移除索引；预览时已经缺失且仍未出现的文件可直接移除索引。变化、被占用、链接路径及回收失败的项目会跳过或保留索引。操作失败或停止后显示已完成数量与原因。
- **停止当前操作**：导出/预览检查取消后退出；清理在项目边界停止，已完成的操作保留。后台操作中关闭窗口会先请求停止，结束后关闭。

执行这两个清理操作前，需要结束本实例的下载任务，包括暂停任务；清理期间本实例不接收新下载任务。清理还会在每项处理前检查同一数据库中的其他任务，检测到新任务就停止后续清理。该协调只覆盖共享数据库及遵守输出锁的程序，不保证其他安装实例或外部软件不会改动同一目录。

清理平台历史与删除本地文件是两项操作。清理历史默认保留本地媒体；删除媒体必须在下载库明确选择并确认。

原有“重命名”和“移到回收站”按钮也使用与批量清理相同的维护门禁和状态检查：需要先结束下载任务（含暂停任务），已被占用或自选择/确认以来发生变化的文件不会继续操作。重命名不会覆盖已有文件或已有目标索引，数据库更新失败时尝试恢复原文件名；文件系统和数据库不是同一个原子事务，恢复失败会报告保留位置。

### 成品清单与只读核验

在下载库点击 **筛选 / 导出 / 清理**，设置范围后点击 **导出成品清单**。选择包含全部匹配索引路径的文件根目录，再选择一个尚不存在的 JSON 文件名。清单按完整匹配索引生成，不受界面显示数量限制，单次最多 10000 项；匹配文件超出根目录时会报错，请缩小筛选范围或选择共同根目录。

清单记录相对路径、当前实际大小、SHA-256 及必要来源字段，剔除来源 URL 中的账号、查询参数和片段，不导出 Cookie、任务配置或引擎原始元数据。不存在、正在使用、读取中变化或不能安全读取的文件单独标记，不给它们伪造有效摘要。空文件也可建立本地基线，不代表它是有效图片或视频。

点击 **读取清单核验**，选择清单、文件当前所在根目录及一个新报告文件名。核验使用清单全部条目，不使用窗口的筛选条件；文件夹整体迁移后可以选择新根目录。报告区分匹配、缺失、变化、无法读取、正在使用和无有效基线。同大小文件改写也会通过摘要发现；原来缺失的文件后来出现时，因没有旧摘要仍报告无有效基线。

两项操作均在后台进行，可点 **停止当前操作**。操作不修改媒体、下载库索引或任务历史；不自动补下、删除、改名或更新旧基线。清单和报告使用新文件名，不覆盖旧文件，也不能占用已登记的缺失资源路径。输出目录需支持硬链接原子创建（例如 NTFS）；可将报告保存在与媒体不同的目录。

第一次清单记录的是导出时的本地内容，不能证明文件最初下载正确或来源可信；如果清单和文件同时被改写，也不能据此证明未被篡改。当前不提供来源 checksum 验证、媒体解码检查或源文件到转换产物的完整关系图。核验期间每个文件单独检查一致性，不是整个下载目录同一时刻的快照。

## 13. 压缩、PDF 和长图

公共媒体下载及普通网页的 FFmpeg 格式转换现支持任务取消：取消后回收本次转换进程，未提交的转换临时文件会清理，旧成品不会被半成品覆盖。直接转换入口保留原输入；下载器内部源工作副本仍按原规则清理。图片转换在渲染后、提交前检查取消，不会中途打断 Pillow 渲染；暂停也不等于挂起 FFmpeg 进程。1800 秒转换超时继续有效，成功退出及非空检查不代表完整解码校验。

在设置页的 **公共压缩 / 解压** 中选择：

- **按整个任务压缩**：一个任务生成一个 ZIP。
- **按资源文件夹压缩**：每个漫画章节或资源目录分别生成 ZIP。
- **安全解压下载到的 ZIP**：只解压通过路径和容量检查的普通 ZIP。
- **压缩校验成功后清理源文件**：ZIP 校验成功后，再核对源文件身份、大小、时间及 SHA-256 内容摘要。整组预检有任一项变化、缺失或无法读取时，保留本组全部源文件并记录警告；开始删除后，逐项复核，变化或被占用的文件继续保留。只移除实际删除文件的下载库索引。内容复核会额外读取源文件，大文件清理可能需要更多时间。
- 生成的 ZIP 文件保存在对应资源文件夹内（按资源文件夹压缩时）或任务输出根目录内（按整个任务压缩时），文件名为 `{文件夹名}_归档_{任务ID}.zip`。

ZIP 创建遵循任务保存的重名策略。选择复用时会检查已有 ZIP；开启源文件清理后，还会比对归档成员列表和内容，旧归档与本次源文件不一致时不会删除源文件。解压过程锁定源 ZIP 与目标目录，目标目录已出现时不会覆盖。

JMComic 的章节后处理可以单独选择 PDF、长图或两者，每组最多处理 30 张图片。合成与 ZIP 创建共用重名策略；PDF 和长图同时生成时按组选择基名。新成品先写临时文件，所选格式都生成成功后再逐个原子替换；转换失败或提交前取消会保留旧成品。每个文件的替换是原子的，多文件提交与文件系统/数据库之间不是同一个事务。

## 14. 常见问题

### 页面返回 403

- 检查当前站点域名是否与 Cookie 一致。
- 检查软件代理是否与浏览器取得 Cookie 时一致。
- JMComic 需要一起更新请求标头、User-Agent 和 `cf_clearance`。

### 提示缺少登录会话

- Pixiv 检查 `PHPSESSID`，FANBOX 检查 `FANBOXSESSID`。
- JMComic 账号功能检查 `AVS`；只有 `cf_clearance` 不能读取收藏和历史。
- Instagram 登录限定页面检查 `sessionid`；Cookie 必须来自当前域名及相同代理环境。

### 启动显示 No module named 'Crypto'

执行 `py -3.12 -m pip install "pycryptodome>=3.20"`，然后也用 `py -3.12 .\run_software.py` 启动。若使用其他 Python 版本，把两条命令中的版本保持一致。

### Google 显示视觉效果已过期

重新选择原图并开始新搜索。不要继续切换已经失效的匿名 Lens 结果页。

### 缩小窗口后内容看不到

操作按钮会按可用宽度换行。任务和相似搜索的操作区可单独滚动，日志和结果表保留独立空间；左侧资料卡支持滚动。设置内容过宽时可横向滚动，“保存设置”固定在底部。下载库图片预览可收起，为文件表保留空间。

### 清理历史后文件还在

这是正常行为。历史清理只删除数据库记录；需要删除媒体时，到下载库选择具体文件并移到回收站。

## 15. 本地数据和隐私

- 打包版（exe）：Cookie、浏览器请求头、数据库、关注缓存和下载记录保存在 exe 所在目录的 `data/software_app/` 中。
- 源码运行版：保存在项目目录的 `data/software_app/` 中。
- 默认下载目录：源码版为项目的 `data/downloads/`，exe 版为当前用户的 `Downloads/欲求达/`，也可以在设置中修改。`YUQIUDA_HOME` 可改变运行根目录，`YUQIUDA_OUTPUT_DIR` 可改变默认下载目录。
- ChromeDriver 驱动：源码版的全局位置为 `data/software_app/browser/chromedriver.exe`；打包版先找 exe 同级驱动，再兼容旧版 `_internal/`，然后使用单文件包临时解压的内置驱动。设置页检测结果会给出实际路径，不能假定所有 exe 都把驱动放在同级目录。
- 当前 GUI 和 CLI 均为单文件包，运行库在启动时解压到系统临时目录，不要求 exe 旁存在 `_internal/`。旧版目录包可能仍有 `_internal/`；程序运行时 Windows 会占用其中的 DLL，需退出相关进程后更新。
- 更新或替换打包文件前，先正常退出软件并等待几秒，再在任务管理器的“详细信息”中确认所有 `欲求达.exe` 和 `欲求达-cli.exe` 实例均已退出。若仍被占用，检查是否还有软件启动的 Chrome、ChromeDriver 或 aria2 进程；确认无相关任务后，可在 Windows 资源监视器的“CPU → 关联的句柄”中搜索 `VCRUNTIME140.dll`，查看实际持有文件的进程，再正常关闭该进程后重试。
- DLL 位于软件包 `_internal/` 时，只用新版软件包中的对应文件更新；不要从其他来源单独下载，也不要删除 `System32` 中的系统运行库。若任务管理器中已没有相关进程但文件仍短暂无法替换，稍等片刻后重试；仍不行时重启 Windows 再更新。
- 软件不会保存 JMComic 密码或 Bluesky 应用密码。
- 任务错误信息和详情对可识别的敏感字段进行脱敏；导入凭证、原始缓存和下载记录仍需作为本地私密资料保管。Twitter 未完成清单特意保留原始媒体 URL，可能带临时签名参数，不适合直接公开。
- 不要把 Cookie、完整请求标头、数据库或个人账号缓存提交到 Git 或发送给其他人。
- 收藏、观看记录、屏蔽和静音的读取不会修改网站。另有需要明确确认的写入入口：EH 单项收藏管理，以及 Bluesky 关注/取消关注；本地黑名单与这些站内操作相互独立。
